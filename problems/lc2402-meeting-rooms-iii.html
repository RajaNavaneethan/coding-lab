Meeting Rooms III

LeetCode 2402 · Hard · Pattern: two heaps (free rooms, busy rooms) · O((n+m) log(n+m)) time, O(n+m) space

Problem. You have n rooms numbered 0..n−1 and a list of meetings meetings[i] = [starti, endi] (end exclusive). Rules:
  • Process meetings in order of start time.
  • If any room is free, use the lowest-indexed free room.
  • If no room is free, the meeting is delayed until the earliest-ending room is free. The meeting runs for its original duration (end − start). Delayed meetings do not change the order of future meetings.
Return the room that held the most meetings; break ties by lowest index.
n=2, meetings=[[0,10],[1,5],[2,7],[3,4]] → 0
n=3, meetings=[[1,20],[2,10],[3,5],[4,9],[6,8]] → 1
Link: LeetCode

1. The one idea that solves it

Two priority queues let us answer the two questions this problem asks every step:

  • free: a min-heap of free room indices. The top is the lowest-indexed free room.
  • busy: a min-heap of (endTime, roomIndex). The top is the earliest-ending busy room (ties break by index, which also matches the rule for picking which room goes next).

Sort meetings by start, then for each meeting [s, e] (duration d = e − s):

  1. Move every room from busy to free whose endTime is ≤ s.
  2. If free is non-empty, pop the smallest index; that room runs [s, e].
  3. Otherwise, pop the earliest-ending room (endT, idx) from busy. That room runs the meeting delayed: it starts at endT and ends at endT + d. Push (endT + d, idx) back into busy.
  4. In every case, increment count[idx].
Idea. The two things we care about at each step are "the smallest-indexed free room" and "the room that will free up first". A min-heap on each gives us both in O(log n). The meeting's duration is sacred: delaying preserves it.

Why long long matters

Delayed meetings push end times forward. In the worst case this cascades: a stream of long meetings on a single room means each one's end time grows by one duration. With end ≤ 5·105 and up to 105 meetings the end time can reach ~5·1010, which overflows a 32-bit int. Store end times as long long; the room index is still int.

4. Code (C++)

class Solution {
public:
    int mostBooked(int n, vector<vector<int>>& meetings) {
        sort(meetings.begin(), meetings.end(),
             [](const vector<int>& a, const vector<int>& b){ return a[0] < b[0]; });
        priority_queue<int, vector<int>, greater<int>> freeRooms;    // by index
        for (int i = 0; i < n; i++) freeRooms.push(i);
        using P = pair<long long, int>;                              // (endTime, idx)
        priority_queue<P, vector<P>, greater<P>> busy;
        vector<int> count(n, 0);

        for (auto& m : meetings) {
            long long s = m[0], e = m[1], d = e - s;
            while (!busy.empty() && busy.top().first <= s) {
                freeRooms.push(busy.top().second); busy.pop();      // room freed in time
            }
            if (!freeRooms.empty()) {
                int idx = freeRooms.top(); freeRooms.pop();
                count[idx]++;
                busy.push({e, idx});                                // run as requested
            } else {
                auto [endT, idx] = busy.top(); busy.pop();
                count[idx]++;
                busy.push({endT + d, idx});                         // delayed, duration preserved
            }
        }
        int best = 0;
        for (int i = 1; i < n; i++) if (count[i] > count[best]) best = i;
        return best;
    }
};

Complexity: sort is O(m log m). Each meeting does O(log n) heap work (one pop from free or busy, one push, plus amortised O(log n) across the while-loop pops which each happen at most once per room). Total O((n + m) log(n + m)) time, O(n + m) space.

5. The part interviewers ask about

Why does popping the earliest-ending busy room produce the "lowest index on tie" rule for free as well? Because the busy heap is ordered on the pair (endTime, index). When two rooms end at the same time, the smaller index comes first. This matches the problem's tie-break and is also what makes answer tiebreak work: a room that reaches a given count first will have the smaller index, so a simple left-to-right scan at the end returns the correct answer.

Overflow is a real trap. With n = 1 and m = 105 meetings each of duration ~5·105, the final room's endTime is around 5·1010. Use long long everywhere end times are stored and arithmetic is done. Room indices stay int.

Alternative data structure. You could keep free as a std::set<int> and use *free.begin() instead of a heap. It is the same O(log n) per op; the heap is just shorter to write.

Why not simulate time tick by tick? Time values can be up to 109; iterating time is hopeless. Event-driven simulation (what the two heaps give us) only touches the m interesting instants.

6. Traps and edge cases

  • Using int for end times. Overflows on cascaded delays. Use long long.
  • Forgetting to sort by start. The problem guarantees distinct starts but not sorted input. Always sort first.
  • Picking any busy room when none is free. Must be the earliest-ending one.
  • Changing a delayed meeting's duration. The meeting runs the full e − s starting from the room's current end time. New end = endT + (e − s), not e.
  • Not freeing rooms before checking free. If a room's endTime is ≤ s it is available right now and must be considered. Drain busy first.
  • Tie-break of the answer by max index. Problem asks lowest index on ties. A plain > comparison (strictly greater) in the final scan keeps the lower index naturally.
  • Comparing pair with <= on first only. busy.top().first ≤ s is the right check; comparing the whole pair with the start would not compile.

7. How to say it in the interview (30 seconds)

"Two min-heaps. free is a heap of room indices; busy is a heap of (endTime, index). I sort meetings by start. For each one I first drain busy: anything that ends by now moves back to free. If free has anyone, I take the lowest index and schedule the meeting as-is. If not, I pop the earliest-ending room from busy, keep the meeting's duration, and reinsert it with endT + duration. I count how many meetings each room held and return the lowest-indexed max. Watch out for long long on end times."
