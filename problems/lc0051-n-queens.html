N-Queens

LeetCode 51 · Hard · Pattern: backtracking (place / unplace) with constant-time attack checks · O(N!) rough bound, O(N) extra space

Problem. Place n queens on an n × n chessboard so that no two queens attack each other (no shared row, column, or diagonal). Return every such board as an array of row strings, each row made of 'Q' and '.'.
n = 4 → [[".Q..","...Q","Q...","..Q."],["..Q.","Q...","...Q",".Q.."]]    n = 1 → [["Q"]]
Link: LeetCode

1. The one idea that solves it

You never need to place two queens in the same row, so place exactly one queen per row, row by row from top to bottom. In row r, loop through every column c, check if (r, c) is attacked by anything already placed, and if not, place a queen there and recurse into row r + 1. On the way back up, remove it.

The attack check is where this becomes fast. Three sets are enough:

  • usedCol[c] — a queen is already in column c
  • usedDiag[r − c] — along a "⎸" diagonal, r − c is constant
  • usedAnti[r + c] — along a "⎷" anti-diagonal, r + c is constant
Idea. One queen per row by construction. Three boolean sets catch the remaining attacks in O(1): column (c), ⎸-diagonal (r − c), ⎷-anti-diagonal (r + c). Place, recurse, unplace — standard backtracking.

4. Code (C++)

class Solution {
public:
    vector<vector<string>> solveNQueens(int n) {
        vector<vector<string>> ans;
        vector<int> col(n, 0);
        vector<bool> usedCol(n, false);
        vector<bool> usedDiag(2*n, false);     // index = r - c + n
        vector<bool> usedAnti(2*n, false);     // index = r + c

        function<void(int)> dfs = [&](int r) {
            if (r == n) {
                vector<string> board(n, string(n, '.'));
                for (int i = 0; i < n; i++) board[i][col[i]] = 'Q';
                ans.push_back(board);
                return;
            }
            for (int c = 0; c < n; c++) {
                if (usedCol[c] || usedDiag[r - c + n] || usedAnti[r + c]) continue;
                col[r] = c;
                usedCol[c] = usedDiag[r - c + n] = usedAnti[r + c] = true;
                dfs(r + 1);
                usedCol[c] = usedDiag[r - c + n] = usedAnti[r + c] = false;
            }
        };
        dfs(0);
        return ans;
    }
};

Complexity: loose bound O(N!), because row r has at most N choices and attacks remove a few more each level. In practice it is far faster — each diagonal mask kills roughly one choice per row. Space is O(N) for the three bool arrays, the col array, and the recursion.

Alternative: bitmask DP

void dfs(int r, int n, int cols, int d1, int d2, vector<int>& col, vector<vector<string>>& ans) {
    if (r == n) { /* build and push board */ return; }
    int avail = ((1 << n) - 1) & ~(cols | d1 | d2);
    while (avail) {
        int p = avail & -avail;             // lowest free bit
        avail -= p;
        int c = __builtin_ctz(p);
        col[r] = c;
        dfs(r + 1, n, cols | p, (d1 | p) << 1, (d2 | p) >> 1, col, ans);
    }
}

Same tree, but columns and both diagonals live in integer bitmasks. Shifting d1 left and d2 right before the recursive call does the "slide one row down" for you. Prefer this for N-Queens II (counting only), or when micro-benchmarks matter.

5. The part interviewers ask about: the diagonal indices

The step most people stumble on is why those three sets catch every attack. Row is already handled by placing one per row. For the rest:

Column. Two cells share a column iff they share c. One bool per column.
⎸ diagonal (top-left to bottom-right): the difference r − c is constant along it. Shift by n to make the index non-negative, so arrays of size 2n work.
⎷ anti-diagonal (top-right to bottom-left): the sum r + c is constant. Already non-negative.

Why that is enough: two queens attack iff they share row, column, ⎸-diagonal, or ⎷-anti-diagonal. We rule out the first by construction and the other three by the sets. Together they are the full set of attack relations for queens, so if all three checks pass the placement is safe.

A follow-up: can you skip the explicit board and still produce it at the end? Yes — col[r] is the whole state. The r == n branch builds a board string from col and that is why col is tracked separately.

6. Traps and edge cases

  • Negative diagonal index. r − c can be negative (e.g. row 0, col 3). Shift by n to get a legal array index.
  • Diagonal size. There are 2n − 1 diagonals and 2n − 1 anti-diagonals. Allocating n entries is a classic out-of-bounds bug.
  • Forgetting the unplace. If you leave usedCol[c] = true after returning, sibling columns in the same row will all look busy and you'll miss solutions.
  • Mutating the shared board. If you keep a single vector<string> and record pointers into it, every entry in ans ends up equal. Build a fresh board from col at the base case, or push_back a copy.
  • n = 2 and n = 3. Both return [], not [[]]. The code handles this because the for loop finds no safe cell.
  • n = 1. Returns [["Q"]]. Easy to special-case by accident.

7. How to say it in the interview (30 seconds)

"I place one queen per row, top to bottom. For each row I try every column; a placement is safe if the column, the r − c diagonal and the r + c anti-diagonal are all free. Three boolean arrays track that in O(1). Place, mark the three sets, recurse into the next row, then unmark on the way back. At row n I turn the column-per-row vector into a board of strings and push it. Loose bound is O(N!), but the diagonal masks cut the real work way below that. Space is O(N) because every structure is linear in n."
