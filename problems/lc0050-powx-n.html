Pow(x, n)

LeetCode 50 · Medium · Pattern: Fast exponentiation (binary exponentiation) · O(log |n|) time, O(1) space

Problem. Compute xn where x is a double and n is a 32-bit signed int (so n can be as low as INT_MIN = -2147483648).
Examples: pow(2.0, 10) = 1024.0, pow(2.1, 3) = 9.261, pow(2.0, -2) = 0.25.
Link: LeetCode

1. The one idea that solves it

Naive multiplication takes n steps. Fast exponentiation uses the identity xn = (x2)n/2 when n is even and xn = x · (x2)(n-1)/2 when n is odd. Halving n every step gives O(log n) multiplications.

Reading n in binary makes it concrete. Write n = bk…b1b0 in binary. Then xn = ∏i: bi=1 x2i. Keep a cur that holds x2i and square it each iteration; multiply it into ans whenever the current bit is 1.

Negative n: replace x with 1/x and make n positive. There is one sharp edge: n = INT_MIN cannot be negated as an int (-INT_MIN doesn't fit). Promote to long long first, then negate.

Idea. Treat the exponent as a binary number. Each bit tells you whether to multiply the current square into the answer. Each step squares the current factor and shifts the bit out. O(log |n|).

2. Picture of the algorithm

Think of it as a worker (cur) walking up the powers of two: after i steps, cur = x2i. A supervisor (ans) only takes cur on board when the current bit of n is 1.

4. Code (C++)

class Solution {
public:
    double myPow(double x, int n) {
        long long N = n;              // promote so -INT_MIN is representable
        if (N < 0) { x = 1 / x; N = -N; }
        double ans = 1.0, cur = x;
        while (N > 0) {
            if (N & 1) ans *= cur;
            cur *= cur;
            N >>= 1;
        }
        return ans;
    }
};

Complexity: O(log |n|) time — one loop iteration per bit of |n|, at most 31 for a 32-bit int (32 for INT_MIN after promotion). O(1) space.

Alternative: recursive halving

double fastPow(double x, long long N) {
    if (N == 0) return 1.0;
    double half = fastPow(x, N / 2);
    return (N % 2) ? half * half * x : half * half;
}

Same complexity. Clean on a whiteboard. Prefer the iterative version in C++ for stack safety and because it visibly shows the bit decomposition — interviewers like seeing the N & 1 / N >>= 1 dance.

5. The part interviewers ask about: three subtle points

  • Why long long N = n? INT_MIN = -231, and -INT_MIN = 231 does not fit in int (that would be INT_MAX + 1). Promoting first makes the negation safe.
  • Why multiply ans *= cur before squaring, not after? Order matters because cur at iteration i represents x2i. If bit i is 1, that is the factor we need to collect now. Squaring first would skip the current bit's contribution.
  • Why does it work for negatives? x-n = (1/x)n. Replacing x with 1/x up front removes the sign and the rest of the loop is identical.

The halving recursion as a picture

Each level halves the exponent. The depth is log2 n, so n = 10 finishes in 4 recursive calls, not 10 multiplications.

6. Traps and edge cases

  • n = INT_MIN. -n as an int overflows. Promote n to long long first. This is the single most asked follow-up on this problem.
  • x = 0, n < 0. LeetCode guarantees this won't happen, but say so if asked: it's division by zero.
  • x = 1 or x = -1 with huge |n|. Answer is 1 or ±1 and the algorithm handles it; worth noting as a quick sanity test.
  • Floating point error. The problem accepts answers within 1e-5. Fast exponentiation keeps error logarithmic in n; naive multiplication accumulates it linearly — another reason the log-time method wins.
  • Starting cur = x, not cur = 1. After zero loop iterations cur should equal x20 = x.
  • Starting ans = 1.0, not ans = x. The answer collects factors as bits of n are read; it must start empty (multiplicative identity).

7. How to say it in the interview (30 seconds)

"I read n in binary. I keep cur = x2i, squaring it every step. When the low bit of n is 1, I multiply cur into ans. Then I shift n right by one. This finishes in O(log |n|) multiplications. For negative n, I invert x up front. The only trap is n = INT_MIN: -INT_MIN doesn't fit in an int, so I promote n to long long first."
