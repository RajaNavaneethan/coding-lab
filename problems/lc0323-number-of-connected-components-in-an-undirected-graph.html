Number of Connected Components in an Undirected Graph

LeetCode 323 · Medium · Pattern: Union-Find (DSU) · O(E α(N)) time, O(N) space

Problem. n nodes labelled 0..n-1, and a list of undirected edges. Return the number of connected components.
n=5, edges=[[0,1],[1,2],[3,4]] → 2
Link: LeetCode

1. The one idea that solves it

Start with n components (every node is a singleton). Walk the edges. Each edge is one of two cases:

  • Different components: merge them. Total count drops by 1.
  • Same component already: the edge forms a cycle inside the component. Count stays the same.

So the answer is n − (number of edges that actually merged two different components).

Union-Find (also called a Disjoint Set Union / DSU) is the data structure that answers "same component?" and "merge these two components" each in near-constant amortised time. It stores a parent[] array where each node points to a parent in its component; a component's root points to itself. Two nodes are in the same component iff walking parents from each ends at the same root.

Idea. Represent each component by a tree rooted at one of its nodes. find(x) walks parent pointers to the root; union(a, b) attaches one root to the other. Two speed tricks (path compression in find and union by rank in union) keep each operation at an inverse Ackermann factor α(N), effectively O(1).

2. Picture of the algorithm

Path compression: whenever find walks a long chain, it flattens the chain by pointing nodes directly closer to the root. Union by rank: attach the shorter tree under the taller one so trees stay shallow. The two tricks are independent and both are needed for the amortised bound.

4. Code (C++)

class UF {
    vector<int> parent, rk;
public:
    UF(int n) : parent(n), rk(n, 0) {
        iota(parent.begin(), parent.end(), 0);     // parent[i] = i
    }
    int find(int x) {
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];      // path compression (halving)
            x = parent[x];
        }
        return x;
    }
    bool unite(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;             // already connected
        if (rk[ra] < rk[rb]) swap(ra, rb);         // smaller tree under bigger
        parent[rb] = ra;
        if (rk[ra] == rk[rb]) rk[ra]++;
        return true;
    }
};

int countComponents(int n, vector<vector<int>>& edges) {
    UF uf(n);
    int components = n;
    for (auto& e : edges) {
        if (uf.unite(e[0], e[1])) components--;
    }
    return components;
}

Complexity: O(E · α(N)) time, O(N) space. With both path compression and union by rank the amortised cost per operation is α(N) ≤ 4 for any practical input, so this is effectively O(E).

Alternative: BFS or DFS on the adjacency list

vector<vector<int>> adj(n);
for (auto& e : edges) { adj[e[0]].push_back(e[1]); adj[e[1]].push_back(e[0]); }
vector<bool> seen(n, false);
int cnt = 0;
for (int i = 0; i < n; i++) if (!seen[i]) {
    cnt++;
    // BFS/DFS from i, mark everything reachable
}
return cnt;

Also O(N + E). Prefer BFS/DFS when the problem later asks for things inside a component (list its nodes, measure its diameter). Prefer Union-Find when the problem is "same-set?" queries, incremental connectivity, Kruskal's MST, or "first redundant edge" style questions (LC 684).

5. The part interviewers ask about: why path compression + union by rank is α(N)

Intuition. Union by rank alone keeps the tree height ≤ log2(size), so find is O(log N) worst case. Path compression alone also gets to O(log N) amortised. Together they interact: compression flattens the longest chains, rank keeps future unions from re-growing them. The combined cost of any sequence of m operations on n elements is O(m · α(n)) — the inverse Ackermann function, ≤ 4 for any n that fits in the universe.

You do not have to prove this in an interview. Say "amortised α(N), effectively constant" and keep moving.

Common variants of each trick

  • Path compression (recursive): return parent[x] = find(parent[x]);. One line, same bound, risks stack overflow on a pathological chain. The iterative halving above is safer.
  • Union by size instead of rank: track component size, attach smaller under larger. Same complexity. If the problem also asks for component sizes, pick union by size — you get the sizes for free.

6. Traps and edge cases

  • Forgetting to initialise parent[i] = i. Then every find walks to a bogus root. Use iota or a loop.
  • Comparing nodes, not roots. if (a == b) return false is wrong. Call find on both and compare roots.
  • Returning void from unite. You need the "did it actually merge?" signal to decrement the component count. Return a bool.
  • Node labels not 0..n-1. If the problem gives string labels or sparse integers, map them to 0..n-1 first.
  • n = 0. Return 0; no nodes, no components.
  • Self-loop [i, i]. unite(i, i) returns false, count stays correct.
  • Duplicate edges. The second copy is rejected by unite, count stays correct.

7. How to say it in the interview (30 seconds)

"I start with n components and walk the edges with a Union-Find. Each edge either merges two different components (count drops by one) or joins two nodes already in the same component (count stays). find walks parent pointers to the root with path compression, union attaches smaller rank under larger rank. Both tricks give amortised α(N), effectively constant per operation, so the total is O(E) time and O(N) space."
