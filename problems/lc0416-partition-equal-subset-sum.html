Partition Equal Subset Sum

LeetCode 416 · Medium · Pattern: 0/1 Knapsack (subset sum) · O(n · S) time, O(S) space (S = sum/2)

Problem. Given a non-empty array of positive integers, can it be split into two subsets with equal sum?
[1,5,11,5] → true ({1,5,5} and {11}, both sum to 11)   [1,2,3,5] → false
Link: LeetCode

1. The one idea that solves it

Call the total S. Two equal subsets means each has sum S/2, so the problem is: is there a subset of the array that sums to exactly S/2? If S is odd, impossible — return false up front.

That reframe is 0/1 subset-sum, the classic knapsack. For each number we either take it or we don't. Track which target sums are reachable so far in a boolean array dp of size S/2 + 1: dp[s] = true once some subset of items seen so far sums to s. Start with dp[0] = true (the empty subset) and add numbers one by one.

Idea. "Equal partition" is just "subset-sum to S/2". Keep a set of reachable sums; each new number x extends every reachable sum s to s + x. Done the moment S/2 is reachable.

2. Picture of the algorithm

The 2-D table has one row per item and one column per target sum. The 1-D update replaces the row vector in place. For 0/1 knapsack (each item used at most once) you MUST sweep the sums from right to left. Here is why, drawn on the same cell.

Right to left reads dp[s − x] while that cell is still the previous row — the state before taking x. Left to right would already have updated dp[s − x] using x, so taking x a second time would look legal. That is the unbounded knapsack (Coin Change). For "at most once" the direction has to be right to left.

3. Step-by-step trace

The strip below is dp[0..target]. Each outer round adds one number x. During the round the sum pointer sweeps right to left; every cell that becomes newly true was reached as s = s' + x from some earlier s'.

4. Code (C++)

class Solution {
public:
    bool canPartition(vector<int>& nums) {
        int sum = 0;
        for (int x : nums) sum += x;
        if (sum % 2) return false;
        int target = sum / 2;
        vector<bool> dp(target + 1, false);
        dp[0] = true;                       // empty subset sums to 0
        for (int x : nums) {
            for (int s = target; s >= x; s--)  // right to left (0/1 knapsack)
                dp[s] = dp[s] || dp[s - x];
            if (dp[target]) return true;        // early exit
        }
        return dp[target];
    }
};

Complexity: O(n · S/2) time — one bit flip per (item, sum) pair. O(S/2) space for the 1-D array. LeetCode caps the sum at ~20000, so this is fast in practice.

5. The part interviewers ask about: why right to left

The invariant you want after processing item x is "dp[s] is true iff some subset of the items processed so far (x included) sums to s, using each item at most once." The update dp[s] |= dp[s − x] adds exactly the "take x" option.

Reading dp[s − x] must give the state before this round, otherwise you are using x twice. Sweeping sums right to left guarantees that: by the time you touch cell s, cell s − x (which is smaller) has not been written yet in this round. Left to right would already have updated it and you would silently drift into unbounded knapsack.

Mental shortcut: 0/1 knapsack → sum loop goes down. Unbounded (reusable items) → sum loop goes up.

Alternative: bitset trick

bool canPartition(vector<int>& nums) {
    int sum = accumulate(nums.begin(), nums.end(), 0);
    if (sum % 2) return false;
    bitset<20001> bs; bs[0] = 1;
    for (int x : nums) bs |= bs << x;    // shift adds x to every reachable sum
    return bs[sum / 2];
}

Same recurrence packed 64 bits per word. ~64x speedup. The right-to-left issue disappears because the shift reads the whole bitset atomically. Use it if the sum is up to ~20000 and the examiner is impressed by one-liners; otherwise the plain loop is clearer.

6. Traps and edge cases

  • Looping left to right. Turns 0/1 knapsack into unbounded knapsack. On [2], target 4 you would wrongly report true (using the 2 twice).
  • Forgetting the odd-sum shortcut. If sum % 2 == 1 you can return false immediately. Not a bug, but target = sum/2 would round down and you would get a wrong answer if you also drop the odd check (e.g. [1,1,1]: sum=3, target=1 is reachable, but no equal partition exists).
  • Zero-sized input. LeetCode guarantees non-empty, but sum = 0 on empty would say "two subsets of sum 0" — depends on your definition. The problem forbids this.
  • Signed overflow. Values up to 100, length up to 200, so sum ≤ 20000. Safe in int.
  • Using vector<bool> and expecting & operator. Use || on the boolean, or |= on a vector<int>. The code above uses ||, fine.
  • Skipping the early exit. Not wrong, just slower on large inputs where dp[target] becomes true halfway through.

7. How to say it in the interview (30 seconds)

"Two equal halves means a subset summing to S/2, which is 0/1 subset-sum. I keep a boolean dp[0..S/2] where dp[s] is true if some subset so far sums to s. For each number x I update dp[s] |= dp[s−x] from s = S/2 down to x. Going right to left is what makes it 0/1: when I read dp[s−x] it is still the pre-round state, so x cannot be reused. Odd total returns false up front. Answer is dp[S/2]. O(n · S) time, O(S) space."
