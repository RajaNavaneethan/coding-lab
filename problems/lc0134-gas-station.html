Gas Station

LeetCode 134 · Medium · Pattern: running sum, reset-on-dip greedy · O(n) time, O(1) space

Problem. n gas stations in a circle. Station i has gas[i] fuel; going from i to i+1 costs cost[i]. Return the index of the only station you can start from and complete the loop, or -1 if impossible.
gas=[1,2,3,4,5], cost=[3,4,5,1,2] → 3    gas=[2,3,4], cost=[3,4,3] → -1
Link: LeetCode

1. The one idea that solves it

Define diff[i] = gas[i] - cost[i]: the net fuel you gain by traversing the hop that starts at i. Walk forward from some start, keeping a running tank. The tank is a prefix sum of diff rooted at the start. The loop is possible from s iff the running tank never goes negative over a full lap.

Two things fall out of this reframing:

  • If sum(diff) < 0, no start works. Not enough fuel exists for one full loop.
  • If sum(diff) ≥ 0, exactly one start works and we can find it in one left-to-right pass.
Idea. Walk once. Keep a running tank. If it drops below 0 after station i, no station in [start, i] can be a valid start, so reset: start = i + 1, tank = 0. If total diff is non-negative, the final start is the answer; otherwise return -1.

Why the greedy choice is safe (exchange argument)

Suppose we start at s, run the tank, and at index j it goes negative for the first time. Pick any s' ∈ [s+1, j]. Call P(a, b) = diff[a] + diff[a+1] + … + diff[b].

Because s did not fail before j, every prefix P(s, s'-1) for s' ≤ j is ≥ 0. So:

P(s', j) = P(s, j) − P(s, s'−1) ≤ P(s, j) < 0

So station s' also runs the tank negative by j. None of s+1, …, j can be a valid start. We may jump straight to j+1 without re-checking them.

Combined with "if total fuel is non-negative there is a valid start somewhere", this proves one left-to-right pass is enough.

4. Code (C++)

class Solution {
public:
    int canCompleteCircuit(vector<int>& gas, vector<int>& cost) {
        int totalTank = 0, curTank = 0, start = 0;
        for (int i = 0; i < (int)gas.size(); i++) {
            int diff = gas[i] - cost[i];
            totalTank += diff;                 // does one full lap even work?
            curTank  += diff;                  // running tank from current start
            if (curTank < 0) {               // start..i all fail; skip past i
                start = i + 1;
                curTank = 0;
            }
        }
        return totalTank >= 0 ? start : -1;
    }
};

Complexity: single pass, constant work per station. O(n) time, O(1) space. We never wrap around physically because once total tank is non-negative, the chosen start is provably valid; we rely on the exchange argument, not on a second lap.

5. The part interviewers ask about: how do we know start actually completes the lap?

Two things to prove together:

(a) If sum(diff) < 0 the answer is -1. Over a full lap the tank returns to its start value plus sum(diff). If that is negative, you cannot be where you started with non-negative fuel. No start works.

(b) If sum(diff) ≥ 0, the final start completes the lap. Call it s. By the exchange argument, every reset proves that no earlier station is a valid start, so a valid start, if one exists, is ≥ s. From s onward to n - 1 the tank never dipped negative (otherwise we would have reset again). The remaining concern is the wrap-around [0, s-1]. But

P(s, n−1) + P(0, s−1) = sum(diff) ≥ 0

and P(s, n-1) is the final curTank, which is itself ≥ 0. So P(0, s-1) ≥ -P(s, n-1) ≥ -∞… that is weak. The tighter version uses the fact that during the earlier walk the prefix P(0, s-1) dropped below every intermediate low (it is what caused the reset at s-1). More carefully: let m be the minimum of all prefix tanks starting at 0. That minimum is reached at some index s* - 1, and we set start = s*. From there the running sum is P(s*, k) = P(0, k) - m, which is ≥ 0 for all k ≥ s* (because m was the minimum). For k < s* the wrapped sum is P(s*, n-1) + P(0, k) = sum(diff) + (P(0, k) - P(0, s* - 1)) - P(0, s* - 1) + P(0, s* - 1) ≥ sum(diff) ≥ 0 (using P(0, k) ≥ m = P(0, s* - 1)). So the tank stays non-negative on the whole lap.

Picture the proof as a graph. Plot the prefix tank from index 0. The valid start is the index right after the lowest valley. Starting at that index shifts the whole plot up by the depth of the valley, which lifts every value to ≥ 0, and the wrap-around is covered because the total change over one lap is non-negative.

6. Traps and edge cases

  • Checking totalTank at the end is required. The algorithm will happily return some start even on infeasible inputs; the final guard is what returns -1.
  • Do not forget to reset curTank to 0, not to diff. After a reset, the next station is a fresh start with an empty tank, and its own diff is added in the next loop iteration.
  • Nested loops that try every start. O(n2) accepts smaller cases on LeetCode but fails performance tests. The single-pass greedy is the expected solution.
  • Interpreting "exactly one" guarantee. LC guarantees at most one. "Exactly one" is only when total diff is non-negative; in that case this algorithm returns it. Otherwise the answer is -1.
  • n = 1. You just need gas[0] ≥ cost[0]. The code handles it: one iteration, totalTank = diff; if negative, final guard returns -1, else start = 0.

7. How to say it in the interview (30 seconds)

"I define diff[i] = gas[i] - cost[i] and walk once left to right. I keep two running totals: a global totalTank and a local curTank from the current start candidate. Whenever curTank drops below zero, I know no station in [start, i] can be a valid start, so I set start = i + 1 and reset curTank to 0. At the end, if totalTank ≥ 0 I return the last start, otherwise -1. The greedy skip is justified by an exchange argument on prefix sums. O(n), O(1)."
