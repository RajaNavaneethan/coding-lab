Word Break

LeetCode 139 · Medium · Pattern: 1-D DP over string prefixes · O(n2 · L) time, O(n) space

Problem. Given string s and dictionary wordDict, return true if s can be split into one or more dictionary words (words may repeat).
s = "leetcode", dict = ["leet","code"] → true
s = "applepenapple", dict = ["apple","pen"] → true
s = "catsandog", dict = ["cats","dog","sand","and","cat"] → false
Link: LeetCode

1. The one idea that solves it

Define dp[i] = true if the first i characters of s (that is s[0..i)) can be split into dictionary words. The whole string is just the prefix of length n, so the answer is dp[n].

Base: dp[0] = true. The empty prefix is trivially a valid "sum of zero words".

For i > 0, scan every split point j < i. If dp[j] is true and s[j..i) is a dictionary word, then dp[i] is true too:

dp[i] = ∃ j < i:  dp[j] ∧ s[j..i) ∈ dict

The intuition: pick a last word ending at index i. Its start is some j; before j we need another valid split (that's dp[j]).

Idea. dp[i] asks "can I reach position i?" You can reach i iff you can reach some earlier position j and the chunk s[j..i) is a word in the dictionary. The scan is a 1-D reachability over positions.

2. Picture of the algorithm

Put the dictionary in a unordered_set for O(1) lookup. Then dp[i] for a prefix of length i costs at most O(i) tries, each a substring + hash. The whole table is O(n2) tries, each a substring hash of average length L. You can prune the inner loop by only checking j values where i − j ≤ max word length.

4. Code (C++)

class Solution {
public:
    bool wordBreak(string s, vector<string>& wordDict) {
        unordered_set<string> words(wordDict.begin(), wordDict.end());
        int n = s.size();
        vector<bool> dp(n + 1, false);
        dp[0] = true;
        for (int i = 1; i <= n; i++) {
            for (int j = 0; j < i; j++) {
                if (dp[j] && words.count(s.substr(j, i - j))) {
                    dp[i] = true;
                    break;                 // one witness is enough
                }
            }
        }
        return dp[n];
    }
};

Complexity: O(n2 · L) time — n · n pairs, each with a substring of average length L and an O(L) hash lookup. O(n · L) space including the hash set, O(n) for dp alone.

Alternative: only try plausible word lengths

int maxLen = 0;
for (auto& w : wordDict) maxLen = max(maxLen, (int)w.size());
for (int i = 1; i <= n; i++) {
    for (int j = max(0, i - maxLen); j < i; j++) {
        if (dp[j] && words.count(s.substr(j, i - j))) { dp[i] = true; break; }
    }
}

Any j farther back than maxLen can't match — no word is that long. This is a constant-factor win when dictionary words are much shorter than s.

5. The part interviewers ask about: why "greedy from the left" fails

A tempting approach: at each position, grab the longest word that matches and move on. This is wrong because the right split can depend on information that is not yet visible.

Example: s = "aaab", dict = ["a", "aa", "aaab"]. Greedy longest-first takes aaab directly and succeeds, fine. But flip to s = "aaaab", dict = ["aaa", "aab", "a"]: longest-first grabs aaa at position 0, leaves ab, which is not in the dictionary — it reports false. The real split is a + aab + ... wait, that one is actually impossible too; take instead s = "aaaaab", dict = ["aaaa", "aab", "b"]: greedy picks aaaa, leaves ab, fails; DP finds aa? no, aa is not in the dict; actually the right split is aaa? not in dict either, so neither works here — the point is that only exhaustive search over split points is guaranteed.

Greedy or any ordered scan can commit to a word that prevents a later match. DP tries every split, so if any valid split exists it finds one. The break inside the inner loop only exits the search for this dp[i], not the whole algorithm.

Also notice we only need to know whether a split exists, not which words. For "give me the actual split" you record a parent[i] = j at the moment you set dp[i] = true, then walk back from n. That's LC 140 Word Break II territory, which is a different problem (and uses backtracking + memoisation because it must enumerate all splits).

6. Traps and edge cases

  • Forgetting dp[0] = true. Without the empty-prefix base, no cell ever becomes true and everything is false.
  • Checking only one window length. You must try all j from 0 (or i − maxLen) to i − 1, not just i − 1.
  • Using vector<string> as a lookup. O(dict size) per check turns the whole algorithm O(n2 · dict). Use unordered_set.
  • Word repetition. Words can be used any number of times — the DP already allows it, because at every i we re-check the whole dictionary.
  • Empty string. n = 0, so dp[0] = true is returned. LeetCode's constraints don't actually allow this, but your code should still handle it.
  • Dictionary bigger than needed. Letters outside s don't hurt, but you may want to filter the dictionary to words whose letters all appear in s as a fast reject.

7. How to say it in the interview (30 seconds)

"I define dp[i] as true if the first i characters split into dictionary words. Base dp[0] = true. For each prefix length i I look for a split point j such that dp[j] is true and s[j..i) is in the dictionary. I put the dictionary in a hash set, so each (i, j) pair is an O(L) substring and hash lookup, giving O(n2 · L) time overall. The answer is dp[n]. I can prune by only scanning j within maxWordLength of i."
