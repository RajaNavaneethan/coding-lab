3Sum

LeetCode 15 · Medium · Pattern: sort + fix anchor + L/R two pointers · O(n2) time, O(1) extra space

Problem. Return every unique triple [a, b, c] from nums with a + b + c = 0. The returned list cannot contain duplicate triples.
[-1,0,1,2,-1,-4] → [[-1,-1,2], [-1,0,1]]    [0,0,0] → [[0,0,0]]
Link: LeetCode

1. The one idea that solves it

Sort first. Then fix the leftmost element of the triple at index i, and the rest is Two Sum II on the suffix nums[i+1..n-1]: find pairs that sum to -nums[i] using two pointers l and r. The sorted order makes a hit, miss, and shift decision O(1) per step.

Sorting pays for itself three times over:

  1. Two pointers work only on a sorted suffix.
  2. Duplicates sit next to each other, so skipping them is a one-line while.
  3. We can stop early when nums[i] > 0: the suffix is all positive, so no triple can sum to zero.
Idea. Sort. For each anchor i, run L/R two pointers on nums[i+1..] looking for -nums[i]. On a hit, record the triple, then skip over duplicates on both sides before advancing.

4. Code (C++)

class Solution {
public:
    vector<vector<int>> threeSum(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        vector<vector<int>> ans;
        int n = nums.size();
        for (int i = 0; i + 2 < n; i++) {
            if (nums[i] > 0) break;                      // suffix all positive
            if (i > 0 && nums[i] == nums[i-1]) continue;  // skip duplicate anchor
            int l = i + 1, r = n - 1;
            while (l < r) {
                long long s = (long long)nums[i] + nums[l] + nums[r];
                if (s < 0) l++;
                else if (s > 0) r--;
                else {
                    ans.push_back({nums[i], nums[l], nums[r]});
                    while (l < r && nums[l] == nums[l+1]) l++;  // skip dup l
                    while (l < r && nums[r] == nums[r-1]) r--;  // skip dup r
                    l++; r--;
                }
            }
        }
        return ans;
    }
};

Complexity: sort is O(n log n). Each anchor runs a linear two-pointer sweep, so the main work is O(n2). No extra data structure beyond the output: O(1) extra space (ignoring the output).

5. The part interviewers ask about: three dedup rules, not one

  • Anchor dedup. if (i > 0 && nums[i] == nums[i-1]) continue; This skips the second -1 in [-4,-1,-1,0,1,2]: using it as an anchor would recreate every triple the first -1 already found.
  • L dedup on hit. After recording a triple, while (nums[l] == nums[l+1]) l++; then l++. This skips the second 0 in [0,0,0,0] so [0,0,0] is reported only once.
  • R dedup on hit. Symmetric. Required for inputs with repeated large positives like [-2,0,1,1,2,2]: without R dedup you report [-2,0,2] twice.
Dedup only matters after a hit. On s < 0 or s > 0 you just move one side; duplicates there would never produce a hit either, so no need to skip pre-emptively.

Why not use a hash set to drop duplicates?

You can. Hash a triple's string key and insert into an unordered_set. It costs an extra O(n2) space, more allocations, and hides the structure of the problem. The three local while loops are tighter and make the dedup logic visible.

6. Traps and edge cases

  • Forgetting one of the three dedup rules. You will fail [0,0,0,0], [-2,0,0,2,2], or similar. The failure is "triple appears twice", not a wrong triple.
  • Comparing nums[i] == nums[i+1] instead of nums[i] == nums[i-1]. The former skips the first occurrence of a duplicated anchor, which is the one you want to keep.
  • Overflow. With |nums[i]| ≤ 105, three ints sum fits in int on LC. The long long cast above is defensive; you can drop it if constraints allow.
  • nums[i] > 0 break. Optional optimisation. Skipping it is still correct, just slower.
  • Returning indices. This problem wants values, not indices. Sort is free, unlike in LC 1.
  • Empty or small input. n < 3 → return {}. The loop bound i + 2 < n handles it with no special case.

7. How to say it in the interview (30 seconds)

"Sort, then fix each number as an anchor and run two pointers on the rest looking for pairs that sum to minus the anchor. If the sum is too small advance L, too big retreat R, equal record and dedup both sides. Also dedup the anchor itself. Sort is O(n log n), the two-pointer sweep is O(n) per anchor, so overall O(n2). The three dedup while loops are what stop duplicate triples from appearing."
