Minimum Window Substring

LeetCode 76 · Hard · Pattern: variable-size sliding window, shrink to minimise · O(|s| + |t|) time, O(Σ) space

Problem. Given strings s and t, return the shortest substring of s that contains every character of t (with multiplicity). Return "" if no such window exists.
s = "ADOBECODEBANC", t = "ABC" → "BANC"
s = "a", t = "aa" → ""
Link: LeetCode

1. The one idea that solves it

Keep two counts over the characters in t: need[c] (how many of c must be in the window) and have[c] (how many are in the window right now). The window is valid when have[c] ≥ need[c] for every c.

Grow to the right. The moment the window becomes valid, try to shrink from the left while it stays valid, recording the smallest valid window seen. Then grow again.

Comparing all 128 or 52 counts after every move is wasteful. Track one integer: formed = the number of distinct characters whose have[c] has reached need[c]. The window is valid exactly when formed == required (required = distinct characters in t). You only need to touch formed when a count crosses the threshold either way.

So the question becomes: maintain need, have, and the counter formed. Expand right until formed == required, shrink left as long as that stays true (recording bestLen), expand again. One left-to-right pass over s.

4. Code (C++)

string minWindow(string s, string t) {
    if (t.empty() || s.size() < t.size()) return "";
    int need[128] = {0}, have[128] = {0};
    for (char c : t) need[(unsigned char)c]++;
    int required = 0;
    for (int i = 0; i < 128; i++) if (need[i]) required++;

    int formed = 0, l = 0, bestLen = INT_MAX, bestL = 0;
    for (int r = 0; r < (int)s.size(); r++) {
        int c = (unsigned char)s[r];
        have[c]++;
        if (need[c] && have[c] == need[c]) formed++;      // just hit the threshold
        while (formed == required) {                        // shrink while valid
            if (r - l + 1 < bestLen) { bestLen = r - l + 1; bestL = l; }
            int lc = (unsigned char)s[l];
            have[lc]--;
            if (need[lc] && have[lc] < need[lc]) formed--;  // fell below the threshold
            l++;
        }
    }
    return bestLen == INT_MAX ? "" : s.substr(bestL, bestLen);
}

Complexity: each index in s is visited once by r and at most once by l, so O(|s| + |t|). Space is O(Σ) for the two count arrays, O(1) when the alphabet is fixed.

Alternative: filter s down to characters that appear in t

When |t| is tiny compared to |s|, you can first build a list of positions in s whose character is in t, then run the same window over that list. Each shrink/expand costs the same but you skip over irrelevant characters. Same asymptotic complexity, faster constants on sparse inputs.

5. The part interviewers ask about: why one counter beats comparing maps

The naive version re-checks "every have[c] ≥ need[c]" after every move. That is O(Σ) per step. On the full string that gives O(|s| · Σ). Fine for ASCII, slow for Unicode or paragraphs.

Why formed is correct. A character c contributes to formed while have[c] ≥ need[c]. have[c] changes by ±1 per operation, so it crosses the threshold need[c] only at one specific moment during an expand and one specific moment during a shrink. Incrementing/decrementing formed exactly at those crossings keeps it consistent with the real state. The guard need[c] ensures characters not in t never affect formed.

Follow-up: what if a character can appear with any count (just "at least one occurrence")? Set required = distinct chars in t, and have[c] ≥ 1 contributes. The code simplifies: no need to count copies.

Why we record bestLen at the top of the shrink loop, not after. The window is valid at the instant we enter the loop body. If we shrink first and then check, we might skip past the smallest valid window, because the step that removes the last required copy both invalidates the window and advances l.

Can this be done with two pointers but no counts? No. "Contains all of t" is not a monotone substring predicate in the sense you can test by looking at endpoints alone; you need to know the multiset.

6. Traps and edge cases

  • Treating t as a set. t = "aabc" needs two as. If you lose the counts, "abc" would wrongly match.
  • Incrementing formed on every match. It must increment only when have[c] == need[c] for the first time. A later extra copy keeps the window valid but should not bump formed again.
  • Decrementing formed on every removal. It must decrement only when have[c] drops below need[c]. If you had extras, removing one still leaves the character satisfied.
  • Recording bestLen outside the while loop. You miss the smallest window.
  • Returning s.substr(l, bestLen) instead of s.substr(bestL, bestLen). l has moved past the best window by the end.
  • t longer than s, or empty t. Guard early and return "".
  • Mixed case. The problem is case-sensitive. s = "ab", t = "A" → "".

7. How to say it in the interview (30 seconds)

"I count the characters in t into need, and track have for the current window. To avoid re-checking the whole map, I keep a single counter formed that counts how many characters have reached their required count. I expand to the right, bumping formed when a count hits the threshold; while the window is valid (formed == required) I shrink from the left, recording the smallest valid window, and I drop formed when a count falls below. O(|s| + |t|) time."
