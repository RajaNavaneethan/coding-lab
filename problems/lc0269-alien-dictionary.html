Alien Dictionary

LeetCode 269 · Hard (Premium) · Pattern: topological sort (Kahn) over inferred letter order · O(C) time, O(1) extra on the alphabet, where C is total characters

Problem (LeetCode Premium). You are given words sorted lexicographically under some unknown alien letter order. Return any valid total order of the letters that is consistent with the sort, or "" if no order is consistent.
["wrt","wrf","er","ett","rftt"] → "wertf"
["z","x"] → "zx"
["z","x","z"] → "" (cycle: z < x and x < z)
["abc","ab"] → "" ("abc" cannot precede its own prefix "ab" in any dictionary order)
Note: the problem is Premium; the same pattern is free in LC 2392, included separately.

1. The one idea that solves it

A sorted dictionary leaks pairwise information about the letter order: for two consecutive words a and b, scan until the first differing character. That one pair tells you a[k] < b[k] in the alien order. Nothing else is implied by that pair — and in particular the later characters are irrelevant, because the sort only cared about the first mismatch.

Collect all those pairs as directed edges on the letters. The letters themselves are the vertices — every letter that appears anywhere in words must appear in the output. The problem is then "topological sort of this DAG". If the graph is cyclic, no order is consistent → return "".

One sharp special case: if a is a prefix of b ("ab" before "abc"), there is no differing character; the pair gives no edge, which is fine. But if b is a prefix of a ("abc" before "ab"), the sort is already broken — no dictionary order can place a longer word before its own prefix — so we return "" immediately.

Idea. Each consecutive word pair contributes at most one edge (first differing char). The letter set is every character that ever appears. Run Kahn's topological sort over that graph; a cycle (fewer letters emitted than exist) means no valid order. Handle the "longer word before its prefix" case up front.

2. Picture of the algorithm

Why Kahn (BFS) over DFS? Both work; Kahn is easier to defend because the "zero in-degree" queue literally reads as "a letter that no other letter must come before, so it can go next". It also finds cycles for free: if the final output has fewer letters than the vertex set, exactly the letters stuck in a cycle were skipped.

3. Step-by-step trace

Enter a word list. The run first scans each adjacent pair to extract one edge (or detect the prefix violation), then runs Kahn's queue. Each step shows the current graph (letters + edges), the in-degree numbers, and the queue/output state.

4. Code (C++)

class Solution {
public:
    string alienOrder(vector<string>& words) {
        unordered_map<char, unordered_set<char>> adj;
        unordered_map<char, int> indeg;

        // Register every letter that ever appears.
        for (auto& w : words)
            for (char c : w) if (!indeg.count(c)) indeg[c] = 0;

        // One edge per consecutive pair; detect prefix violation.
        for (int i = 0; i + 1 < (int)words.size(); i++) {
            const string& a = words[i];
            const string& b = words[i + 1];
            int m = (int)min(a.size(), b.size());
            bool found = false;
            for (int k = 0; k < m; k++) {
                if (a[k] != b[k]) {
                    if (!adj[a[k]].count(b[k])) {
                        adj[a[k]].insert(b[k]);
                        indeg[b[k]]++;
                    }
                    found = true;
                    break;
                }
            }
            if (!found && a.size() > b.size()) return ""; // "abc" before "ab"
        }

        // Kahn's BFS over the letter DAG.
        queue<char> q;
        for (auto& p : indeg) if (p.second == 0) q.push(p.first);
        string out;
        while (!q.empty()) {
            char c = q.front(); q.pop();
            out += c;
            for (char nb : adj[c])
                if (--indeg[nb] == 0) q.push(nb);
        }
        return out.size() == indeg.size() ? out : "";
    }
};

Complexity. Scanning all pairs costs O(C), where C is the total characters across words. Kahn's is O(V + E), with at most 26 vertices and at most words.size() - 1 edges. So O(C) total, constant on the alphabet.

Alternative: DFS with post-order and 3-colour cycle detection

bool dfs(char u) {
    color[u] = 1;                            // visiting
    for (char v : adj[u]) {
        if (color[v] == 1) return false; // cycle
        if (color[v] == 0 && !dfs(v)) return false;
    }
    color[u] = 2;                            // finished; prepend to answer
    out.push_back(u);
    return true;
}

Reverse the out vector at the end to get a valid topological order. Same complexity; use Kahn when asked to produce any valid order and defend it from zero-in-degree reasoning, DFS when you also need the exact post-order for free (e.g. SCC via Tarjan).

5. The part interviewers ask about: why only the first differing character?

Dictionary order sorts by the first position where strings differ — nothing after that position was consulted. So a < b only tells us one strict ordering between a[k] and b[k], not between the later letters. Pulling more edges from a single pair is incorrect: it would introduce constraints that the sort never actually implied.

The prefix case is where almost everyone slips. "ab" < "abc" is consistent with any order: no edge needed. But "abc" < "ab" contradicts every total order on letters, because the dictionary sort compares character-by-character and treats "end of string" as smaller than any letter. If both pairs share every letter and the first is strictly longer, no edge is derivable and the input is already inconsistent → return "".

Second question: how do we handle a disconnected letter graph? Each letter is a vertex regardless of whether it participates in an edge. An isolated letter has in-degree 0, so Kahn's enqueues it immediately. It appears in the output in some arbitrary position relative to the rest — which is correct, because nothing about the sort constrains where it goes.

Third: the problem says "return any valid order", not the lex-smallest. Multiple orders can satisfy the constraints, and both Kahn and DFS can produce different ones depending on container iteration. If an interviewer asks for the lex-smallest order, swap Kahn's queue for a priority_queue (min-heap) and keep everything else the same.

6. Traps and edge cases

  • Missing the prefix violation. ["abc","ab"] must return "". Easy to miss when the pair-scanning loop exits with found = false and no edge was added — you still have to reject if a.size() > b.size().
  • Double-counting an edge. If the same pair (x, y) appears in two different word pairs, increment indeg[y] only once. Guard with if (!adj[x].count(y)).
  • Forgetting isolated letters. Any letter appearing anywhere in words must appear in the output. Initialise indeg[c] = 0 for every letter before adding edges.
  • Treating identical words as a prefix violation. ["ab","ab"] is fine — equal strings are consistent with any order. The check is a.size() > b.size(), strictly greater.
  • Returning the alphabet when the input is empty. No words → no letters known → return "" (there are no letters to order).
  • Cycle vs. ambiguity. A graph with multiple topological orders is not a cycle. Returning "insufficient information" is wrong unless the interviewer asks for that distinction — LC 269 wants any valid order.
  • Using vector<char> adjacency without dedup. Duplicate edges inflate in-degrees and leave letters stuck. Use unordered_set or check for presence before incrementing.

7. How to say it in the interview (30 seconds)

"The dictionary sort gives me one letter-order edge per consecutive pair: scan to the first differing character. I collect those edges as a graph over all letters that appear, then run Kahn's topological sort — a queue of zero in-degree letters, pop one into the output, decrement each neighbour's in-degree, enqueue when it hits zero. If the output ends up shorter than the letter set there is a cycle, so I return the empty string. One trap: when a word strictly contains the next word as a prefix the input is already inconsistent, so I check that up front. Linear in total input."
