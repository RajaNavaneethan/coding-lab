Kth Largest Element in an Array

LeetCode 215 · Medium · Pattern: size-k min-heap · O(n log k) time, O(k) space

Problem. Return the kth largest element in an unsorted array nums. "kth largest" means the one that would sit at position n-k after sorting ascending (not the kth distinct value).
[3,2,1,5,6,4], k=2 → 5.    [3,2,3,1,2,4,5,5,6], k=4 → 4.
Link: LeetCode

1. The one idea that solves it

You do not need the whole sorted array. You only need to know what sits at rank k from the top. So keep a small bag of size k that always holds the k largest numbers seen so far. When a new number arrives, add it; if the bag exceeds k, throw away the smallest element of the bag. At the end, the bag holds the top k, and the one at the bottom (its minimum) is the answer.

The "smallest of the bag" needs to be found and removed in O(log k). That is exactly what a min-heap does: top() is the smallest, pop() removes it. A max-heap of size n would also work but costs O(n) space; the min-heap trick keeps space to O(k).

Idea. Keep a min-heap of the k largest numbers seen so far. Push every new number; whenever size > k, pop the smallest. The heap's top() at the end is the kth largest.

2. Picture of the algorithm

A heap is a complete binary tree with the heap property. In a min-heap each parent is less than or equal to its children, so the root is the smallest. The array layout is level order: for a node at index i, its children are at 2i+1 and 2i+2. Push bubbles up, pop swaps the root with the last leaf and sifts down.

4. Code (C++)

int findKthLargest(vector<int>& nums, int k) {
    priority_queue<int, vector<int>, greater<int>> pq;   // min-heap
    for (int x : nums) {
        pq.push(x);
        if ((int)pq.size() > k) pq.pop();              // drop the smallest; keep top-k
    }
    return pq.top();                                   // smallest of the top-k = k-th largest
}

Complexity: each element does at most one push and one pop, each O(log k). Total O(n log k) time and O(k) space.

About greater<int>. std::priority_queue is a max-heap by default: the "top" is the element the comparator says is largest, and the default comparator is less<int> (a < b). To get a min-heap you flip the comparator to greater<int>, so the "top" is now whatever greater ranks highest, which is the smallest number. The rule to remember: top is the element the comparator deems the largest; pass greater to invert the order.

Alternative: quickselect (expected O(n))

int findKthLargest(vector<int>& nums, int k) {
    int target = (int)nums.size() - k;                   // index in sorted ascending order
    int lo = 0, hi = (int)nums.size() - 1;
    mt19937 rng(random_device{}());
    while (lo <= hi) {
        int p = lo + rng() % (hi - lo + 1);              // random pivot avoids O(n^2)
        swap(nums[p], nums[hi]);
        int pivot = nums[hi], store = lo;
        for (int i = lo; i < hi; i++)
            if (nums[i] < pivot) swap(nums[i], nums[store++]);
        swap(nums[store], nums[hi]);                        // final pivot position
        if (store == target) return nums[store];
        if (store < target) lo = store + 1;
        else hi = store - 1;
    }
    return -1;
}

Quickselect is partition-based, like quicksort but it only recurses into the side that contains the target rank. Expected O(n), worst case O(n2). Prefer it when the interviewer asks for linear-time average. The heap is the safer default: deterministic O(n log k), simpler code, friendlier to streaming input (you need not know n up front).

5. The part interviewers ask about: why a size-k min-heap, not a size-k max-heap

A beginner reads "kth largest" and reaches for a max-heap. A max-heap of all n elements works — pop k times and the last pop is the answer — but it costs O(n) space and O(n + k log n) time. The size-k min-heap is better: the heap holds exactly the top-k candidates. Its root is the smallest number in that bag, which is the exact threshold a new number must beat to belong to the top-k. So you compare the new number against the root and either skip it or evict the root.

A second angle: the min-heap approach is naturally a streaming algorithm. If numbers arrive one by one and you cannot store them all, you can still maintain the top-k in O(k) memory. Quickselect needs the whole array in memory.

6. Traps and edge cases

  • Default priority_queue<int> is a max-heap. Omitting the greater<int> template argument gives you a max-heap, and the whole algorithm breaks silently. Always spell out the comparator.
  • Order of push and pop. Push first, then pop if size > k. If you pop before pushing, you drop one of the current top-k.
  • Returning pq.top() after draining the heap. Only call top() while the heap is non-empty. Here the final heap has exactly k elements, so it is fine.
  • Duplicates. kth largest is not the kth distinct value. [7,7,7,7], k=3 → 7. The heap approach handles this; naive "use a set" does not.
  • Negative numbers and all-equal arrays. The algorithm is comparison-based and does not care about signs or ties. Just make sure your test harness covers them.
  • Quickselect pivot choice. A deterministic "always pick the last element" pivot is O(n2) on a sorted input. Use a random pivot or median-of-three.
  • Quickselect on a copy. Quickselect reorders nums in place. If the caller expects the array unchanged, copy first.

7. How to say it in the interview (30 seconds)

"I keep a min-heap of size k. I push every number; whenever the heap grows past k, I pop the smallest. At the end the heap holds the top-k numbers, and its root is the smallest of those, which is the kth largest overall. In C++ that is priority_queue<int, vector<int>, greater<int>>: the default is a max-heap, so I pass greater to flip it. Time O(n log k), space O(k). If the interviewer asks for linear time, I switch to quickselect with a random pivot, average O(n), worst O(n2)."
