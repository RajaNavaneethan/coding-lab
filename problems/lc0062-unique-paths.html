Unique Paths

LeetCode 62 · Medium · Pattern: 2-D grid DP · O(m · n) time, O(m · n) space (O(min(m,n)) with the rolling trick)

Problem. A robot sits at the top-left corner (0, 0) of an m × n grid. It can move only right or down. How many distinct paths reach the bottom-right corner (m−1, n−1)?
m = 3, n = 7 → 28    m = 3, n = 2 → 3    m = 1, n = 1 → 1
Link: LeetCode

1. The one idea that solves it

Any path that ends at (i, j) must have arrived from exactly one of two cells: the one above it (i−1, j) (the robot's last move was down), or the one to its left (i, j−1) (last move was right). So the number of paths to (i, j) is the sum of the two:

dp[i][j] = dp[i−1][j] + dp[i][j−1]

Base: the first row and first column each have exactly one path (keep moving right, or keep moving down). So dp[0][*] = dp[*][0] = 1.

Idea. Every path ends with one final move: either down into (i,j) from above, or right into (i,j) from the left. Count the paths that use each kind of final move and add them. No path can arrive from any other cell, so there is no over-count.

2. Picture of the algorithm

Fill the table row by row, left to right. By the time you compute dp[i][j], both dp[i−1][j] (above, filled in the previous row) and dp[i][j−1] (left, filled one cell earlier in the same row) are already set. The answer is the bottom-right cell.

4. Code (C++)

class Solution {
public:
    int uniquePaths(int m, int n) {
        vector<vector<int>> dp(m, vector<int>(n, 1)); // first row/col all 1s
        for (int i = 1; i < m; i++) {
            for (int j = 1; j < n; j++) {
                dp[i][j] = dp[i-1][j] + dp[i][j-1];
            }
        }
        return dp[m-1][n-1];
    }
};

Complexity: O(m · n) time — one addition per cell. O(m · n) space for the table.

Alternative: one row of memory

vector<int> dp(n, 1);
for (int i = 1; i < m; i++) {
    for (int j = 1; j < n; j++) {
        dp[j] += dp[j-1]; // dp[j] is "above", dp[j-1] is "left"
    }
}
return dp[n-1];

When you process cell (i, j), dp[j] still holds the value from row i−1 (that's the "above" cell) and dp[j−1] already holds the new value from row i (that's "left"). Add them in place. Prefer this on a cramped interview whiteboard; the 2-D version is easier to explain.

5. The part interviewers ask about: the closed form

Every path takes exactly m − 1 down moves and n − 1 right moves, in some interleaving. So the answer is the number of ways to choose which of the m + n − 2 steps are the down moves:

C(m + n − 2, m − 1)
The DP is really just computing one entry of Pascal's triangle: dp[i][j] = C(i + j, i). You can verify by induction: Pascal's identity is C(i+j, i) = C(i+j−1, i−1) + C(i+j−1, i), which is exactly the recurrence shifted by one. Interviewers love this because it reduces the problem to an O(min(m, n)) multiplication, no table at all.

Careful with overflow if you compute the binomial directly: (m+n−2)! blows up fast. Compute it as a running product, dividing by k at each step (which stays integer because the partial product is C(i+j, i) at every stage).

6. Traps and edge cases

  • Zero-initialising the whole grid. The recurrence then gives dp[i][j] = 0 everywhere. You must seed the first row and column with 1, or seed dp[0][0] = 1 and treat out-of-range reads as 0.
  • Looping from i = 0, j = 0. The recurrence reads dp[-1][0]. Either start the loops at 1, or guard with if (i == 0 || j == 0) dp[i][j] = 1.
  • Big grids and overflow. At m = n = 23 the answer C(44, 22) is already past 2^31. LC's constraints keep it under 2 · 109 but barely — use int safely, but the closed-form binomial needs 64-bit intermediates.
  • Confusing with "Unique Paths II" (LC 63). That version has obstacles. The recurrence is the same but a blocked cell has dp = 0, and the first row/column stop being all ones at the first obstacle.
  • Confusing with "Minimum Path Sum" (LC 64). Same table shape, but you take min of above/left and add the cell's cost. The recurrence structure is identical; the semantic (count vs min cost) differs.

7. How to say it in the interview (30 seconds)

"I define dp[i][j] as the number of paths from (0,0) to (i,j). Every path's last move was either down or right, so dp[i][j] = dp[i−1][j] + dp[i][j−1]. The first row and column are all 1 (one path, straight line). I fill the table row by row and return dp[m−1][n−1]. That's O(m · n) time and space; I can roll to one row and get O(n) space. For a bonus: the answer equals the binomial C(m+n−2, m−1) because every path is a specific interleaving of m−1 downs and n−1 rights."
