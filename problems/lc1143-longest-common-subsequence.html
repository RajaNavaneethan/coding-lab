Longest Common Subsequence

LeetCode 1143 · Medium · Pattern: 2-D DP on two strings · O(m · n) time, O(m · n) space (O(min(m,n)) rolling)

Problem. Given two strings text1 and text2, return the length of their longest common subsequence. A subsequence keeps the original order but may skip characters.
"abcde", "ace" → 3 (ace)    "abc", "abc" → 3    "abc", "def" → 0
Link: LeetCode

1. The one idea that solves it

Define dp[i][j] as the LCS length of the prefixes text1[0..i) and text2[0..j). Look at the two last characters:

  • If text1[i−1] == text2[j−1], those two characters can both be the last letter of the LCS. Strip them and solve the smaller problem: dp[i][j] = dp[i−1][j−1] + 1.
  • Otherwise, at least one of them is not used in the LCS. Try dropping each in turn and take the better one: dp[i][j] = max(dp[i−1][j], dp[i][j−1]).
dp[i][j] = text1[i−1]=text2[j−1] ? dp[i−1][j−1]+1 : max(dp[i−1][j], dp[i][j−1])

Base: dp[0][*] = dp[*][0] = 0. An empty string shares nothing with anything.

Idea. On the two end characters there are only two cases. If they match, the LCS of the prefixes gains a character for free; the question reduces to the shorter prefixes on both sides. If they don't match, the LCS cannot use both of them, so the answer is the best of "drop the end of text1" or "drop the end of text2". No third option exists.

2. Picture of the algorithm

Fill the table row by row, left to right. Row i and column j are 1-indexed into the DP, so cell (i, j) is comparing text1[i−1] with text2[j−1]. The answer is in the bottom-right cell.

4. Code (C++)

class Solution {
public:
    int longestCommonSubsequence(string text1, string text2) {
        int m = text1.size(), n = text2.size();
        vector<vector<int>> dp(m + 1, vector<int>(n + 1, 0));
        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                if (text1[i-1] == text2[j-1]) dp[i][j] = dp[i-1][j-1] + 1;
                else dp[i][j] = max(dp[i-1][j], dp[i][j-1]);
            }
        }
        return dp[m][n];
    }
};

Complexity: O(m · n) time — one constant-work decision per cell. O(m · n) space; can be reduced to O(min(m, n)) with one rolling row.

Alternative: one rolling row

vector<int> dp(n + 1, 0);
for (int i = 1; i <= m; i++) {
    int prevDiag = 0;             // dp[i-1][j-1] from last iteration
    for (int j = 1; j <= n; j++) {
        int save = dp[j];           // current dp[j] is dp[i-1][j]
        if (text1[i-1] == text2[j-1]) dp[j] = prevDiag + 1;
        else dp[j] = max(dp[j], dp[j-1]);
        prevDiag = save;
    }
}
return dp[n];

Keep one prevDiag variable to remember the top-left before we overwrite it. Use when memory matters, e.g. for very long strings or whenever you'd otherwise allocate an n × m grid.

5. The part interviewers ask about: recovering the subsequence

The length alone is often not enough. To rebuild the actual LCS, walk back from dp[m][n]:

  • If text1[i−1] == text2[j−1]: that character is in the LCS, move to (i−1, j−1).
  • Else if dp[i−1][j] ≥ dp[i][j−1]: move up to (i−1, j).
  • Else: move left to (i, j−1).

Prepend the match-characters to a string along the way, until i = 0 or j = 0. The walk is O(m + n), so you don't need to store any extra parent pointers — the DP table encodes the choices.

LCS and the Longest Palindromic Subsequence (LC 516) are the same problem: the longest palindromic subsequence of s is LCS(s, reverse(s)). Any palindromic subsequence of s read in order equals itself read in reverse, so it also sits inside reverse(s) at matching positions.

6. Traps and edge cases

  • Confusing subsequence with substring. Substrings must be contiguous. "ace" is a subsequence of "abcde" but not a substring. The Longest Common Substring problem is similar in shape but resets to 0 on a mismatch instead of taking the max of neighbours.
  • Off-by-one. The DP is 1-indexed (dp[0][*] is the empty prefix), the strings are 0-indexed. So cell (i, j) compares text1[i−1] and text2[j−1], not text1[i].
  • Taking dp[i−1][j−1] + 1 on a mismatch too. That counts a letter that is not in both strings. The branch is only valid when the two characters are equal.
  • Both strings empty or one empty. Returns 0 from the base, no special case needed.
  • Reporting the subsequence as a set. It's a sequence: order and multiplicity matter. "aa" and "a" are different subsequences of "aba".

7. How to say it in the interview (30 seconds)

"I define dp[i][j] as the LCS length of the two prefixes text1[0..i) and text2[0..j). If the last characters match, I take dp[i−1][j−1] + 1; otherwise I take the better of dropping one end: max(dp[i−1][j], dp[i][j−1]). Base is zero for empty prefixes. Fill the table row by row and return dp[m][n]. That's O(m · n) time and space, and the space drops to O(min(m, n)) with one rolling row if I keep a prevDiag variable. If asked for the actual string, I walk back from (m, n) following which neighbour we came from."
