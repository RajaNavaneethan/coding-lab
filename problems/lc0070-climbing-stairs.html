Climbing Stairs

LeetCode 70 · Easy · Pattern: 1-D DP (Fibonacci recurrence) · O(n) time, O(1) space

Problem. You climb n stairs. Each step you take 1 or 2 stairs. Return the number of distinct ways to reach step n.
n = 2 → 2    n = 3 → 3    n = 5 → 8
Link: LeetCode

1. The one idea that solves it

To reach step i your last move was either a 1-step (from i-1) or a 2-step (from i-2). Those two sources of arrivals do not overlap, because the last move length is different. So the ways to reach i are the sum of ways to reach i-1 and i-2.

dp[i] = dp[i−1] + dp[i−2]

Base: dp[1] = 1 (only "1"), dp[2] = 2 ("1+1" or "2"). Everything above is the sum of the two cells on its left. This is the Fibonacci sequence shifted by one.

Idea. Classify every path to n by its last move. Two cases, no overlap. So the count at i is the sum of the counts at i−1 and i−2.

2. Picture of the algorithm

The whole table only ever reads the two cells to the left of the current one. So you can throw the table away and keep just two running integers (shown below in the alternative code).

4. Code (C++)

class Solution {
public:
    int climbStairs(int n) {
        if (n <= 2) return n;
        vector<int> dp(n + 1, 0);
        dp[1] = 1;
        dp[2] = 2;
        for (int i = 3; i <= n; i++) dp[i] = dp[i - 1] + dp[i - 2];
        return dp[n];
    }
};

Complexity: one pass fills n cells with one addition each, so O(n) time. The array is O(n) space.

Alternative: O(1) space, two rolling variables

int climbStairs(int n) {
    if (n <= 2) return n;
    int a = 1, b = 2;                   // dp[i-2], dp[i-1]
    for (int i = 3; i <= n; i++) {
        int c = a + b;
        a = b; b = c;
    }
    return b;
}

Prefer this form in the interview: the recurrence only looks back two cells, so an array is wasteful. Mention the table version first so the interviewer sees you understand the DP; collapse to two variables once it is clear.

5. The part interviewers ask about: why the two cases don't overlap

Every path to step n ends with exactly one last move. If the last move is a 1-step, the path's prefix is a path to n−1. If the last move is a 2-step, the prefix is a path to n−2. These two families are disjoint because they are told apart by the last move's length. So the counts add, not max, not a careful inclusion-exclusion.

You will also hear "isn't this just Fibonacci?" Yes: dp[1]=1, dp[2]=2, dp[3]=3, dp[4]=5, dp[5]=8, … is Fibonacci starting one index later. If the interviewer presses on sub-linear time, mention matrix exponentiation of [[1,1],[1,0]] to get O(log n), but note that n on this problem is small (≤ 45) and the constant from fast exponentiation makes it slower in practice.

6. Traps and edge cases

  • Off-by-one on the base cases. dp[0] = 1 if you treat "no stairs" as the empty path; then dp[1] = 1, dp[2] = 2 fall out of the recurrence. Pick one convention and stick with it.
  • Starting the loop at i = 2 without first setting dp[2]. Then dp[2] is computed as dp[1] + dp[0], which only works if dp[0] = 1.
  • Overflow for large n. LeetCode caps n ≤ 45, where the answer 1,836,311,903 still fits in a signed 32-bit int. Any larger and you need long long.
  • Trying to enumerate paths. The count grows exponentially, so printing them for large n is impossible. Only the count is asked for.

7. How to say it in the interview (30 seconds)

"Classify paths to step n by the last move: either a 1-step from n−1 or a 2-step from n−2. The two groups are disjoint, so ways(n) = ways(n−1) + ways(n−2), with ways(1) = 1 and ways(2) = 2. I'd fill a table left to right; because each cell only looks back two, I collapse to two rolling variables for O(n) time and O(1) space."
