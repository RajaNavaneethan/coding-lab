Longest Increasing Subsequence

LeetCode 300 · Medium · Pattern: 1-D DP (ending-at-i) & patience sort · O(n2) or O(n log n) time, O(n) space

Problem. Given nums, return the length of the longest strictly increasing subsequence (elements keep their order, but need not be adjacent).
[10,9,2,5,3,7,101,18] → 4 (one LIS is [2,3,7,101])    [0,1,0,3,2,3] → 4    [7,7,7,7,7] → 1
Link: LeetCode

1. The one idea that solves it

Define dp[i] as the length of the longest strictly increasing subsequence that ends exactly at index i. The last two elements of any such subsequence are nums[j] and nums[i] for some j < i with nums[j] < nums[i]. Chop nums[i] off and the rest is an LIS ending at j. So:

dp[i] = 1 + max { dp[j] : j < i and nums[j] < nums[i] }

Base: dp[i] = 1 for every i (the subsequence that contains just nums[i]). The final answer is max(dp), not dp[n−1]: the LIS may end at any index.

Idea. Anchor the subsequence at its last element. For each ending position, look back at every smaller value and extend its best run by one. The LIS is the longest run found anywhere.

2. Picture of the algorithm

Two nested loops: fill dp[i] in order, scanning all j < i. Each cell only reads cells to its left, so left-to-right order is enough. There is a sharper O(n log n) method using "patience sorting"; it is in Section 4 below.

O(n log n) tails trace

Scan nums left to right, keep a side array tails. For each new x, run lower_bound(tails, x). If the result is past the end, append x (we have grown the longest run by one). Otherwise, replace the element at that position with x (we have found a smaller possible tail for a run of that length). The LIS length is tails.size().

4. Code (C++)

Main approach, O(n2) DP:

class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        int n = nums.size();
        if (n == 0) return 0;
        vector<int> dp(n, 1);          // every element is its own LIS of length 1
        int best = 1;
        for (int i = 1; i < n; i++) {
            for (int j = 0; j < i; j++) {
                if (nums[j] < nums[i])
                    dp[i] = max(dp[i], dp[j] + 1);
            }
            best = max(best, dp[i]);
        }
        return best;
    }
};

Complexity: two nested loops, O(n2) time. O(n) space for dp.

Alternative: O(n log n) patience sort with tails + lower_bound

int lengthOfLIS(vector<int>& nums) {
    vector<int> tails;                  // tails[k] = smallest tail of any IS of length k+1 seen so far
    for (int x : nums) {
        auto it = lower_bound(tails.begin(), tails.end(), x);
        if (it == tails.end()) tails.push_back(x);   // x is larger than every tail: grow the LIS
        else *it = x;                              // shrink an existing tail; same length, better future prospects
    }
    return (int)tails.size();
}

Complexity: each element costs one binary search over a vector of size ≤ n, so O(n log n) time, O(n) space. Prefer this version when n is large (104 or more).

Why tails is not itself an LIS

The tails array is not an actual increasing subsequence of nums. It records the smallest achievable tail for each possible run length, and those tails may come from different subsequences.

Example: nums = [3, 4, 1].

  • After 3: tails = [3]. Backing subsequence [3].
  • After 4: tails = [3, 4]. Backing [3, 4].
  • After 1: lower_bound([3,4], 1) = 0, replace. tails = [1, 4]. Now tails[0] = 1 is backed by the length-1 subsequence [1], and tails[1] = 4 is still backed by [3, 4].

The final tails = [1, 4] is not a subsequence of [3, 4, 1], because 1 occurs after 4 in the array. The length (2) is correct; the array contents are a mix of records, not a path. If an interviewer asks for the LIS itself, reconstruct it from a parent[] array during the O(n2) DP, not from tails.

5. The part interviewers ask about: strict vs non-strict, and the tails invariant

The invariant: after processing a prefix of nums, tails[k] is the minimum possible last value over all strictly increasing subsequences of length k + 1 drawn from that prefix. Smaller tails are strictly better: anything that could extend a run ending at the old tail can also extend the smaller new one, and the smaller tail may admit extensions the old one would reject.

Strict vs non-strict. lower_bound finds the first position with value ≥ x, which keeps the sequence strictly increasing (LC 300). If the problem allows equal (longest non-decreasing), use upper_bound instead. Mixing them up changes the answer on inputs with duplicates:

Inputlower_bound (strict)upper_bound (non-decreasing)
[7,7,7,7]14
[1,3,3,5]3 (one 3)4 (keeps both 3s)
Proof sketch of correctness (O(n log n)). By induction on the prefix. The length never falls, since the only shrink is a replace (same length). It can only grow by appending x, which happens when x exceeds every current tail, meaning we have a strictly longer increasing subsequence. For optimality: suppose the real LIS so far has length L with last element v. Then our algorithm maintains a tails array of length L with tails[L−1] ≤ v, by the "smaller tails are better" invariant. So tails.size() equals the LIS length at every step.

6. Traps and edge cases

  • Returning dp[n−1]. The LIS may not end at the last element. Track a running best (or take max(dp) at the end). [1, 2, 3, 0] is the classic trap: the answer is 3, but dp[3] = 1.
  • Using upper_bound for strict LIS. You will count duplicates. On [7, 7, 7] upper_bound gives 3; the correct strict answer is 1.
  • Treating tails as the LIS. It is not. Only its length is meaningful. If you need the actual sequence, use the DP version with a parent[] array.
  • Empty input. Return 0. Both approaches handle this: the DP loop never runs and best stays at its starting value (initialise it to 0 for n = 0), and tails stays empty.
  • Negative or very large values. No special care in C++: vector<int> stores anything that fits in int and lower_bound only compares.
  • Confusing with longest contiguous increasing subarray (LC 674). That one is a greedy O(n) scan; this one is DP because elements need not be adjacent.

7. How to say it in the interview (30 seconds)

"I define dp[i] as the length of the longest strictly increasing subsequence ending at index i. For each i I scan j < i, and whenever nums[j] < nums[i] I try dp[j] + 1. Answer is max(dp). That is O(n2). For larger n I use the patience-sort trick: keep a tails array where tails[k] is the smallest tail of any length-k+1 increasing subsequence seen so far. For each x I lower_bound it; if it is past the end I append, otherwise I overwrite. The LIS length is tails.size(), which is O(n log n). Note the final tails is not the LIS, just the right length."
