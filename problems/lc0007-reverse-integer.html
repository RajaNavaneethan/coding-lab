Reverse Integer

LeetCode 7 · Medium · Pattern: Math (overflow-safe digit extraction) · O(log10 x) time, O(1) space

Problem. Reverse the digits of a 32-bit signed integer x. If the reversed value overflows the signed 32-bit range [-231, 231-1], return 0.
Examples: 123 → 321, -123 → -321, 120 → 21, 1534236469 → 0 (reversed is 9646324351, too big).
Link: LeetCode

1. The one idea that solves it

Peel digits off the right of x with d = x % 10, divide x by 10 to drop that digit, and glue d onto a running result with r = r * 10 + d. In C++ the % operator keeps the sign of x, so negatives come out right without a special case.

The one real difficulty is the overflow. The result is an int, and if the reversed value does not fit, we must return 0 — but we must detect this before the multiply that actually overflows, otherwise the overflow is undefined behaviour. The check is on r compared to INT_MAX/10 and INT_MIN/10, done before the next r * 10 + d.

Idea. Pull one digit, push one digit. Before each push, check whether the push would overflow by comparing the current r to INT_MAX/10 (positive side) and INT_MIN/10 (negative side).

2. Picture of the algorithm

Each iteration moves exactly one digit from x to r. The loop runs at most 10 times for a 32-bit int, so the whole thing is O(log10 x).

4. Code (C++)

class Solution {
public:
    int reverse(int x) {
        int r = 0;
        while (x != 0) {
            int d = x % 10;        // keeps sign of x
            x /= 10;
            // overflow checks (branch-free on signed int)
            if (r > INT_MAX / 10 || (r == INT_MAX / 10 && d > 7)) return 0;
            if (r < INT_MIN / 10 || (r == INT_MIN / 10 && d < -8)) return 0;
            r = r * 10 + d;
        }
        return r;
    }
};

Complexity: O(log10 x) time — at most 10 iterations for a 32-bit int. O(1) space.

Why 7 and -8? INT_MAX = 2147483647 ends in 7, and INT_MIN = -2147483648 ends in -8 under C++ truncated division. So on the knife-edge where r == INT_MAX/10 = 214748364, a next digit greater than 7 would push past INT_MAX; similarly for -8 at INT_MIN.

Alternative: use long long and compare

long long r = 0;
while (x) { r = r * 10 + x % 10; x /= 10; }
if (r > INT_MAX || r < INT_MIN) return 0;
return (int)r;

Simpler, but relies on a wider type. Interviewers often ban it and want the int-only version. Learn both; lead with the int-only one.

5. The part interviewers ask about: why the overflow check is tricky

  • Check before the multiply. If you compute r = r * 10 + d first and then test overflow, the multiply itself is undefined behaviour on signed overflow. The check must happen on the OLD r.
  • Why compare to INT_MAX/10, not INT_MAX? INT_MAX/10 = 214748364. If r > 214748364 then r*10 is already past INT_MAX, no matter what digit comes next. If r == 214748364, the next digit decides: anything above 7 overflows, anything ≤ 7 is fine (because INT_MAX itself ends in 7).
  • Negative side is symmetric but not identical. INT_MIN is -2147483648: the last digit magnitude is 8, one bigger than INT_MAX's 7. This asymmetry is why the two bounds have different cutoff digits (7 vs -8).
  • C++'s % is sign-preserving. -123 % 10 is -3, not 7. So we don't need to split on sign; the same loop handles negatives.

6. Traps and edge cases

  • Testing overflow after the multiply. Classic trap. The multiply has already invoked undefined behaviour, so the test may lie (and on strict compilers may be optimised away). Always check first.
  • Forgetting one bound. People check r > INT_MAX/10 and skip the INT_MIN/10 side. For most tests this works because x = -1534236469 is rare, but LeetCode has such tests.
  • x = 0. Loop never runs; return 0.
  • Trailing zeros. 120 → 21, not 021. Falls out naturally because r*10 + 0 = 0 on the first push.
  • x = INT_MIN. -2147483648 reversed is -8463847412 which overflows, so the answer is 0. Don't try -x up front; -INT_MIN is itself UB.
  • Palindromes. 1221 → 1221. Not a special case, but a good sanity check.

7. How to say it in the interview (30 seconds)

"I keep a running result r and peel digits off x with x % 10 and x / 10. C++'s % preserves sign, so the same loop handles negatives. Before each r = r * 10 + d, I check overflow against INT_MAX/10 (digit cutoff 7) and INT_MIN/10 (digit cutoff -8). If the check fails, return 0. The loop runs at most 10 times for a 32-bit int, so it's O(log10 x) time, O(1) space, and uses no wider type."
