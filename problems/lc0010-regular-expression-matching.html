Regular Expression Matching

LeetCode 10 · Hard · Pattern: 2-D DP on text × pattern · O(m · n) time, O(m · n) space

Problem. Match a string s against a pattern p where:
  • . matches any single character.
  • * matches zero or more of the element preceding it (a letter or .).
Return true if the pattern matches the entire string.
s="aa", p="a" → false    s="aa", p="a*" → true    s="ab", p=".*" → true    s="aab", p="c*a*b" → true
Link: LeetCode

1. The one idea that solves it

Define dp[i][j] = true if s[0..i) matches p[0..j). Look at the last pattern token:

  • Letter or . at p[j−1] (and no following *): one character of pattern consumes one character of text. True iff the characters match and the previous prefixes matched.
    dp[i][j] = (p[j−1] == '.' || p[j−1] == s[i−1]) && dp[i−1][j−1].
  • * at p[j−1]: the token is p[j−2]*, which stands for zero or more copies. Two sub-cases, OR them together:
    • Zero copies. Delete p[j−2]* from the pattern: dp[i][j] = dp[i][j−2].
    • One or more copies. If p[j−2] matches s[i−1], we may consume one more character of s under the same *: dp[i][j] |= dp[i−1][j].

Base: dp[0][0] = true. For dp[0][j], the pattern can still match the empty string if it is all x* pairs: whenever p[j−1] == '*', dp[0][j] = dp[0][j−2].

Idea. The * turns a single pattern cell into "take zero or many". So dp[i][j] either skips the whole x* group (jump left by 2 in the pattern) or consumes one more s character under the same * (jump up by 1 in the text and stay in the same pattern cell). Everything else is classic single-character matching.

2. Picture of the algorithm

Row i represents using i characters of s; column j represents using j characters of p. A * cell reads two neighbours (left-by-two and above) instead of one, so the recurrence is "almost 1-D" with a special two-step hop for star columns.

4. Code (C++)

class Solution {
public:
    bool isMatch(string s, string p) {
        int m = s.size(), n = p.size();
        vector<vector<bool>> dp(m + 1, vector<bool>(n + 1, false));
        dp[0][0] = true;
        for (int j = 2; j <= n; j++) {           // x* can match empty
            if (p[j-1] == '*') dp[0][j] = dp[0][j-2];
        }
        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                if (p[j-1] == '*') {
                    dp[i][j] = dp[i][j-2];                            // zero copies of x
                    if (p[j-2] == '.' || p[j-2] == s[i-1])
                        dp[i][j] = dp[i][j] || dp[i-1][j];              // one more x
                } else if (p[j-1] == '.' || p[j-1] == s[i-1]) {
                    dp[i][j] = dp[i-1][j-1];                          // one letter matches
                }
            }
        }
        return dp[m][n];
    }
};

Complexity: O(m · n) time — at most two neighbour reads per cell. O(m · n) space, reducible to O(n) with a rolling previous row.

5. The part interviewers ask about: why "star eats one more" is dp[i−1][j]

The * is attached to p[j−2]. When we say "consume one more s character under the same *", we eat s[i−1] and keep p[j−2]* active for the next consumption. That means the pattern column does not move: we stay at column j and shrink s by one, hence dp[i−1][j].

The symmetric trap is "I should read dp[i−1][j−1] because the character matched". No: dp[i−1][j−1] uses up the pattern character too, which would be the correct read for a plain letter but not when there's a * after it. The * lets you reuse p[j−2] indefinitely, so the column stays put.

Equivalent recursion. match(s, p):
  • If p is empty, return s.empty().
  • Let first = !s.empty() && (p[0] == '.' || p[0] == s[0]).
  • If p[1] == '*': return match(s, p.substr(2)) (zero copies) || (first && match(s.substr(1), p)) (one more copy).
  • Else: return first && match(s.substr(1), p.substr(1)).
Memoise on (i, j) and you get the DP table above with the recursion flipped from top-down to bottom-up.

Why greedy fails here

Naive "scan left to right and consume as much as * allows" fails because sometimes consuming fewer characters leaves the right amount for a later part of the pattern. Example: s = "aaa", p = "a*a". A greedy a* gobbles all three as, leaving no room for the trailing a. DP tries all consumption counts, so it finds "a* matches two as, trailing a matches the last one".

6. Traps and edge cases

  • Treating * as "one or more" (regex-ish) instead of "zero or more". Classic bug. Without the zero-copy branch, "a*" cannot match the empty string.
  • Not initialising dp[0][j] for star patterns. A pattern like "a*b*c*" matches the empty string, but you only get that if you walk the first row and set dp[0][j] = dp[0][j−2] whenever p[j−1] == '*'.
  • Pattern starting with *. LC says this can't happen (every * has a preceding element), but your code shouldn't index p[j−2] when j < 2.
  • Partial match. The function requires the whole string to match, not a substring. Check dp[m][n], not any dp[i][j].
  • Wrong "same cell" read. On the many-copy branch you must read dp[i−1][j] (same column, one row up), not dp[i−1][j−1] or dp[i−1][j−2].
  • Supporting + or ?. They aren't in this problem's grammar. Don't add them.

7. How to say it in the interview (30 seconds)

"I define dp[i][j] = true iff s[0..i) matches p[0..j). Base: dp[0][0] = true, and I walk the first row to set dp[0][j] = dp[0][j−2] whenever p[j−1] = '*' so patterns like a*b*c* match empty. For each cell: if p[j−1] is *, the pattern token is p[j−2]*, and dp[i][j] is dp[i][j−2] (zero copies) OR, if p[j−2] matches s[i−1], dp[i−1][j] (one more copy). Otherwise, if p[j−1] is a letter or . and matches s[i−1], dp[i][j] = dp[i−1][j−1]. Return dp[m][n]. O(m · n) time and space."
