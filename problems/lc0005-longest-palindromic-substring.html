Longest Palindromic Substring

LeetCode 5 · Medium · Pattern: Expand around center (DP table is the common 2-D alternative) · O(n2) time, O(1) space

Problem. Given a string s, return the longest substring that is a palindrome.
"babad" → "bab" (or "aba")    "cbbd" → "bb"    "a" → "a"
Link: LeetCode

1. The one idea that solves it

Every palindrome has a center. If its length is odd, the center is a single character i. If its length is even, the center is between two characters i and i+1. A string of length n has exactly 2n − 1 such centers.

From any center, extend outwards one character at a time, as long as the two outer characters are equal: s[l] == s[r]. The moment they differ (or you fall off the string) you have the longest palindrome centred there. Try every center and keep the best.

Idea. A palindromic substring is uniquely determined by its center and radius. There are O(n) centers and each one grows for at most O(n) steps, so the whole scan is O(n2). We never need to look at any substring that doesn't actually center somewhere, which rules out brute-force O(n3).

2. Picture of the algorithm

Two cursors l and r start at the center. At every step we check s[l] == s[r]. If yes, record the window and push l one left and r one right. If no (or we fall off either end) we stop expanding this center and move to the next one.

4. Code (C++)

class Solution {
public:
    string longestPalindrome(string s) {
        int n = s.size();
        if (n == 0) return "";
        int bestStart = 0, bestLen = 1;
        auto expand = [&](int l, int r) {
            while (l >= 0 && r < n && s[l] == s[r]) { l--; r++; }
            int len = r - l - 1;      // last valid window ran from l+1 to r-1
            if (len > bestLen) { bestLen = len; bestStart = l + 1; }
        };
        for (int i = 0; i < n; i++) {
            expand(i, i);       // odd length center
            expand(i, i + 1);   // even length center
        }
        return s.substr(bestStart, bestLen);
    }
};

Complexity: O(n2) time — 2n − 1 centers, each expanding up to n/2 steps. O(1) extra space.

Alternative: DP table in O(n2) time, O(n2) space

int n = s.size();
vector<vector<bool>> dp(n, vector<bool>(n, false));
int bestStart = 0, bestLen = 1;
for (int i = 0; i < n; i++) dp[i][i] = true;
for (int len = 2; len <= n; len++) {
    for (int i = 0; i + len <= n; i++) {
        int j = i + len - 1;
        if (s[i] == s[j] && (len == 2 || dp[i+1][j-1]))
            dp[i][j] = true;
        if (dp[i][j] && len > bestLen) { bestLen = len; bestStart = i; }
    }
}
return s.substr(bestStart, bestLen);

dp[i][j] is true if s[i..j] is a palindrome. The recurrence is dp[i][j] = (s[i] == s[j]) && dp[i+1][j−1] for lengths ≥ 3, with lengths 1 and 2 as the base. Same O(n2) time as expand-around-center but O(n2) space, so expand is strictly better in practice. The DP is still worth knowing because it's the natural fit for Pattern 14 and generalises to Longest Palindromic Subsequence (LC 516).

If you need O(n) time, use Manacher's algorithm. In an interview, say "expand around center for O(n2), Manacher for O(n) if you ask for optimal" — nobody expects you to code Manacher cold.

5. The part interviewers ask about: why both centers

Students often forget the even-length case. On "cbbd", the odd-only version returns "c" or "b" because no single character sits in the middle of the "bb" palindrome; its center is between the two bs. Running expand(i, i+1) at every i covers these centers.

Any palindrome of length L has its "center" at position (l + r) / 2:
  • If L is odd, this is one real character index. There are n such centers.
  • If L is even, this falls between two indices. There are n − 1 such gaps.
Total: 2n − 1 centers. Visiting every one guarantees you find the optimal palindrome.

Length formula at a glance

When expand exits, both l and r are one past the valid window. So the valid window is [l+1, r−1] and its length is r − l − 1. If the first comparison already fails (odd center on a length-1 palindrome, or even center on two different letters), l and r never move, and the length comes out as 1 or 0 accordingly.

6. Traps and edge cases

  • Only trying odd centers. You miss every even-length palindrome. "cbbd" → "b" instead of "bb".
  • Returning the length instead of the substring. Read the signature. LC 5 asks for the actual string, so track bestStart alongside bestLen.
  • Off-by-one in bestStart. After the loop exits with s[l] != s[r], the last valid palindrome starts at l + 1, not l.
  • Empty string. The problem says s.length ≥ 1, but your code should still return "" for empty input without crashing.
  • Confusing with Longest Palindromic Subsequence (LC 516). Subsequence can skip characters; here the letters must be contiguous. The DP recurrences are different.
  • "All same characters" worst case. "aaaa...a" makes every center expand to the full length. This is O(n2) — still acceptable, but a correctness check: your code should return the whole string in that case, not just one character.

7. How to say it in the interview (30 seconds)

"Every palindrome has a center. I iterate over all 2n − 1 centers — n single characters for odd lengths and n − 1 gaps between adjacent characters for even lengths. From each center I run a two-pointer expand(l, r) while s[l] == s[r] and the pointers are in bounds. After the loop the valid window is [l+1, r−1], length r − l − 1, and I track the longest seen. That's O(n2) time, O(1) space. The 2-D DP (dp[i][j] true if s[i..j] is a palindrome) is equivalent in time but costs O(n2) space; Manacher's gives O(n) if asked."
