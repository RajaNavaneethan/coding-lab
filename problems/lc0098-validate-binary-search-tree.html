Validate Binary Search Tree

LeetCode 98 · Medium · Pattern: DFS with inherited bounds · O(n) time, O(h) space

Problem. Given a binary tree, decide if it is a valid BST. For every node: left subtree values are strictly less, right subtree values are strictly greater. Equal values are not allowed.
[2,1,3] → true    [5,1,4,null,null,3,6] → false
Link: LeetCode

1. The one idea that solves it

Checking only "left < parent < right" at each node is not enough. Each value also has to satisfy every ancestor it sits beneath. A value in the right subtree of a node must be greater than that node, even if its own immediate parent is smaller.

So each node has an open range (lo, hi) of allowed values, inherited from the chain of ancestors. The root starts at (−∞, +∞). Going left tightens the upper bound to the parent. Going right tightens the lower bound to the parent. If any node's value falls outside its range, the tree is not a BST.

Idea. Walk the tree with a running range (lo, hi). At each node, require lo < val < hi. Pass (lo, val) to the left child and (val, hi) to the right child. Bounds flow down the tree; validity flows back up.

2. Picture of the algorithm

The bounds get tighter as you go down. In the figure below the root is 5 with range (−∞, +∞). Its left child 1 inherits (−∞, 5); its right child 4 inherits (5, +∞). Then 4's children inherit (5, 4) and (4, +∞). The value 3 sits under the range (5, 4), which is empty, so the check fails.

4. Code (C++)

bool check(TreeNode* n, long lo, long hi) {
    if (!n) return true;
    if (n->val <= lo || n->val >= hi) return false;    // out of allowed range
    return check(n->left, lo, n->val) && check(n->right, n->val, hi);
}
bool isValidBST(TreeNode* root) {
    return check(root, LONG_MIN, LONG_MAX);
}

Complexity: each node is visited once, O(n) time. Recursion depth is the height, O(h) stack space.

Alternative: inorder walk and check strictly increasing

long prev = LONG_MIN;
bool isValidBST(TreeNode* root) {
    if (!root) return true;
    if (!isValidBST(root->left))  return false;
    if (root->val <= prev) return false;
    prev = root->val;
    return isValidBST(root->right);
}

An inorder traversal of a BST yields values in strictly increasing order, so you can walk left-root-right and compare each value to the previous one. Same O(n) time. The bounds version is more common because it also handles duplicate-free checks without a mutable "prev" global, and it fails fast on the first violation.

5. The part interviewers ask about: the parent-only trap

The naive "left < node < right at every node" check is wrong. A node is in a subtree, not just under its immediate parent. The tree [5,4,6,null,null,3,7] looks locally fine (4 < 5 < 6, 3 < 6 < 7), but the value 3 sits in the right subtree of the root 5, so it must be greater than 5. Only inherited bounds catch this.

Why integer bounds need widening: LeetCode allows INT_MIN and INT_MAX as node values. The root starts with lo = INT_MIN, so a left-most node holding INT_MIN itself would fail with val <= lo. The usual fix is long bounds (LONG_MIN, LONG_MAX) so the int values can equal the extremes without colliding with the sentinels. Another fix: pass pointers (TreeNode* or optional<int>) instead of integer sentinels.

6. Traps and edge cases

  • Checking only immediate parent. The [5,4,6,null,null,3,7] tree is the canonical gotcha, see above.
  • Using < instead of <=. BST is strict: duplicates violate. [1,1] must return false.
  • int bounds and INT_MIN/INT_MAX values. A node of value INT_MIN fails against lo = INT_MIN. Use long or pointers.
  • Edge: empty tree. Valid. The base case returns true.
  • Edge: single node. Valid. Any single value sits in (−∞, +∞).
  • Mutable "prev" in the inorder version. If you forget to reset it between test cases, a second call sees stale state and gives a wrong answer. Prefer the bounds version in a shared service.

7. How to say it in the interview (30 seconds)

"Each node must satisfy every ancestor, not just its parent. So I carry a range (lo, hi) down the recursion. The root starts at full range. Going left tightens the upper bound to the parent, going right tightens the lower bound. At each node I check lo < val < hi. One pass, O(n) time, O(h) stack. The classic trap is checking only the immediate parent — [5,4,6,null,null,3,7] fools it."
