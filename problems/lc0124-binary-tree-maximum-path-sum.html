Binary Tree Maximum Path Sum

LeetCode 124 · Hard · Pattern: post-order DFS, two numbers per node · O(n) time, O(h) space

Problem. A path is any sequence of nodes connected by parent-child edges, visiting each node at most once. The path need not go through the root. Return the maximum sum of node values over any path.
[1,2,3] → 6    [-10,9,20,null,null,15,7] → 42
Link: LeetCode

1. The one idea that solves it

Any path in a binary tree has a highest node — the one point where it bends from going up to going down (or just the single node if the path doesn't bend). Fix that top. The path is then: a downward chain in the left subtree + the node itself + a downward chain in the right subtree. One side (or both) may be empty.

So for every node, compute two numbers:

  • gain(n): best sum of a chain starting at n and going only downward. This is what we can hand up to our parent, who may extend it further.
  • candidate at n: n->val + max(0, gain(left)) + max(0, gain(right)). This is the best path that bends at n. We record it in a running maximum, but we do not return it — it already uses two children, so the parent cannot extend it.

Negative branches get clipped to zero: if a side is negative we drop it from the chain. The answer is the maximum candidate seen across all nodes.

Idea. One post-order walk. Each call returns a straight-up chain gain; each call also updates a global best with the bending-at-this-node candidate. Negative subtree gains are clipped to zero.

4. Code (C++)

int best;
int gain(TreeNode* n) {
    if (!n) return 0;
    int L = max(0, gain(n->left));             // drop negative branches
    int R = max(0, gain(n->right));
    best = max(best, n->val + L + R);          // candidate: path bending at n
    return n->val + max(L, R);                 // return: must extend upward
}
int maxPathSum(TreeNode* root) {
    best = INT_MIN;
    gain(root);
    return best;
}

Complexity: each node computes constant work after both children return, so O(n) time. Recursion depth equals the tree height, O(h) stack. The sum of node values can overflow int in theory; LeetCode's constraints keep it within int, but defensive code could use long long for best.

5. The part interviewers ask about: why "return one side" is the whole trick

The returned value and the recorded candidate are different. The candidate is val + L + R, a path that bends at this node and so cannot be extended by any ancestor without reusing a node. The return value is val + max(L, R), a straight chain that an ancestor can still extend. Confusing the two is the single most common bug on 124 — "I return val + L + R and get wrong answers like 22 instead of 20".

Clipping to zero is also easy to get wrong. If gain(left) is negative, the chain is better off ignoring that side — the ancestor would rather we return val than val + (negative). So we take max(0, gain(left)). But do not clip val itself: a tree of all negatives still has an answer (the single largest value), which the candidate line captures because best starts at INT_MIN.

What if the tree has one node? gain(root) clips L and R to 0, records val + 0 + 0 = val as a candidate, and returns val. The answer is val, including when it's negative. Perfect.

6. Traps and edge cases

  • Returning val + L + R. That path already bends, so an ancestor can't extend it. You must return val + max(L, R).
  • Initialising best = 0. On a tree of all negatives you'd then return 0, which no path can produce (every path has at least one node). Start at INT_MIN.
  • Clipping val to zero. You'd miss the all-negative case. Only clip the subtree gains.
  • Edge: single node. Return the node's value, even if negative. The code handles it with no special case.
  • Edge: a chain to the right. [-10,9,20,null,null,15,7] → 42. The best path doesn't go through the root: it is 15 ← 20 → 7.
  • Overflow in theory. With 10^4 nodes of value ±1000, the sum fits in int. LeetCode's constraints are tight on purpose.
  • Using a member variable in a class without resetting. If best is a field and the solution object is reused, reset it at the top of maxPathSum.

7. How to say it in the interview (30 seconds)

"Every path has a highest node where it bends from going up to going down. So I post-order DFS: at each node I compute the best straight-down chain gain from the left and the right, clipped at zero if negative. The candidate at this node is val + L + R, which I compare against a running best. The call returns val + max(L, R) so the parent can keep extending the chain, since a bent path can't go further. One pass, O(n) time, O(h) stack."
