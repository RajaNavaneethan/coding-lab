Redundant Connection

LeetCode 684 · Medium · Pattern: Union-Find (DSU) · O(N α(N)) time, O(N) space

Problem. You start with a tree on n nodes labelled 1..n, then one extra edge was added. You are given the full edge list (n edges, so exactly one cycle). Return the extra edge; if multiple answers exist, return the one that appears last in the input.
[[1,2],[1,3],[2,3]] → [2,3]
Link: LeetCode

1. The one idea that solves it

Walk the edges in order and build the graph one edge at a time. A tree is defined by exactly this property: adding each new edge connects two different components. The first edge whose two endpoints are already in the same component is the one that closes a cycle. That is the redundant edge.

Because the problem guarantees the input is a tree with exactly one extra edge, there is exactly one such edge, and walking left-to-right returns it, which is also the latest-in-input answer the problem asks for.

Idea. Treat the edge list as a stream. Use Union-Find to keep a forest. The first edge that fails to merge — both endpoints already in the same tree — is the redundant one.

2. Picture of the algorithm

Same core as LC 323, but we don't count components; we stop at the first edge whose endpoints are already connected. Everything about find (path compression) and union (by rank) is identical.

3. Step-by-step trace

Each step consumes one edge. The forest grows until an edge connects two nodes that already share a root — that is the redundant edge, and we stop. The parent array below shows the state after each step.

4. Code (C++)

class UF {
    vector<int> parent, rk;
public:
    UF(int n) : parent(n), rk(n, 0) {
        iota(parent.begin(), parent.end(), 0);
    }
    int find(int x) {
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];      // path compression
            x = parent[x];
        }
        return x;
    }
    bool unite(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;             // cycle: already connected
        if (rk[ra] < rk[rb]) swap(ra, rb);
        parent[rb] = ra;
        if (rk[ra] == rk[rb]) rk[ra]++;
        return true;
    }
};

vector<int> findRedundantConnection(vector<vector<int>>& edges) {
    int n = edges.size();
    UF uf(n + 1);                                   // nodes are 1..n
    for (auto& e : edges) {
        if (!uf.unite(e[0], e[1])) return e;         // first edge that closes a cycle
    }
    return {};
}

Complexity: O(N · α(N)) time (near-constant per edge thanks to path compression + union by rank), O(N) space for the parent and rank arrays.

5. The part interviewers ask about: why "first failing edge" is the answer

Correctness. Before any edge is seen, every node is its own component. Each successful union merges two components into one, so after any prefix of the input in which i unions succeeded, the forest has n − i trees. An edge whose endpoints are in the same tree creates the first (and, since the original input was a tree plus one edge, the only) cycle. Any later edge in the same cycle would be a different cut of the same cycle but a valid tree edge, not a redundant one — the problem simply asks for the last redundant one in input order, and in this problem there is only one.

Why left-to-right is the "last-in-input" edge. This problem (684, undirected graph) guarantees exactly one extra edge, so the first failure is also the last candidate. If the input had multiple cycles the right-to-left walk would not help — this trick is single-cycle-specific.

Why not plain DFS?

You can also solve it with DFS: for each edge (u, v) in order, check "is there already a path from u to v?" with a DFS. If yes, return (u, v). Correct, but each check is O(N), and you do it for every edge, so O(N2). Union-Find is O(N · α(N)), effectively linear, and it is the natural tool when the question is "do these two things end up in the same group?".

6. Traps and edge cases

  • Off-by-one with 1-indexed nodes. Nodes are 1..n, so parent needs n + 1 slots. Index 0 is unused.
  • Breaking out of the loop at the wrong time. Return the edge as soon as unite fails, not after the loop.
  • Running find only on one endpoint. You need both roots to compare. Call find twice.
  • Union by rank with size. Fine, but either use rank or size consistently. Mixing them causes subtle bugs.
  • Recursive find. On a chain built edge-by-edge, recursion depth can reach N and blow the stack. The iterative halving in the code above avoids this.
  • Thinking all cycle edges are "redundant". They aren't — only the input's last-in-order cycle-closing edge is. This problem is single-cycle, so first-failure = last-in-input.

7. How to say it in the interview (30 seconds)

"A tree with one extra edge has exactly one cycle. I walk edges left-to-right with a Union-Find. Each edge either merges two components or closes a cycle because its endpoints are already connected. The first edge that fails to merge is the redundant one, and I return it. Union-Find has path compression and union by rank, so each operation is amortised α(N) and the total is effectively O(N)."
