Word Search II

LeetCode 212 · Hard · Pattern: Trie + DFS on a grid · O(M · N · 4L) time, O(total word chars) extra space

Problem. Given an m × n board of letters and a list of words, return every word that can be built by stepping between 4-directionally adjacent cells, without reusing a cell within one word.
board = [[o,a,a,n],[e,t,a,e],[i,h,k,r],[i,f,l,v]], words = ["oath","pea","eat","rain"] → ["eat","oath"]
Link: LeetCode

1. The one idea that solves it

LC 79 (Word Search) runs one DFS per word. With k words the cost is O(k · M · N · 4L); if the words share prefixes you pay for the shared walking many times.

Put the words into a trie and run one DFS over the grid. Carry a trie pointer alongside each DFS: the cell letter is only legal if its child exists in the trie. Hitting a node whose word field is non-null means "the walked path spells an inserted word" — add it to the output and clear the marker to avoid duplicates.

With the trie, every DFS branch dies the moment the current prefix is not a prefix of any remaining word. On typical inputs this prunes the search massively compared to looking up a prefix set with a hash.

Idea. Flip the loop: don't run one search per word. Build a trie of all words, then walk the grid once — the trie's shape tells you when to prune, and the word marker tells you when you have found one.

2. Picture of the algorithm

During the DFS, mark the current cell with a sentinel (we use '#') so you don't revisit it along the same path, then recurse into the 4 neighbours, then restore it. Standard grid DFS; only the pruning changes.

Three details earn their keep on this problem:

  • Found-word deduplication: when you emit a word, delete its word marker so the next DFS doesn't push it again.
  • Live pruning: after returning from the 4 children, if the current trie node has no children left and no word of its own, unlink it from its parent. The next DFS branch will give up at the parent instead of walking in.
  • Reversing long words: inserting word or reverse(word), whichever has rarer starting letters on the board, cuts the DFS roots. Nice follow-up answer, not needed for the base solution.

4. Code (C++)

class Solution {
    struct Node {
        Node* ch[26] = {};
        string* word = nullptr;  // non-null at end of a word
    };
    void insert(Node* root, const string& w) {
        Node* cur = root;
        for (char c : w) {
            int i = c - 'a';
            if (!cur->ch[i]) cur->ch[i] = new Node();
            cur = cur->ch[i];
        }
        cur->word = new string(w);
    }
    void dfs(vector<vector<char>>& b, int r, int c, Node* node, vector<string>& out) {
        char ch = b[r][c];
        if (ch == '#') return;
        int i = ch - 'a';
        Node* nxt = node->ch[i];
        if (!nxt) return;                  // prefix not in trie: prune
        if (nxt->word) {
            out.push_back(*nxt->word);
            delete nxt->word; nxt->word = nullptr; // avoid duplicates
        }
        b[r][c] = '#';
        int R = b.size(), C = b[0].size();
        if (r > 0)     dfs(b, r - 1, c, nxt, out);
        if (r + 1 < R) dfs(b, r + 1, c, nxt, out);
        if (c > 0)     dfs(b, r, c - 1, nxt, out);
        if (c + 1 < C) dfs(b, r, c + 1, nxt, out);
        b[r][c] = ch;                        // restore
        bool anyChild = false;
        for (int k = 0; k < 26; k++) if (nxt->ch[k]) { anyChild = true; break; }
        if (!anyChild && !nxt->word) node->ch[i] = nullptr;  // prune dead subtrie
    }
public:
    vector<string> findWords(vector<vector<char>>& board, vector<string>& words) {
        Node* root = new Node();
        for (auto& w : words) insert(root, w);
        vector<string> out;
        int R = board.size(), C = R ? board[0].size() : 0;
        for (int r = 0; r < R; r++)
            for (int c = 0; c < C; c++) dfs(board, r, c, root, out);
        return out;
    }
};

Complexity: O(M · N · 4L) in the worst case, with L the longest word. In practice the trie prunes most branches: an unreachable prefix cuts the entire subtree. Space is one trie node per distinct prefix character across all words.

5. The part interviewers ask about: why not run LC 79 k times?

Running LC 79 for each word does k independent DFSes. Two problems:
  • No prefix sharing. If "oath" and "oats" both start at the same cell, you walk the shared "oa" path once per word. The trie walks it once.
  • No early kill. You can only test the whole word at the leaf; the trie kills the branch the moment the current cell's letter has no child in the trie.
The deeper mental model: one grid DFS, with the trie as the "allowed prefix" oracle.

Why delete the word marker after emitting?

LeetCode's answer is a set, not a multiset: each word appears at most once. Without clearing the marker you emit "eat" every time the grid DFS finds another path spelling it. The simplest fix is to clear the marker. A hash set over the output vector works too, but hurts the asymptotics in the dense case.

Why prune empty subtries?

Say every word starting with "o" was found and removed. The subtrie under "o" is now empty, so the trie node for "o" has no reason to exist. Unlinking it means the next DFS reaching an "o" on the board returns at line if (!nxt) return without ever entering recursion. This is the "live pruning" that makes the solution fast on big inputs.

6. Traps and edge cases

  • Not clearing the sentinel. Forgetting board[r][c] = ch; after the recursive calls poisons the board for all later walks and you miss words.
  • Letting duplicates slip. If you don't delete the word marker, a word with multiple paths on the board appears multiple times in the output.
  • Checking the sentinel before the trie. If you check nxt first on '#', you may index '#' - 'a' which is negative. Always test the cell letter before computing i.
  • Allocating in a hot path. Using unordered_map at every trie node is correct but slower than the 26-array given the lowercase alphabet. Use the array.
  • Mutating the words vector. Not your problem, but keep the trie's string copy independent of the caller's buffer so a surprising modification doesn't crash you.
  • Very long words that fit the grid. The DFS depth is bounded by the number of cells (max M · N), not by the word length. Stack overflow is unlikely on LeetCode constraints (12×12, words ≤ 10).
  • Grid of all one letter + repeated word in dictionary. E.g. board of a's and words ["a","aa","aaa","aaaa"]. Make sure your DFS does not loop forever: the sentinel prevents reuse within one path.

7. How to say it in the interview (30 seconds)

"I build a trie of all words with a word pointer at each terminal node. Then one DFS from every grid cell, carrying a trie pointer: the next cell letter is only legal if it is a child of the current trie node, which prunes branches early. On reaching a word node I append the word to the output and clear its marker so duplicates can't slip. I also unlink dead subtries after a recursive call returns to prune future DFS branches immediately. Beats running one DFS per word because shared prefixes are walked once."
