Cheapest Flights Within K Stops

LeetCode 787 · Medium · Pattern: bounded-edge shortest path (Bellman-Ford) · O((k+1) · E) time, O(V) space

Problem. n cities (0..n-1) and directed flights[i] = [u, v, price]. Find the cheapest src → dst price using at most k stops (so at most k + 1 edges). Return -1 if impossible.
flights=[[0,1,100],[1,2,100],[0,2,500]], src=0, dst=2, k=1 → 200
Link: LeetCode

1. The one idea that solves it

This isn't plain shortest path. Each path has two costs: its total price and the number of edges it uses. Dijkstra always keeps the cheapest-price frontier, but the cheapest path can use too many stops. Once Dijkstra settles a node, it never looks at it again, so a slightly more expensive path that uses fewer stops is lost forever.

Bellman-Ford fixes this by thinking in rounds: after round i, dist[v] is the cheapest price using at most i edges. So run exactly k + 1 rounds and read dist[dst].

Idea. Count edges, not just price. After round i, dist[v] = cheapest cost reachable from src using ≤ i edges. Run k + 1 rounds. The round structure caps the number of edges and lets us read the answer directly.

2. Picture of the algorithm

The key implementation detail: in each round we relax from a snapshot of the previous round's distances, not from the row we are updating. Otherwise, an edge we just relaxed could be used again inside the same round and we would quietly let the path use more than k + 1 edges.

4. Code (C++)

int findCheapestPrice(int n, vector<vector<int>>& flights, int src, int dst, int k) {
    vector<int> dist(n, INT_MAX);
    dist[src] = 0;

    // k stops == k+1 edges
    for (int i = 0; i <= k; i++) {
        vector<int> next = dist;            // snapshot of previous round
        for (auto& f : flights) {
            int u = f[0], v = f[1], w = f[2];
            if (dist[u] == INT_MAX) continue;
            if (dist[u] + w < next[v]) next[v] = dist[u] + w;
        }
        dist = next;
    }
    return dist[dst] == INT_MAX ? -1 : dist[dst];
}

Complexity: O((k + 1) · E) time, O(V) space (two distance arrays). No adjacency list is needed because every round scans the flight list once.

Alternative: Dijkstra with a (cost, node, stops) state

priority_queue<tuple<int,int,int>, vector<tuple<int,int,int>>, greater<>> pq;
pq.push({0, src, 0});                    // (cost, node, edges used)
while (!pq.empty()) {
    auto [c, u, e] = pq.top(); pq.pop();
    if (u == dst) return c;
    if (e > k) continue;             // no more edges allowed
    for (auto& [v, w] : adj[u]) pq.push({c + w, v, e + 1});
}

Works because the state now includes edges used, so the heap can revisit a node via a longer-but-fewer-stops path. In the worst case it explores O(k · E) states, same ballpark as Bellman-Ford, with a log factor. Prefer Bellman-Ford for its simplicity and the clean per-round array that is easy to reason about.

5. The part interviewers ask about: why plain Dijkstra fails

The counterexample. Three cities: 0 → 1 cost 1, 1 → 2 cost 1, 0 → 2 cost 5. Target src=0, dst=2, k=0 (zero stops allowed).

Dijkstra pops (0, 0), relaxes to dist[1]=1, dist[2]=5. Next pops (1, 1) and relaxes to dist[2]=2. Done; it returns 2. But that path uses one stop at node 1, which is not allowed. The right answer is 5 (take the direct edge).

The failure is structural: Dijkstra's "once settled, always settled" invariant assumes a single cost dimension. The moment you add a second constraint (edge count), the greedy by price no longer dominates.

Why the snapshot matters

If you relax into the same array you read from, one round can chain two edges. Example: round 1 updates dist[1] = 1, then still in round 1 it relaxes 1 → 2 and gets dist[2] = 2. Now round 1 "with at most 1 edge" has a 2-edge entry inside it. Over k+1 rounds you leak 2(k+1) edges in the worst case.

6. Traps and edge cases

  • Running k rounds instead of k + 1. "At most k stops" means at most k + 1 edges. Off-by-one is the most common bug.
  • Relaxing in place. You must snapshot dist at the start of each round and read from the snapshot. Updating in place over-counts edges.
  • Overflow. Guard with if (dist[u] == INT_MAX) continue; before computing dist[u] + w.
  • Using regular Dijkstra. It gives the wrong answer whenever a cheaper multi-stop path exists that is not allowed by the stop limit. See the counterexample above.
  • src == dst. Return 0 immediately (dist[src] = 0 handles it).
  • Returning the answer after each round. Fine, but you still have to run all k + 1 rounds to give later rounds a chance to improve.

7. How to say it in the interview (30 seconds)

"Each path has two costs, total price and number of edges, so a plain Dijkstra by price alone can lock in an answer that uses too many stops. I use Bellman-Ford: let dist[v] be the cheapest price using at most i edges, run k + 1 rounds. Each round takes a snapshot of the previous row, relaxes every flight once against that snapshot, and writes to a new row. Snapshot is the only subtle bit — without it one round would chain edges. Read dist[dst]; return -1 if still infinity. Time O((k+1) · E), space O(V)."
