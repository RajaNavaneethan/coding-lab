Binary Search

LeetCode 704 · Easy · Pattern: classic binary search on a sorted array · O(log n) time, O(1) space

Problem. nums is sorted in ascending order with distinct values. Return the index of target, or -1 if it is not there.
nums = [-1,0,3,5,9,12], target = 9 → 4    target = 2 → -1
Link: LeetCode

1. The one idea that solves it

The array is sorted. Pick the middle element. One comparison with target tells you which half the answer must be in, so you can throw the other half away. Repeat on what is left. Every step cuts the search range in half, so after log2 n steps the range has shrunk to one cell.

Track the range with two indices, lo and hi. The answer, if it exists, is in the closed interval [lo, hi]. Pick mid = lo + (hi - lo) / 2 (not (lo + hi) / 2, which can overflow). Compare, keep the half that could still contain target, strike through the other.

Idea. Shrink the search interval [lo, hi]. On each step, if nums[mid] is too small move lo = mid + 1, if it is too big move hi = mid - 1, if equal return mid. Stop when lo > hi: the interval is empty, so the target is not there.

Why mid + 1 and mid - 1 matter

If you set lo = mid or hi = mid on a mismatch, the two-cell interval [lo, lo+1] can loop forever: mid rounds down to lo, and lo = mid leaves the interval unchanged. Writing mid + 1 / mid - 1 excludes the already-tested index, so the interval strictly shrinks every iteration.

4. Code (C++)

class Solution {
public:
    int search(vector<int>& nums, int target) {
        int lo = 0, hi = (int)nums.size() - 1;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;      // avoid lo + hi overflow
            if (nums[mid] == target) return mid;
            if (nums[mid] < target) lo = mid + 1;
            else                     hi = mid - 1;
        }
        return -1;
    }
};

Complexity: each iteration halves the interval, so at most ⌈log2 n⌉ iterations. O(log n) time, O(1) space.

5. The part interviewers ask about: closed vs half-open intervals

The template above uses the closed interval [lo, hi]. Three details are tied together: the loop condition is lo <= hi, the updates are mid ± 1, and hi starts at n - 1. If you ever change one, change all three.

Alternative: half-open interval [lo, hi). Then hi = n, the loop is while (lo < hi), the mismatch updates are lo = mid + 1 and hi = mid. Pick one and stick with it. Mixing a <= loop with hi = mid is the classic infinite loop.

A second detail: mid = (lo + hi) / 2 can overflow when both are near INT_MAX. Writing lo + (hi - lo) / 2 stays safe because hi - lo is at most n.

Variants that come up right after this problem:

  • Lower bound. First index where nums[i] ≥ target. Return lo after the loop instead of -1. Uses the half-open template.
  • Upper bound. First index where nums[i] > target. Same template, change ≥ to >. Count of a value = upper - lower.
// lower_bound: first i with nums[i] ≥ target
int lo = 0, hi = (int)nums.size();
while (lo < hi) {
    int mid = lo + (hi - lo) / 2;
    if (nums[mid] < target) lo = mid + 1;
    else hi = mid;
}
return lo;    // 0 .. n

6. Traps and edge cases

  • mid = (lo + hi) / 2 overflow. For LC 704 the bounds are small, but write the safe form every time. Interviewers watch for it.
  • hi = mid inside a lo <= hi loop. Infinite loop when the window is two cells. Mix carefully.
  • Empty array. hi = -1, the loop never runs, return -1. The template handles it.
  • Target smaller than all / larger than all. [1,2,3], target = 0 or 4: the interval walks off one end, then lo > hi and we return -1.
  • Duplicates. LC 704 says distinct, but if duplicates are allowed, search finds some occurrence, not the first. Use lower_bound if you want the first.
  • Returning lo or hi at the end. For "find exact index or -1" that is wrong. Those values are the insertion point, not a match.

7. How to say it in the interview (30 seconds)

"The array is sorted, so I keep two indices lo and hi for the closed interval that could still hold the target. Each step I pick the middle, compare, and throw away the half the target cannot be in. I use lo + (hi - lo) / 2 to avoid overflow, and mid + 1 / mid - 1 on the updates so the interval strictly shrinks. The loop runs log n times and I return mid on a hit or -1 when the interval is empty."
