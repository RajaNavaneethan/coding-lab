Burst Balloons

LeetCode 312 · Hard · Pattern: interval DP (last to burst) · O(n3) time, O(n2) space

Problem. You have n balloons with values nums[i]. Bursting balloon i earns left · nums[i] · right, where left and right are the values of the current neighbours (treat anything off the array as 1). After bursting, the neighbours become adjacent. Find the maximum coins you can collect.
nums = [3,1,5,8] → 167 (one optimal order: 1, 5, 3, 8)
nums = [1,5] → 10
Link: LeetCode

1. The one idea that solves it

The obvious recursion "pick the next balloon to burst" fails because the neighbours of balloon i depend on what has already been removed. So any sub-problem written as "a set of remaining balloons" has state that is not a contiguous interval, and interval DP cannot be applied cleanly.

The fix is to think backwards. Instead of asking "which to burst first", ask which balloon is burst last inside the interval (l, r). When balloon k is the last one left in that open interval, both its real neighbours at that moment are the fixed boundaries v[l] and v[r] — everyone between them is already gone. So the coins from the final pop are exactly v[l] · v[k] · v[r], which no longer depends on the burst order of the rest.

That lets us split the interval around k: before we can pop k last, we must empty (l, k) and (k, r) independently, and these two intervals do not interact because k is still there as a wall between them.

dp[l][r] = maxl < k < r   dp[l][k] + dp[k][r] + v[l] · v[k] · v[r]
Idea. Pad nums with a 1 on each end to kill the "off the array" special case. For the open interval (l, r), pick which balloon k is the last to burst. Its final left/right are fixed at v[l] and v[r], and the two sides split cleanly. Fill the table by interval length.

2. Picture of the algorithm

Fill order matters. dp[l][r] reads dp[l][k] and dp[k][r] for every l < k < r. Both are strictly shorter intervals than (l, r), so if we loop by interval length (shortest first), the entries we read are already filled. Any other order risks reading from an empty cell.

The answer is dp[0][n+1]: the open interval over the whole padded array, i.e. "burst everything between the two phantom 1-balloons".

4. Code (C++)

class Solution {
public:
    int maxCoins(vector<int>& nums) {
        int n = nums.size();
        vector<int> v(n + 2, 1);                 // pad with phantom 1-balloons
        for (int i = 0; i < n; i++) v[i + 1] = nums[i];

        // dp[l][r] = best coins from popping every balloon strictly
        // between l and r. l,r themselves are never popped.
        vector<vector<int>> dp(n + 2, vector<int>(n + 2, 0));

        for (int len = 2; len <= n + 1; len++) {         // len = r - l
            for (int l = 0; l + len <= n + 1; l++) {
                int r = l + len;
                for (int k = l + 1; k < r; k++) {       // k is the LAST pop
                    int cur = v[l] * v[k] * v[r] + dp[l][k] + dp[k][r];
                    if (cur > dp[l][r]) dp[l][r] = cur;
                }
            }
        }
        return dp[0][n + 1];
    }
};

Complexity. The outer two loops enumerate all O(n2) intervals; the inner loop over k is O(n). So O(n3) time and O(n2) space for the table.

Alternative: top-down memoisation

int solve(int l, int r, vector<int>& v, vector<vector<int>>& memo) {
    if (r - l < 2) return 0;
    if (memo[l][r] != -1) return memo[l][r];
    int best = 0;
    for (int k = l + 1; k < r; k++)
        best = max(best, v[l]*v[k]*v[r] + solve(l,k,v,memo) + solve(k,r,v,memo));
    return memo[l][r] = best;
}

Same recurrence, same complexity. Prefer bottom-up in C++ interviews — the fill order is explicit, and you avoid recursion depth concerns. Prefer top-down when you want to say "I'll fill only the sub-problems I need," but on this problem the full table is visited anyway.

5. The part interviewers ask about: why "burst last" and not "burst first"?

Try the natural recurrence first and see where it breaks. If f(set) picks which balloon k to burst first, the coins earned are left(k) · v[k] · right(k) + f(set \ {k}). The problem: left(k) and right(k) are the current neighbours in set, which depend on the shape of set — so the state isn't a contiguous interval, it's an arbitrary subset. That's 2n states, not n2.

Switching to "burst last in interval (l, r)" fixes the state because the moment balloon k is bursting, its left and right are determined by v[l] and v[r], not by which other balloons were bursted earlier. All the choices inside (l, k) and (k, r) are independent of each other because k acts as a wall. That independence is the whole trick.

Second question people ask: does an optimal order really exist? Yes, trivially — there are only n! orders, and the max is attained by some order. The DP's optimality follows by induction on interval length: at length 2 the only balloon is v[l+1], and dp[l][l+2] = v[l]·v[l+1]·v[l+2] is correct; longer intervals pick the best "last to burst" over all choices, by the recurrence.

Third: the padding trick. Adding v[-1] = v[n] = 1 replaces the "off the array" special case with plain multiplication, which keeps the code free of branches. If the balloons already contain 1s this is still fine — the recurrence doesn't require strict inequality on values.

6. Traps and edge cases

  • Writing the recurrence as "burst first". Looks natural, is exponential. Interviewers test this because the fix is the whole lesson.
  • Forgetting the padding. Without v[-1] = v[n] = 1 you must branch on l == -1 and r == n, which is bug-prone.
  • Filling by l and r directly. You can, but you have to loop l from n down to 0 and r from l + 2 upward. Interval-length order is clearer and avoids off-by-one bugs.
  • Including k = l or k = r. k is strictly inside the open interval; the boundaries are walls, not candidates.
  • Integer overflow. Values are up to 100, length up to 300, so one pop is at most 1003 = 106, and the whole answer is bounded by about 3 · 108. int holds this, but long long is safe for larger constraints.
  • Empty nums. No balloons to pop, answer 0. The padded array has only two phantom 1s and the loop with len ≥ 2 never fires on n + 1 = 1; dp[0][1] stays 0.
  • Single balloon. dp[0][2] = 1 · nums[0] · 1 = nums[0]. The code handles it, but it's a nice sanity check.

7. How to say it in the interview (30 seconds)

"Trying to pick which balloon to burst first gives subsets as state, which is exponential. I flip it: for the open interval (l, r), pick which balloon k is burst last. At that moment its real neighbours are the fixed boundaries v[l] and v[r], so the final pop earns v[l] · v[k] · v[r], and the two sub-intervals (l, k) and (k, r) are independent because k walls them off. I pad with phantom 1s on both ends, fill dp[l][r] by increasing interval length, and return dp[0][n + 1]. Time O(n3), space O(n2)."
