Largest Rectangle in Histogram

LeetCode 84 · Hard · Pattern: monotonic increasing stack of indices · O(n) time, O(n) space

Problem. heights[i] is the height of bar i, each 1 unit wide. Return the area of the largest rectangle that fits entirely inside the histogram.
[2,1,5,6,2,3] → 10   [2,4] → 4   [1,1,1,1] → 4
Link: LeetCode

1. The one idea that solves it

Fix the shortest bar of the rectangle and let it set the height. The best rectangle whose shortest bar is h[k] extends left and right as far as it can without hitting anything shorter. So the key quantities for each bar k are:

  • L[k]: index of the first bar to the left that is strictly shorter than h[k] (or -1 if none).
  • R[k]: index of the first bar to the right that is strictly shorter than h[k] (or n if none).

Then the max rectangle anchored at bar k has width R[k] − L[k] − 1 and area h[k] · (R[k] − L[k] − 1). Take the max over all k.

A single scan with a monotonic increasing stack of indices computes both bounds on the fly. The stack is kept so that heights from bottom to top are strictly increasing. When bar i arrives and is shorter than the top, the top k has finally hit a shorter bar on its right: R[k] = i. And L[k] is the new top after popping k — the stack below k is strictly shorter, by invariant. So the width is i − st.top() − 1 (or just i if the stack is empty, meaning no shorter bar exists to the left of k).

Append a sentinel bar of height 0 at the end so the final pass flushes every remaining bar in the stack. Without it you have to run a second cleanup loop with R[k] = n; the sentinel folds that into the main loop.

Idea. Monotonic increasing stack of indices. When bar i is shorter than the stack top k, pop k and record its rectangle: height h[k], left boundary = new stack top (or -1), right boundary = i, so width = i − st.top() − 1 (or i if the stack is empty). Sentinel 0 at the end flushes everything.

2. Picture of the algorithm

The width formula is the whole trick. After popping k, the new stack top is the first index strictly left of k whose height is strictly less than h[k] (because the stack was increasing and we just removed k). The current index i is the first index strictly right of k whose height is strictly less than h[k] (that is exactly why we are popping). So the open interval (st.top(), i) contains every bar ≥ h[k], with width i − st.top() − 1.

4. Code (C++)

class Solution {
public:
    int largestRectangleArea(vector<int>& h) {
        int n = (int)h.size();
        stack<int> st;                                 // strictly increasing bar heights
        int best = 0;
        for (int i = 0; i <= n; i++) {
            int cur = (i == n) ? 0 : h[i];              // sentinel 0 flushes the stack
            while (!st.empty() && h[st.top()] > cur) {
                int top = st.top(); st.pop();
                int w = st.empty() ? i : i - st.top() - 1;
                best = max(best, h[top] * w);
            }
            st.push(i);
        }
        return best;
    }
};

Complexity: each index is pushed and popped at most once across the entire scan. O(n) time. The stack can hold up to n indices (strictly increasing input), so O(n) space.

Alternative: precompute left / right boundaries explicitly

vector<int> L(n), R(n);
stack<int> s;
for (int i = 0; i < n; i++) {
    while (!s.empty() && h[s.top()] >= h[i]) s.pop();
    L[i] = s.empty() ? -1 : s.top();
    s.push(i);
}
while (!s.empty()) s.pop();
for (int i = n - 1; i >= 0; i--) {
    while (!s.empty() && h[s.top()] >= h[i]) s.pop();
    R[i] = s.empty() ? n : s.top();
    s.push(i);
}
int best = 0;
for (int i = 0; i < n; i++) best = max(best, h[i] * (R[i] - L[i] - 1));

Two passes, three arrays. Clearer about what L and R mean, so write it this way if the one-pass version does not click under pressure. Note the ≥ in the pop condition: it lets runs of equal heights be summarised by the last of them, which still gives the correct maximum (any equal-height prefix can be covered by anchoring at the rightmost one).

5. The part interviewers ask about: why the width is i − st.top() − 1

When we pop k, two things are true because of the increasing-stack invariant:
  • The index now on top of the stack, call it p, has h[p] < h[k] (it sat below k while the stack was strictly increasing, so h[p] was strictly less than h[k]). Every index between p and k was popped earlier for the same reason, so bars p+1 .. k-1 are all ≥ h[k].
  • Bars k+1 .. i-1 that were on the stack at some point were themselves ≥ h[k] (they sat on top of k in a strictly increasing stack) and have already been popped.
So the entire open interval (p, i) contains bars all at least h[k]: its width is i − p − 1. If the stack is empty, there is no bar strictly shorter than h[k] on the left, so the rectangle starts at index 0 and the width is i − 0 = i.

A second subtlety: the pop condition uses strict >. Equal heights are left on the stack. That is fine because when a run of equal heights finally meets a shorter bar, each equal bar in the run gets popped in turn, and the first one to be popped gets a small (correct) width, while the last one popped gets the full run as its width — exactly the maximal rectangle for that height.

6. Traps and edge cases

  • Forgetting the sentinel. Without the extra i == n iteration with cur = 0, bars that are never popped during the normal loop (a strictly increasing suffix) have no final answer. Either run a second cleanup loop or append the sentinel as shown.
  • Using i - top instead of i - st.top() - 1. That is the width "between top and i" counting top, but top has just been popped; the new top is the left boundary. The right fencepost: an open interval (newTop, i) has width i - newTop - 1.
  • Using i - top - 1 after popping (so top is now a stale local). This is actually wrong because top is the index that was just popped, not the left boundary. The left boundary is the stack's new top, not the thing you popped.
  • Comparing heights with ≥ in the main loop. Runs of equal heights pop each other with tiny widths and you under-count. Use > and let the sentinel flush them later with the full run as width.
  • Empty input or single bar. [] → 0 (loop body does not execute if n == 0, since i ≤ n gives i == 0 == n, cur = 0, stack empty, nothing happens). [7] → 7, via one pop at the sentinel.
  • Monotone shapes. [1,2,3,4,5] → 9 (height 3, width 3 anchored at index 2 or equivalently height 2 width 4 at index 1 — take the max). [5,4,3,2,1] → 9 by symmetry. Both reach their answer only at the sentinel.

7. How to say it in the interview (30 seconds)

"I maintain a monotonic increasing stack of indices. When the new bar is shorter than the top, I pop until the top is not taller, and for each popped index k I compute a rectangle: height h[k], width i − stack.top() − 1 after popping, or i if the stack is empty. That width is valid because the new stack top is the first shorter bar on the left of k, and i is the first shorter bar on the right. I append a sentinel 0 so the final pass flushes everything. Each index is pushed and popped once, so O(n) time, O(n) space."
