Binary Tree Level Order Traversal

LeetCode 102 · Medium · Pattern: BFS with per-level batching · O(n) time, O(w) space

Problem. Return the values of a binary tree level by level, left to right, as a list of lists.
[3,9,20,null,null,15,7] → [[3],[9,20],[15,7]]
Link: LeetCode

1. The one idea that solves it

Breadth-first search already visits a tree level by level, but a plain BFS gives one flat list. To split it into levels, record the queue's size at the start of each round and pop exactly that many nodes. Those are the nodes of the current level; everything they push during this round belongs to the next level.

The size snapshot is the whole trick. Without it, the queue mixes two levels and you can't tell where one ends and the next begins.

Idea. Standard BFS, but at the top of each round freeze sz = q.size() and pop exactly that many nodes into one level. Push their children for the next round.

4. Code (C++)

vector<vector<int>> levelOrder(TreeNode* root) {
    vector<vector<int>> out;
    if (!root) return out;
    queue<TreeNode*> q;
    q.push(root);
    while (!q.empty()) {
        int sz = (int)q.size();                 // frozen width of this level
        vector<int> level;
        for (int i = 0; i < sz; i++) {
            TreeNode* n = q.front(); q.pop();
            level.push_back(n->val);
            if (n->left)  q.push(n->left);
            if (n->right) q.push(n->right);
        }
        out.push_back(level);
    }
    return out;
}

Complexity: each node enters and leaves the queue once, O(n) time. The queue holds at most one full level, so O(w) space, where w is the maximum width of the tree. For a balanced tree w ≈ n/2.

Alternative: DFS with depth

void dfs(TreeNode* n, int d, vector<vector<int>>& out) {
    if (!n) return;
    if ((int)out.size() == d) out.push_back({});   // first visit at this depth
    out[d].push_back(n->val);
    dfs(n->left,  d + 1, out);
    dfs(n->right, d + 1, out);
}

Same O(n) time, O(h) stack. Use this when you'd rather avoid an explicit queue, or when the parent problem is already recursive. BFS wins when you need "stop at the first level with property X" because you can early-exit at that round.

5. The part interviewers ask about: the size-snapshot trick

Why not use a sentinel like nullptr between levels? That works, but you then have to push and pop the sentinel, and the queue stops being pure "pointers to real nodes". The size snapshot is cheaper, clearer, and generalises to every BFS-by-level variant: zigzag (LC 103), right-side view (LC 199), average per level (LC 637), bottom-up order (LC 107, just reverse the output).

What if you don't need levels, just a flat BFS order? Drop the inner for and the level vector — push into one flat output. That's the plain BFS skeleton that also powers LC 100 (same tree with two queues) and LC 199 (right-side view by remembering the last node of each level).

6. Traps and edge cases

  • Reading q.size() inside the inner loop. The size changes as you push children. Freeze it once at the start of the round.
  • Pushing a null child. The null test if (n->left) is required or the queue fills up with nulls and crashes on n->val dereference.
  • Empty tree. Must return [], not [[]]. The early if (!root) handles it.
  • Using a stack by accident. Pop from the wrong end and you get DFS, which doesn't preserve left-to-right at each level the way BFS does.
  • Appending to out before you have any children. You end up with an empty trailing level. The outer while only runs when the queue is non-empty, so this doesn't bite — unless you forgot the early return for the empty tree.

7. How to say it in the interview (30 seconds)

"Standard BFS splits into levels if, at the start of each round, I freeze the queue size and pop exactly that many nodes. Those nodes are the current level; everything they push belongs to the next round. One pass over every node, O(n) time, O(w) space for the queue. The same trick extends to zigzag, right-side view, and bottom-up order."
