Best Time to Buy and Sell Stock

LeetCode 121 · Easy · Pattern: one pass, running minimum · O(n) time, O(1) space

Problem. prices[i] is the stock price on day i. Buy on some day and sell on a later day. Return the maximum profit, or 0 if no profit is possible.
[7,1,5,3,6,4] → 5    [7,6,4,3,1] → 0
Link: LeetCode

1. The one idea that solves it

For every day r, the best profit if you sell on day r is prices[r] − min(prices[0..r]). The best profit overall is the max of this over all r. So you only need the smallest price seen so far on your left.

This is a sliding window where the right end walks forward one step at a time, and the left end only jumps to r when a new minimum appears. Between jumps, you just update the profit against the fixed lo.

So the question becomes: as you scan left to right, keep the smallest price so far. Each day, either it is the new low (then move the buy day here) or it beats the best known profit against the current low.

Why one pass is enough: the buy day only ever moves forward to a cheaper price, and the sell day only ever moves forward. There is no case where going back helps — a cheaper buy day in the past would already have been captured.

4. Code (C++)

int maxProfit(vector<int>& prices) {
    int lo = INT_MAX, best = 0;
    for (int p : prices) {
        if (p < lo) lo = p;                         // new buy day
        else if (p - lo > best) best = p - lo;    // try selling today
    }
    return best;
}

Complexity: one linear scan, two integers of state. O(n) time, O(1) space.

5. The part interviewers ask about: why not try every pair?

The brute force is "for every i, for every j > i, track prices[j] − prices[i]". That is O(n2) and fails on big inputs. The one-pass trick works because the inner loop was redundant — for a fixed sell day r, the best buy day is the cheapest day on its left, and that information is one variable.

Generalisation. The same trick turns any "max of f(j) − g(i) for i < j" problem into a single pass: keep min g(i) seen so far on the left, update the answer against today's f(j), then update the running min with today's g(j).

Related harder problems. If you can trade multiple times with no cooldown (LC 122) the answer is the sum of all positive deltas prices[i] − prices[i-1]. With at most k trades (LC 188) it becomes DP over state (day, trades_left, holding?). The sliding-min idea here is the k = 1 base case.

A real interview wrinkle. If prices can be negative or go to zero, the code still works because the inequality p < lo only looks at the raw value. Just make sure lo starts at INT_MAX, not 0.

6. Traps and edge cases

  • Initialising lo to prices[0] and skipping day 0 in the loop. Fine, but then the empty-input case must be handled first or you dereference prices[0].
  • Initialising best to a negative value. You cannot "sell before you buy", so the floor is 0, not a negative profit. The problem asks for max profit achievable, which includes doing nothing.
  • Updating lo and best in the wrong order. If you set lo = p first and then check p - lo > best, every day scores 0. Either compute profit first, or use the if / else if as shown.
  • Monotonically decreasing input. Returns 0, not a negative number. Example: [7,6,4,3,1] → 0.
  • Single-day or empty input. No sell possible, answer is 0.
  • Confusing with LC 122 (multiple trades). That problem is a different pattern: sum of positive daily deltas, not a single buy-sell pair.

7. How to say it in the interview (30 seconds)

"For every day treated as a sell day, the best profit is today's price minus the cheapest price before it. So I walk left to right, keep the minimum price seen so far, and on each day I either beat the minimum (update it) or try to sell against it (update the answer). One pass, O(n) time, O(1) space."
