Longest Substring Without Repeating Characters

LeetCode 3 · Medium · Pattern: variable-size sliding window · O(n) time, O(min(n, Σ)) space

Problem. Given a string s, find the length of the longest substring that contains no repeated character.
"abcabcbb" → 3    "bbbbb" → 1    "pwwkew" → 3
Link: LeetCode

1. The one idea that solves it

Grow a window to the right one character at a time. The window is valid when every letter inside appears at most once. When the new character s[r] was already inside the window, shrink from the left until it is gone.

The key accelerator: you do not need to shrink one step at a time. If you remember the last position of every character, you can jump the left pointer directly past the previous copy.

So the question becomes: keep a map last[c] = last index of c. On every r, if last[s[r]] ≥ l, set l = last[s[r]] + 1. Then write last[s[r]] = r and update best.

Why one jump works: l can only move forward. If last[s[r]] is before l, that copy is already outside the window, so no shrink is needed. If it is inside, moving l to last[s[r]] + 1 removes exactly that copy and leaves everything to its right.

4. Code (C++)

int lengthOfLongestSubstring(string s) {
    int last[128];                         // last index each ASCII char was seen
    fill(last, last + 128, -1);
    int l = 0, best = 0;
    for (int r = 0; r < (int)s.size(); r++) {
        int c = (unsigned char)s[r];
        if (last[c] >= l) l = last[c] + 1;      // jump past the previous copy
        last[c] = r;
        best = max(best, r - l + 1);
    }
    return best;
}

Complexity: each index is visited once by r and the left pointer only moves forward, so O(n). The last array is fixed at 128 ASCII slots, so O(1) space; for arbitrary Unicode it is O(min(n, Σ)) with a hash map.

Alternative: shrink one step at a time with a Set

int lengthOfLongestSubstring(string s) {
    unordered_set<char> seen;
    int l = 0, best = 0;
    for (int r = 0; r < (int)s.size(); r++) {
        while (seen.count(s[r])) { seen.erase(s[l]); l++; }
        seen.insert(s[r]);
        best = max(best, r - l + 1);
    }
    return best;
}

Easier to explain. Still O(n) amortised (each char enters and leaves at most once), but with hashing overhead and no jump trick. Prefer the index map in C++; this version is cleaner in interviews when you want "pure sliding window".

5. The part interviewers ask about: last[c] ≥ l, not last[c] != -1

You might be tempted to write if (last[c] != -1). That is wrong, because an old copy from outside the current window is irrelevant. Example: "abba".

Why the inequality. At index r = 3 ('a'), last['a'] = 0, but l has already moved to 2 because of the earlier 'b','b' clash. Using last[c] ≥ l correctly says "the previous 'a' is not in the window", so no jump needed. The answer is 2 ("ba"). The wrong check would set l = 1, counting the stale index, and give a wrong answer 3.

Follow-up: longest substring with at most k distinct characters (LC 340). Same window shape, but the invariant is "distinct count ≤ k" instead of "every char appears once". Use a count map and shrink while distinct > k.

Why not sort or hash the substring? Any such approach needs to try O(n2) substrings. The window works because adding a letter can only increase the duplicate count, and removing from the left can only decrease it, so the valid region is a single interval of right endpoints for each left — a monotone structure a window exploits.

6. Traps and edge cases

  • Not clearing stale indices. Using last[c] != -1 instead of last[c] ≥ l gives wrong answers on strings like "abba". Expected 2, bug gives 3.
  • Updating last[c] before the jump check. Then every character would jump to itself and l would equal r forever, returning 1. Jump first, then record.
  • Using size_t or unsigned for l and r. Fine here (both only move forward), but mixing them with signed arithmetic (r - l + 1) can produce surprising values. Keep both int.
  • Only sizing the array for lowercase. The problem allows ASCII symbols, digits and spaces. Use 128 or a hash map.
  • Empty string. Answer is 0. The loop body never runs, which is correct.
  • Spaces and symbols count. " !$" has three distinct characters so the answer is 3.

7. How to say it in the interview (30 seconds)

"I grow a window to the right and shrink from the left whenever the new character is already in it. To avoid shrinking one step at a time, I keep a map from character to its last index. When s[r] was last seen at or after l, I jump l to last[s[r]] + 1. Then I update last[s[r]] = r and the answer with the new window length. O(n) time, O(Σ) space."
