Network Delay Time

LeetCode 743 · Medium · Pattern: single-source shortest path (Dijkstra) · O((V+E) log V) time, O(V+E) space

Problem. You have n nodes numbered 1..n. times[i] = [u, v, w] means a signal from u to v takes w time (directed, non-negative weights). A signal is sent from node k. Return the time until every node has received it, or -1 if some node never does.
times=[[2,1,1],[2,3,1],[3,4,1]], n=4, k=2 → 2
Link: LeetCode

1. The one idea that solves it

"Time until the last node hears it" is "the maximum shortest distance from k to any node". So this is single-source shortest path on a directed graph with non-negative weights — the exact problem Dijkstra solves.

Dijkstra keeps a tentative distance dist[v] for every node (infinity at the start, 0 at the source) and a min-heap of (distance, node) candidates. Each step pops the cheapest unsettled node, locks in its distance, and relaxes its outgoing edges.

Idea. Greedy by shortest tentative distance. The first time the heap pops a node, that distance is final, because every edge weight is ≥ 0 so no later path can be cheaper.

2. Picture of the algorithm

The "stale entry" check is the small trick that lets us push an improved distance instead of expensively decreasing a key already inside the heap. We just push a new pair; the old one gets ignored when it finally pops.

4. Code (C++)

int networkDelayTime(vector<vector<int>>& times, int n, int k) {
    vector<vector<pair<int,int>>> adj(n + 1);        // adj[u] = {(v, w), ...}
    for (auto& t : times) adj[t[0]].push_back({t[1], t[2]});

    vector<int> dist(n + 1, INT_MAX);
    dist[k] = 0;

    priority_queue<pair<int,int>, vector<pair<int,int>>, greater<>> pq;
    pq.push({0, k});

    while (!pq.empty()) {
        auto [d, u] = pq.top(); pq.pop();
        if (d > dist[u]) continue;                      // stale entry, skip
        for (auto [v, w] : adj[u]) {
            if (d + w < dist[v]) {
                dist[v] = d + w;
                pq.push({dist[v], v});
            }
        }
    }

    int ans = 0;
    for (int i = 1; i <= n; i++) {
        if (dist[i] == INT_MAX) return -1;
        ans = max(ans, dist[i]);
    }
    return ans;
}

Complexity: O((V + E) log V). Each edge is relaxed at most once per push into the heap; the heap holds at most E entries. The adjacency list is O(V + E) space, the heap O(E).

5. The part interviewers ask about: why the first pop is final

Correctness. Suppose Dijkstra pops u with distance d, and some other path to u exists with total cost d' < d. Walk that path from the source: the first node on it that is still unsettled has tentative distance ≤ d' (we would have relaxed into it from a settled predecessor). So it is cheaper than u and would have popped first — contradiction. The first pop is final.

This argument needs non-negative weights. With a negative edge, a later detour through it could cheapen a node we have already settled, breaking the invariant. For negative weights use Bellman-Ford instead (LC 787).

Why we push duplicates instead of decrease-key

C++'s priority_queue has no efficient decrease-key. The clean fix is: when we find a cheaper distance, push a new pair and let the old one sit. When the stale pair pops, d > dist[u] and we continue. The heap stays O(E) and each pop is still O(log V).

6. Traps and edge cases

  • Treating the graph as undirected. Edges are directed. u → v does not imply v → u.
  • Forgetting the stale check. Without if (d > dist[u]) continue; you re-relax from an out-of-date distance and the result is still correct, but you pay a lot more work. Keep the check.
  • 1-indexed nodes. Nodes are 1..n, so use n + 1 sized arrays and check indices 1..n for the answer.
  • Overflow with INT_MAX. Do not compute dist[u] + w when dist[u] == INT_MAX. The stale check guards us (we only relax after popping a real distance), but a hand-rolled version has to be careful.
  • Unreachable node. Return -1 as soon as any dist[i] stays infinite. Easy to miss when you are focused on the "max" computation.
  • Self-loops. Allowed, don't shorten anything, and the stale check filters the re-pop.

7. How to say it in the interview (30 seconds)

"The answer is the maximum shortest distance from k to any node, so I run Dijkstra. I keep a distance array and a min-heap seeded with (0, k). Pop the smallest, skip if the popped distance is bigger than the recorded one, otherwise relax every outgoing edge and push improved distances. Non-negative weights make the first pop of each node final. At the end I take the max of the distance array; if any node is still infinity, return -1. The time is O((V+E) log V)."
