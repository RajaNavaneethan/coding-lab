Reverse Nodes in k-Group

LeetCode 25 · Hard · Pattern: in-place reversal in blocks · O(n) time, O(1) space

Problem. Given a linked list, reverse every consecutive run of k nodes. If the final run has fewer than k nodes, leave it alone. Modify the nodes in place (no new allocations).
[1,2,3,4,5], k=2 → [2,1,4,3,5]    [1,2,3,4,5], k=3 → [3,2,1,4,5]
Link: LeetCode

1. The one idea that solves it

Split the list mentally into blocks of k. For each block that has exactly k nodes, reverse it using the LC 206 three-pointer flip, then stitch it back to the previous block's tail and to the next block's head. The last block is reversed only if it has k nodes; otherwise it stays as-is.

The stitching is where the hard-level reputation comes from. Keep a groupPrev pointer at the node immediately before the current block. After reversing the block, groupPrev->next must point at what used to be the k-th node of the block (its new head), and the old first node (its new tail) must point at the first node of the next block. A dummy head at the very front gives groupPrev somewhere to start.

Idea. Dummy head + groupPrev. For each block: locate the k-th node, abort if fewer than k remain, reverse the block in place, re-link groupPrev->next to the new head and the block's new tail to the next block's head. Advance groupPrev.

2. Picture of the algorithm

Each block is reversed with the same loop as LC 206, except we stop at groupNext (the first node after the block) instead of at nullptr. That one change makes the reversal "local" to the block. After reversal, the old block head becomes the new block tail, which is exactly the node you'll want to groupPrev from on the next iteration.

4. Code (C++)

ListNode* reverseKGroup(ListNode* head, int k) {
    ListNode dummy(0);
    dummy.next = head;
    ListNode* groupPrev = &dummy;

    while (true) {
        // 1. Find the k-th node after groupPrev; abort if fewer than k remain.
        ListNode* kth = groupPrev;
        for (int i = 0; i < k && kth; i++) kth = kth->next;
        if (!kth) break;

        ListNode* groupStart = groupPrev->next;
        ListNode* groupNext  = kth->next;

        // 2. Reverse nodes [groupStart .. kth]. Stop when curr == groupNext.
        ListNode* prev = groupNext;
        ListNode* curr = groupStart;
        while (curr != groupNext) {
            ListNode* nxt = curr->next;
            curr->next = prev;
            prev = curr;
            curr = nxt;
        }

        // 3. Re-link ends. groupStart is now the new tail of the block.
        groupPrev->next = kth;
        groupPrev = groupStart;
    }
    return dummy.next;
}

Complexity: each node is reversed at most once (and the k-counter walks it once more). Total work is 2n pointer updates ⇒ O(n) time. The dummy, four pointers inside the loop; O(1) extra space.

Alternative: recursive

ListNode* reverseKGroup(ListNode* head, int k) {
    // Peek k nodes; if fewer, return head unchanged.
    ListNode* kth = head;
    for (int i = 0; i < k; i++) {
        if (!kth) return head;
        kth = kth->next;
    }
    // Reverse [head .. kth), stopping at kth.
    ListNode* prev = reverseKGroup(kth, k);
    ListNode* curr = head;
    while (curr != kth) {
        ListNode* nxt = curr->next;
        curr->next = prev;
        prev = curr;
        curr = nxt;
    }
    return prev;
}

Prefer when the interviewer asks for recursion or when you've already solved LC 206 recursively on the same page. Clearer code, but O(n/k) stack frames (up to O(n) if k = 1). The iterative version is the default on long lists.

5. The part interviewers ask about: three stitching invariants

Hold these three facts in your head and the stitching writes itself:
  • At the top of each iteration, groupPrev points at a node whose next is the first node of the unprocessed list.
  • After "find kth", kth is the k-th node of the block (so the block is groupStart .. kth, inclusive).
  • After reversing, kth is the block's new head and groupStart is the block's new tail. We publish those by writing groupPrev->next = kth and the inner loop setting groupStart->next = groupNext (that write happens on the first iteration of the inner loop, when prev = groupNext).

A classic follow-up: what breaks if we start the inner reversal with prev = nullptr instead of prev = groupNext? Then after the block reversal, groupStart->next is nullptr, and we lose the rest of the list. Using groupNext as the sentinel elegantly re-attaches the suffix "for free" during reversal; no extra line needed.

A second follow-up: why advance groupPrev to groupStart, not to kth? Because groupStart is now the tail of the just-finished block, so its next is the head of the next unprocessed block — exactly the invariant for groupPrev.

6. Traps and edge cases

  • Reversing a partial block. The spec says last-block-with-fewer-than-k stays as-is. The if (!kth) break; is doing that; drop it and you reverse a partial block.
  • Losing groupNext before the inner loop. kth->next is overwritten during the reversal; cache it in a local first.
  • Walking k-counter past the end. The kth loop needs the && kth guard, otherwise kth->next may dereference null.
  • Returning head instead of dummy.next. The original head may now be mid-list.
  • Forgetting to initialise dummy.next = head. Then on an input with fewer than k nodes, you return dummy.next = nullptr instead of the untouched list.
  • k = 1. Each "block" is one node, reversing it is a no-op. The code handles it (block reversal copies the single node's next back to itself-via-groupNext, which is a no-op in terms of the final list order).
  • k = n. One single reverse of the whole list. The code reverses it; groupNext is nullptr, matching plain LC 206.

7. How to say it in the interview (30 seconds)

"I keep a dummy head and a groupPrev pointer. For each block, I walk k steps to find the k-th node. If I ran out, I stop; the trailing short block stays. Otherwise I reverse the block in place using the standard three-pointer flip, with the inner reversal's prev seeded as groupNext (the node after the block) so the suffix stays attached. Then I write groupPrev->next = kth and advance groupPrev to the block's old first node, which is now its tail. Each node is touched a constant number of times, so O(n) time, O(1) space."
