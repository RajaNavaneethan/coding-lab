Edit Distance

LeetCode 72 · Hard · Pattern: 2-D DP on two strings (Levenshtein) · O(m · n) time, O(m · n) space

Problem. Given two strings word1 and word2, return the minimum number of operations to convert word1 into word2. Operations are insert a character, delete a character, or replace a character, each costing 1.
"horse" → "ros" = 3 (replace h→r, delete r, delete e)    "intention" → "execution" = 5
Link: LeetCode

1. The one idea that solves it

Define dp[i][j] as the minimum edits to turn word1[0..i) into word2[0..j). Look at the last characters. If they match, do nothing on this pair; the cost is whatever it took to align the shorter prefixes:

  • Match. dp[i][j] = dp[i−1][j−1].
  • Mismatch. Three ways to make this last character line up, pick the cheapest:
    • Replace word1[i−1] with word2[j−1]: cost 1 + dp[i−1][j−1].
    • Delete word1[i−1] (consume one from word1, nothing from word2): cost 1 + dp[i−1][j].
    • Insert word2[j−1] into word1 (consume one from word2, nothing from word1): cost 1 + dp[i][j−1].
dp[i][j] = w1[i−1]=w2[j−1] ? dp[i−1][j−1] : 1 + min(dp[i−1][j−1], dp[i−1][j], dp[i][j−1])

Base: an empty word1 needs j inserts to become word2[0..j), so dp[0][j] = j. Symmetrically dp[i][0] = i.

Idea. Every edit plan ends with exactly one of four local decisions on the two last characters: skip (they already match), replace, delete the last of word1, insert the last of word2. Each decision reduces the problem to a smaller rectangle in a specific direction. The DP tries all three paid decisions and the free skip.

2. Picture of the algorithm

Each cell (i, j) depends on three neighbours: diagonal (i−1, j−1), above (i−1, j) and left (i, j−1). Fill row by row; by the time you reach (i, j) all three are ready. The first row and first column are the number of pure inserts / pure deletes to get there.

4. Code (C++)

class Solution {
public:
    int minDistance(string word1, string word2) {
        int m = word1.size(), n = word2.size();
        vector<vector<int>> dp(m + 1, vector<int>(n + 1, 0));
        for (int i = 0; i <= m; i++) dp[i][0] = i;   // delete i chars
        for (int j = 0; j <= n; j++) dp[0][j] = j;   // insert j chars
        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                if (word1[i-1] == word2[j-1])
                    dp[i][j] = dp[i-1][j-1];
                else
                    dp[i][j] = 1 + min({dp[i-1][j-1], dp[i-1][j], dp[i][j-1]});
            }
        }
        return dp[m][n];
    }
};

Complexity: O(m · n) time — one constant-work min per cell. O(m · n) space, reducible to O(min(m, n)) by rolling one row and keeping a prevDiag variable (same trick as LCS).

5. The part interviewers ask about: why three neighbours

The recurrence has three edit choices plus a "match-free" skip. Why not more? Any sequence of edits that converts word1[0..i) into word2[0..j) ends with one and only one of these cases for the last character on each side:

Last decisionCostComes from
Characters already match0(i−1, j−1)
Replace w1[i−1] with w2[j−1]1(i−1, j−1)
Delete w1[i−1]1(i−1, j)
Insert w2[j−1] at the end1(i, j−1)
"Delete from word1" and "insert into word1" are mirror images, so one of them always moves one step up and the other moves one step left. The diagonal step covers both match and replace in one place. No edit can look at anything further than one row/column back, which is why the table has clean row-order fill.

Recovering the edits

Walk back from dp[m][n]: at each cell, pick the neighbour whose value plus the local cost equals the current cell. "Diagonal, no cost increase" means a match; "diagonal, +1" means replace; "above, +1" means delete; "left, +1" means insert. The walk is O(m + n).

6. Traps and edge cases

  • Forgetting the first row/column. Without dp[i][0] = i and dp[0][j] = j every cell reads a bogus 0, and the answer is wrong (often too small).
  • Mixing up insert and delete. They look symmetric and lots of candidates swap them. If you keep "insert into word1 means consume one char from word2", you read dp[i][j−1]; "delete from word1" reads dp[i−1][j]. One rule to anchor it: the index that moves back is the string whose character you consumed.
  • Taking only two neighbours. On a mismatch, you need all three (diagonal, above, left). Dropping the diagonal (replace) gives wrong answers like Edit Distance of "a" to "b" being 2 instead of 1.
  • One empty string. dp[m][0] = m and dp[0][n] = n handle this correctly — no need for a special case.
  • Case sensitivity. "A" vs "a" is a mismatch (counts as 1), unless the problem says otherwise. LC 72 is case-sensitive.

7. How to say it in the interview (30 seconds)

"I define dp[i][j] as the minimum edits to turn word1[0..i) into word2[0..j). Base: dp[i][0] = i, dp[0][j] = j (pure deletes or inserts). If the last two characters match the cost carries over from the diagonal; otherwise the cell is 1 + min(diagonal, above, left) for replace, delete, insert. I fill row by row and return dp[m][n]. O(m · n) time, O(m · n) space; a rolling row drops it to O(min(m, n)). To report the actual edits, walk back from the bottom-right along the chosen predecessor."
