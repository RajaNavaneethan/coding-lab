Word Search

LeetCode 79 · Medium · Pattern: backtracking on a grid (DFS with mark / unmark) · O(R · C · 4L) time, O(L) extra space

Problem. Given a 2-D grid of letters and a target word, return true if the word can be spelled by walking through adjacent (up / down / left / right) cells. The same cell may not be used twice in one spelling.
board = [["A","B","C","E"],["S","F","C","S"],["A","D","E","E"]], word = "ABCCED" → true
same board, word = "SEE" → true    word = "ABCB" → false
Link: LeetCode

1. The one idea that solves it

Try every cell as the starting letter. From there, run a depth-first search that matches one letter at a time. To avoid using a cell twice, temporarily overwrite that cell with a sentinel ('#') before recursing and restore it after the recursion returns. This is backtracking in grid form: the "unchoose" step is "put the letter back".

Four moves at each level (up, down, left, right). The index into the word acts like the depth of the recursion: when it reaches word.size() you have spelled the whole word and can return true.

Idea. DFS from every starting cell. Walk the word's letters one by one; mark the current cell visited by writing a sentinel in place; unmark it when the recursion returns. The visited-marker on the board is the "cur" of this problem.

4. Code (C++)

class Solution {
public:
    bool exist(vector<vector<char>>& board, string word) {
        int R = board.size(), C = R ? board[0].size() : 0;
        function<bool(int, int, int)> dfs = [&](int r, int c, int k) -> bool {
            if (k == (int)word.size()) return true;
            if (r < 0 || r >= R || c < 0 || c >= C) return false;
            if (board[r][c] != word[k]) return false;

            char save = board[r][c];
            board[r][c] = '#';                                 // mark visited
            bool ok = dfs(r+1, c, k+1) || dfs(r-1, c, k+1)
                   || dfs(r, c+1, k+1) || dfs(r, c-1, k+1);
            board[r][c] = save;                                 // unmark on the way out
            return ok;
        };
        for (int r = 0; r < R; r++)
            for (int c = 0; c < C; c++)
                if (dfs(r, c, 0)) return true;
        return false;
    }
};

Complexity: each DFS has four branches up to depth L = word.size(), so one DFS costs O(4L) in the worst case. The outer loop launches R · C of them, giving O(R · C · 4L) time. Extra space is O(L) for the recursion stack; marking happens in-place.

Alternative: separate visited array

vector<vector<bool>> vis(R, vector<bool>(C, false));
// then: vis[r][c] = true; ... vis[r][c] = false;
// and the mismatch check reads board[r][c] directly, not with a sentinel.

Same complexity, no mutation of the input. Prefer this when the function must be const on board or when you can't tolerate a scratch value colliding with a real letter. Prefer the in-place sentinel in interviews when the problem says "modifying is allowed" because it uses zero extra memory.

5. The part interviewers ask about: pruning and search order

LC 79 inputs can be up to 6×6 with a word of length 15, so a naive 415 ≈ 109 would TLE. Two small tweaks keep it fast in practice.

Starting-letter prune. Only call dfs(r, c, 0) when board[r][c] == word[0]. Simple and cuts out a lot of dead starts.

Rare-end-first. If word's first letter is common on the board and its last letter is rare, reverse word before searching. Fewer successful starts means fewer deep DFS trees. Interviewers like you to notice this.

A related subtle point: the "same cell may not be used twice" condition is the whole point of mark/unmark. If you forget to unmark, cells get stuck visited across sibling branches and you miss valid paths. If you forget to mark, the DFS can walk back onto itself and spell words that use a cell twice.

6. Traps and edge cases

  • Forgetting to unmark. After dfs returns false, the sentinel is still on the board. Later DFS calls from a different starting cell see holes.
  • Returning early inside the four-direction OR. You still need to restore board[r][c] before returning true. The short-circuit in || handles that for you here, but a hand-rolled version with early return true can leave the board dirty.
  • Index into word off by one. The base case is k == word.size(), not k == word.size() - 1. Checking board[r][c] == word[k] at k = L would read past the string.
  • Single-cell board. board = [["A"]], word = "A" must return true; word = "AA" must return false (can't reuse the cell).
  • Word longer than the number of cells. Return false immediately as a cheap prune, or just let the DFS bottom out.

7. How to say it in the interview (30 seconds)

"I try every cell as a starting point and run DFS matching one letter of the word at a time. Before recursing I overwrite the current cell with a sentinel so my own path can't walk back onto it, then restore it when the call returns, which is the backtrack step. Four neighbours at each depth, depth equals the word length, so per start it's O(4L), total O(R · C · 4L). Space is O(L) for the recursion. The one optimisation I'd mention is to skip starts whose letter doesn't match word[0], and reverse the word when its last letter is rarer than its first."
