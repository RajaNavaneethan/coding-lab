Longest Repeating Character Replacement

LeetCode 424 · Medium · Pattern: variable-size sliding window · O(n) time, O(1) space

Problem. s has uppercase letters. You may change at most k characters to any letter. Return the length of the longest substring that is one repeated letter after the changes.
"AABABBA", k=1 → 4    "ABAB", k=2 → 4

1. The one idea that solves it

Pick any substring. The cheapest way to make it a single letter is to keep the letter that appears most and repaint everything else. So the number of changes that substring needs is:

changes needed = window length − count of most frequent letter

Example: the window AABA has 3 A's and 1 B. Keep the A's, repaint the B.

length 4 − maxFreq 3 = 1 change ≤ k=1  valid

So the question becomes: find the longest window where length − maxFreq ≤ k. That is a sliding-window condition. Grow the window to the right; when the condition breaks, shrink from the left.

Why a window works here: adding a letter on the right can only add changes (or keep them the same), and removing a letter on the left can only remove changes. Cost moves in one direction as the window grows, which is exactly what a sliding window needs.

4. Code (C++)

int characterReplacement(string s, int k) {
    int freq[26] = {0};             // letter counts inside the window
    int l = 0, maxFreq = 0, best = 0;

    for (int r = 0; r < (int)s.size(); r++) {
        maxFreq = max(maxFreq, ++freq[s[r] - 'A']);   // 1. expand right

        while ((r - l + 1) - maxFreq > k) {     // 2. too many repaints
            freq[s[l] - 'A']--;
            l++;
        }
        best = max(best, r - l + 1);            // 3. window is valid
    }
    return best;
}

Complexity: each index enters the window once (r) and leaves at most once (l), so O(n). The freq array is fixed at 26, so O(1) space.

5. The part interviewers ask about: maxFreq never goes down

Look at the code again. When we shrink from the left, we decrease freq but we never lower maxFreq. So after a shrink, maxFreq can be larger than the real top count in the window. That looks like a bug. It isn't.

Why it's still correct. We only care about best, the longest window ever found. A window longer than best needs len ≤ maxFreq + k with a bigger maxFreq than we have ever seen. maxFreq only grows when some letter's real count in the current window reaches a new high. So a stale maxFreq can keep a too-long window alive, but it can never make best larger than a real valid window. The answer only improves when maxFreq genuinely improves.

In the trace for "AABABBA": at r=4 the window ABAB really needs 2 changes, but stale maxFreq = 3 says it needs 1. Nothing goes wrong, because best is already 4 and this window is length 4. It cannot push the answer higher.

If you'd rather not defend that in the interview, recompute the true max each time. It's still O(n), just 26 times more work per step:

while ((r - l + 1) - *max_element(freq, freq + 26) > k) {
    freq[s[l] - 'A']--;
    l++;
}

The trace in section 3 uses this exact version, so every window shown there is genuinely valid. Both versions return the same answers on all test cases.

A further detail you may be asked: because best only needs to grow, you can replace while with if. Then the window never shrinks, it just slides one step right whenever it's too long. Same answer, same O(n).

6. Traps and edge cases

  • Counting repaints as "letters that differ from s[l]". The letter to keep is the most frequent one, not the first one in the window. "BAAA", k=1 must give 4.
  • Using s[r] - 'a'. The input is uppercase. Lowercase offset gives negative indexes and undefined behaviour.
  • Recording best before shrinking. You'd record an invalid window. Shrink first, then record.
  • k = 0. Becomes "longest run of one letter". "AAAB", 0 → 3.
  • k ≥ length. The whole string can be repainted. "ABCDE", k=5 → 5. The code handles it with no special case.

7. How to say it in the interview (30 seconds)

"To make a window one letter, I keep its most frequent letter and change the rest, so the cost is length minus max frequency. I need the longest window where that cost is at most k. I grow the window on the right, keep a 26-letter count, and shrink from the left whenever the cost exceeds k. Each index enters and leaves once, so it's O(n) time and O(1) space."
