Invert Binary Tree

LeetCode 226 · Easy · Pattern: post-order DFS · O(n) time, O(h) space

Problem. Given the root of a binary tree, swap every node's left and right child. Return the root.
[4,2,7,1,3,6,9] → [4,7,2,9,6,3,1]    [2,1,3] → [2,3,1]
Link: LeetCode

1. The one idea that solves it

Inversion is defined by one rule: every node's children swap places. Children of children do the same, and so on. That is a recursive definition, so write a recursive function.

At one node, you can't "swap this subtree with that subtree" until both subtrees are already inverted. So invert both children first, then swap the two pointers at the current node. This is post-order DFS (do the children, then the node). A pre-order variant works too (swap first, then recurse), but the post-order shape makes the "do children first, act on node after" habit stick, which is the common tree shape.

Idea. Define invert as: invert left subtree, invert right subtree, then swap the two pointers at this node. Base case: an empty subtree is already inverted.

4. Code (C++)

TreeNode* invertTree(TreeNode* root) {
    if (!root) return nullptr;
    TreeNode* L = invertTree(root->left);     // invert left subtree
    TreeNode* R = invertTree(root->right);    // invert right subtree
    root->left  = R;                          // swap
    root->right = L;
    return root;
}

Complexity: each node is touched exactly once, so O(n) time. Recursion depth equals the tree height, so O(h) stack space (O(log n) balanced, O(n) worst case for a chain).

Alternative: iterative BFS

TreeNode* invertTree(TreeNode* root) {
    if (!root) return nullptr;
    queue<TreeNode*> q; q.push(root);
    while (!q.empty()) {
        TreeNode* n = q.front(); q.pop();
        swap(n->left, n->right);
        if (n->left)  q.push(n->left);
        if (n->right) q.push(n->right);
    }
    return root;
}

Same O(n) time. Use this when the tree is tall enough that recursion depth is a real worry. The queue holds at most one full level, so O(w) space where w is the maximum width.

5. The part interviewers ask about: order doesn't matter here, but usually it does

Invert is one of the rare tree problems where pre-order and post-order give the same tree. Swapping is a self-contained action on one node; it doesn't look at anything the children returned. Most tree problems are not like that: validate BST, maximum path sum, LCA all need information from the children before deciding at the parent, so the post-order shape (recurse first, then combine) is forced.

So the real lesson of 226 is the skeleton: recurse into both children, then do constant work at the node. You will reuse this skeleton for 98, 110, 111, 104, 543, 110, 124. Every page in this pattern that returns a tree-wide answer starts here.

6. Traps and edge cases

  • Forgetting the empty-tree base case. invertTree(nullptr) must return nullptr, not dereference it.
  • Swapping without saving one side first. root->left = root->right; root->right = root->left; loses the original left. Use the two returned pointers, or std::swap.
  • Doing it top-down without recursion. Walking only the original left spine and assigning will leave the right subtree alone. The job is on every node.
  • Edge: single node. Return the node unchanged. The recursion handles it: both children are nullptr, the swap is a no-op.
  • Edge: left-only chain [1,2,null,3]. After inversion it is a right-only chain [1,null,2,null,3].

7. How to say it in the interview (30 seconds)

"Inversion is defined recursively: swap the children of every node. So I invert the left subtree, invert the right subtree, then swap the two pointers at the current node. The base case is an empty tree. Each node is touched once, so it's O(n) time and O(h) stack space. If the tree is very tall, I'd switch to a BFS with a queue."
