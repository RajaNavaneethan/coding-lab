Insert Interval

LeetCode 57 · Medium · Pattern: three-phase sweep · O(n) time, O(n) space

Problem. You are given a list of non-overlapping intervals, already sorted by start, and a single newInterval = [s, e]. Insert the new interval, merging with any that overlap, and return the resulting list (still sorted, still non-overlapping).
[[1,3],[6,9]], [2,5] → [[1,5],[6,9]]
[[1,2],[3,5],[6,7],[8,10],[12,16]], [4,8] → [[1,2],[3,10],[12,16]] (merges three existing intervals)
Link: LeetCode

1. The one idea that solves it

The existing list is already sorted and non-overlapping. On the number line this means the intervals the new one touches form one contiguous block — nothing can skip over a gap. So one left-to-right pass splits into three phases:

  1. Before. Intervals that end strictly before the new one starts. Copy them straight through.
  2. Merge. Intervals whose start is ≤ newInterval.end. These overlap the new one. Fold them all into one stretched interval by taking min of starts and max of ends. Push once.
  3. After. Remaining intervals. Copy them straight through.

No sort is needed. The input is already in the right order, and the three phases happen in that order because the intervals do not overlap each other.

Idea. Because the list is sorted and non-overlapping, the intervals that touch the new one are a single contiguous block. Walk left to right in three phases: copy the ones before, merge the block that overlaps, copy the ones after.

4. Code (C++)

class Solution {
public:
    vector<vector<int>> insert(vector<vector<int>>& intervals, vector<int> newInterval) {
        vector<vector<int>> out;
        int n = intervals.size(), i = 0;
        // 1. copy intervals strictly before the new one
        while (i < n && intervals[i][1] < newInterval[0]) out.push_back(intervals[i++]);
        // 2. merge every interval that overlaps the new one
        while (i < n && intervals[i][0] <= newInterval[1]) {
            newInterval[0] = min(newInterval[0], intervals[i][0]);
            newInterval[1] = max(newInterval[1], intervals[i][1]);
            i++;
        }
        out.push_back(newInterval);
        // 3. copy the rest
        while (i < n) out.push_back(intervals[i++]);
        return out;
    }
};

Complexity: each interval is looked at once — O(n) time, O(n) output space. No sort because the input is already sorted.

5. The part interviewers ask about

Why is the overlapping block contiguous? Suppose interval A at index i does not overlap the new one (ends before it) and interval C at index k > i does. The existing list is non-overlapping and sorted, so every interval B between them has B.start > A.end. Nothing says B must overlap the new one too — but once a C that does overlap appears, every interval from the first overlapper to the last overlapper is in a single run, because the list is sorted by start and each start is ≥ its predecessor. The merge phase closes exactly one run.

Could we use binary search? Yes — find the first index with end ≥ newInterval.start using lower_bound, then linear-merge from there. It saves nothing in the worst case (the merge block can cover everything) but it is a nice touch when the input is big and the overlap is small.

Streaming inserts. If many new intervals arrive one at a time, keep them in a std::set keyed by start. Each insert is O(log n) to find predecessor/successor, then O(k) to erase and merge k touching intervals, which amortises well because once erased they never come back.

6. Traps and edge cases

  • Using ≤ instead of < in phase 1. Touching endpoints count as overlap on LC 57 ([1,3] and [3,5] merge), so an interval ending exactly at newInterval.start belongs to the merge block, not the copy-through block.
  • Forgetting min on the new start. If the new interval starts inside an existing one (e.g. [[1,10]], insert [2,3]), the merged start must stay 1.
  • Pushing newInterval twice — or forgetting to push it when it goes at the end of the list ([[1,2]], insert [3,4]). The push-after-the-merge-loop handles both cases naturally.
  • Empty input list. Result is just [newInterval].
  • New interval covers everything. Phase 2 eats every interval; phase 1 and phase 3 do nothing. Result is a single interval.
  • New interval disjoint on either side. Phase 2 runs zero times; newInterval is pushed as-is between the two copy phases.

7. How to say it in the interview (30 seconds)

"The list is already sorted and non-overlapping, so overlapping intervals form one contiguous block. I do three phases: copy intervals that end before the new start, fold every interval that still overlaps into the new one by taking min of starts and max of ends, push the merged interval once, then copy the rest. One pass, O(n), no sort."
