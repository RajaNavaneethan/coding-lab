Linked List Cycle II

LeetCode 142 · Medium · Pattern: Floyd's tortoise and hare · O(n) time, O(1) space

Problem. Given the head of a linked list, return the node where the cycle begins, or nullptr if there is no cycle.
Example: 3 → 2 → 0 → -4 → (back to 2)  returns the node holding 2.
Link: LeetCode

1. The one idea that solves it

A hash set of visited pointers works in O(n) time and O(n) space. Floyd's algorithm reaches the same answer with O(1) extra memory, which is what interviewers want to see.

It has two phases. Phase 1: a slow pointer (one step) and a fast pointer (two steps) start at the head. If there's a cycle, the fast pointer catches up to the slow pointer from behind inside the cycle. If there isn't, the fast pointer walks off the end. Phase 2: reset the slow pointer to the head and walk both pointers one step at a time. They collide exactly at the entrance of the cycle.

Idea. Phase 1 finds some point inside the cycle (the "meeting point"). Phase 2 uses a short distance argument to turn that into the cycle's entrance: two walkers at the same speed, one from the head and one from the meeting point, meet at the start of the cycle.

2. The distance argument (phase 2's magic)

Call L the length from head to the start of the cycle, C the cycle length, and k the distance from the cycle start forward to the meeting point. When slow and fast meet:

  • Slow has walked L + k steps (it entered the cycle after L steps, then went k more).
  • Fast has walked 2(L + k) steps (twice as fast, same amount of time).
  • Fast is also L + k + n·C for some integer n ≥ 1 (it did some whole laps around the cycle after catching slow's position).

Set those two expressions for fast equal:

2(L + k) = L + k + n·C   ⇒   L + k = n·C   ⇒   L = n·C − k = (n−1)·C + (C − k)

So from the meeting point, walking C − k steps lands exactly on the cycle start. From the head, walking L steps also lands on the cycle start, and L is an integer number of full laps plus those same C − k steps. Two walkers at speed 1, one from each place, must therefore meet exactly at the cycle start.

3. Picture of the algorithm

Phase 1 answers "is there a cycle?" and, if so, parks the slow pointer at some arbitrary point inside. Phase 2 converts that point into the cycle's entrance using the distance identity above.

5. Code (C++)

ListNode* detectCycle(ListNode* head) {
    ListNode* slow = head;
    ListNode* fast = head;
    while (fast && fast->next) {         // phase 1: find any meeting point
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) {
            ListNode* a = head;              // phase 2: walk one step at a time
            ListNode* b = slow;
            while (a != b) { a = a->next; b = b->next; }
            return a;                      // the cycle start
        }
    }
    return nullptr;                       // fast walked off the end ⇒ no cycle
}

Complexity: Phase 1 takes at most 2n steps (slow walks at most n). Phase 2 walks at most L < n steps. Total O(n) time, O(1) extra space. The two pointers are the whole state.

Alternative: hash set

ListNode* detectCycle(ListNode* head) {
    unordered_set<ListNode*> seen;
    while (head) {
        if (seen.count(head)) return head;
        seen.insert(head);
        head = head->next;
    }
    return nullptr;
}

Prefer only when the interviewer explicitly asks the hash version or when the pointer invariants of Floyd's version feel too fragile in a live interview. Still O(n) time but O(n) space; interviewers usually push you off this toward Floyd's.

6. The part interviewers ask about: why fast catches slow at all

Fast gains one step on slow per iteration. Once slow enters the cycle (after L iterations), both pointers are inside a loop of length C. Their gap (fast ahead of slow) changes by exactly +1 each step (mod C). After at most C steps that gap is 0, so they meet. The gap never skips over zero because fast moves at integer speed relative to slow, not by jumps larger than 1.

Follow-up: could there be an off-by-one if fast lands "past" slow instead of exactly on it? No. Both start at the head, so their positions are integer-equal (mod C) at every step after slow enters the cycle. A gap that decreases by 1 each step from some non-negative value must hit 0.

Follow-up: why is fast && fast->next the right termination? Fast reads fast->next->next, so you need both pointers to exist. If either is null, there is no cycle (an acyclic list ends in a null, and we got there).

Follow-up: what if the whole list is one giant cycle? Then L = 0, k is wherever fast and slow meet, and phase 2 starts with a = head and b = slow already satisfying a == b after 0 steps iff the meeting point already is the head. In general they still meet in C − k steps at the head node.

7. Traps and edge cases

  • Returning the meeting point. That's the result of phase 1, not the answer. Phase 2 is mandatory.
  • Writing while (slow != fast). They start equal; the loop would exit immediately. The outer loop must drive the walk; the equality check sits inside.
  • Advancing slow after fast. Not wrong, but makes the invariant harder to state. Standard order: slow one step, fast two steps, then compare.
  • Dereferencing fast->next without the null guard. Crashes on an acyclic list of even length when fast walks to the second-to-last node.
  • Single node with no self-loop. fast = head, fast->next = nullptr, loop never runs, return nullptr. Correct.
  • Single node with a self-loop (head->next == head). First iteration: slow = head, fast = head. They meet. Phase 2: a = head, b = slow = head, already equal, return head. Correct.
  • Empty list. head = nullptr, outer condition false, return nullptr. Correct.

8. How to say it in the interview (30 seconds)

"Phase 1 is Floyd's cycle detection: slow and fast start at the head; slow moves one step, fast two. If fast walks off the end, there's no cycle. If they meet, there is one. Phase 2 finds the cycle start: reset slow to the head and walk both pointers one step at a time. They collide at the entrance. The reason is a short distance identity: if L is the length to the cycle, C the cycle length, and k the distance within the cycle from start to the meeting point, then L + k = nC, so L = nC − k. Two walkers at speed 1, one starting at the head, one at the meeting point, meet after exactly L steps at the cycle start. O(n) time, O(1) space."
