Container With Most Water

LeetCode 11 · Medium · Pattern: shrinking-window two pointers · O(n) time, O(1) space

Problem. height[i] is the height of the i-th vertical line. Pick two lines so the rectangle they form with the x-axis holds the most water. Return that area. Water is min(height[l], height[r]) × (r - l).
[1,8,6,2,5,4,8,3,7] → 49    [1,1] → 1
Link: LeetCode

1. The one idea that solves it

Area has two factors: width (r - l) and limiting height min(h[l], h[r]). Start with the widest possible rectangle: l = 0, r = n - 1. The width can only shrink from here. So the only way to beat the current area is to find a taller limiting height, soon.

Here is the exchange argument. The shorter side is the limit. If you move the taller side inward, the width drops and the limit stays the same or drops (it can never exceed the shorter side). So that move cannot help. Move the shorter side inward: the width drops, but the limit might finally go up. That is the only move with a chance of beating the current area.

Idea. Start wide, keep two pointers l and r. Record min(h[l], h[r]) × (r - l). Then move whichever side is shorter one step inward. Stop when the pointers meet.

Why the discarded side can be dropped forever

Say h[l] < h[r]. For every r' < r, the rectangle (l, r') has smaller width and the same limiting side h[l] (since the limit is the min). So its area cannot exceed h[l] × (r - l), which we already recorded. Column l cannot be part of a better answer, so we retire it. The right pointer plays the symmetric role.

4. Code (C++)

class Solution {
public:
    int maxArea(vector<int>& height) {
        int l = 0, r = (int)height.size() - 1, best = 0;
        while (l < r) {
            int h = min(height[l], height[r]);
            best = max(best, h * (r - l));          // record before moving
            if (height[l] < height[r]) l++;         // move the shorter side
            else r--;
        }
        return best;
    }
};

Complexity: each pointer moves inward only, so at most n - 1 moves in total. O(n) time, O(1) space.

5. The part interviewers ask about: ties and "which side moves"

When height[l] == height[r], you can move either pointer. Both work. The reason: the discarded column has the same height as the surviving limit, so any inner rectangle paired with the discarded column has width strictly smaller and limit at most equal, which cannot beat the current area. The code above uses else r--, which moves r on ties. Interviewers often ask you to defend the tie rule out loud.

A sharper way to prune: when you move the shorter side, keep moving it while the next value is not taller than the one you just dropped. That extra skip is pure optimisation; the plain version is already O(n) and is what you should write first.

6. Traps and edge cases

  • Moving the taller side. That strictly reduces width and cannot raise the limit, so you can only match or lose. The algorithm then misses the answer.
  • Starting with the two tallest bars. Width matters. Tallest pair [8, 8] at indices 1 and 6 gives width 5, area 40. The real best in [1,8,6,2,5,4,8,3,7] uses indices 1 and 8 for area 49.
  • Area ≠ sum of heights. Only the shorter side holds water; water above the taller side spills.
  • Overflow. With LC bounds height[i] ≤ 104 and n ≤ 105, area ≤ 109, fits in int. For larger limits, use long long.
  • Two bars only. Loop runs once, returns min(h[0], h[1]). The empty / single-bar cases are not in the LC constraints (n ≥ 2), but the code handles them (loop runs 0 times, returns 0).

7. How to say it in the interview (30 seconds)

"Start with pointers at both ends. The width is maximal, so the only way to beat the current area is to find a taller limiting height. Record the current rectangle, then move the shorter side inward because the other move can only shrink the width while keeping the same limit. Each pointer walks at most n steps, so it is O(n) time and O(1) space. The shorter side is the one with a chance to grow."
