Course Schedule

LeetCode 207 · Medium · Pattern: topological sort (Kahn's BFS) over a directed graph, cycle detection · O(V + E) time, O(V + E) space

Problem. You have numCourses courses labelled 0 … numCourses - 1. Each prerequisites[i] = [a, b] means "you must take b before a", i.e. the directed edge b → a. Return true if you can finish all courses, false if the prerequisite graph has a cycle.
numCourses = 2, prerequisites = [[1,0]] → true
numCourses = 2, prerequisites = [[1,0],[0,1]] → false (cycle)
Link: LeetCode

1. The one idea that solves it

Model the courses as a directed graph: edge b → a for each [a, b]. "Can I finish all courses?" is "is this graph a DAG?" (no directed cycle). A DAG always has at least one vertex with in-degree 0, which is a course with no prerequisites. Take that course, erase it from the graph (which drops the in-degree of its successors by 1), and repeat. If you drain every course this way, there is no cycle; if you get stuck with courses still unresolved, those remaining ones form a cycle.

This is Kahn's algorithm. The queue holds "ready-to-take" courses, in-degree 0, and the loop pops one at a time. The count of courses that come out of the queue tells you the answer: taken == numCourses.

Idea. Build the directed graph with an in-degree array. Start by enqueuing every course whose in-degree is 0. Pop one, "take" it, and decrement each successor's in-degree; a successor hitting 0 goes into the queue. If every course is taken, no cycle; otherwise the leftover courses sit on a cycle.

2. Picture of the algorithm

Why does "all in-degrees stuck above 0" prove a cycle? Because a DAG has a topological order, and the first vertex in any topological order has in-degree 0. If no vertex has in-degree 0, the remaining subgraph is not a DAG, so by definition it contains a cycle. Kahn's is a constructive version of that proof.

4. Code (C++)

class Solution {
public:
    bool canFinish(int numCourses, vector<vector<int>>& prerequisites) {
        vector<vector<int>> adj(numCourses);
        vector<int> indeg(numCourses, 0);
        for (auto& p : prerequisites) {              // [a, b] means b -> a
            adj[p[1]].push_back(p[0]);
            indeg[p[0]]++;
        }
        queue<int> q;
        for (int i = 0; i < numCourses; i++)
            if (indeg[i] == 0) q.push(i);           // seed with no-prereq courses
        int taken = 0;
        while (!q.empty()) {
            int u = q.front(); q.pop();
            taken++;
            for (int v : adj[u])
                if (--indeg[v] == 0) q.push(v);
        }
        return taken == numCourses;
    }
};

Complexity. Building the graph is O(V + E). Each vertex enters the queue at most once, and each edge is traversed exactly once when its source is popped. Total O(V + E) time, O(V + E) space for the adjacency list, plus O(V) for the in-degree array and the queue.

Alternative: DFS with 3-colour cycle detection

vector<int> colour(numCourses, 0);          // 0 white, 1 grey (on stack), 2 black (done)
function<bool(int)> dfs = [&](int u) -> bool {
    colour[u] = 1;
    for (int v : adj[u]) {
        if (colour[v] == 1) return false;   // back-edge: cycle
        if (colour[v] == 0 && !dfs(v)) return false;
    }
    colour[u] = 2;
    return true;
};
for (int i = 0; i < numCourses; i++)
    if (colour[i] == 0 && !dfs(i)) return false;
return true;

Same complexity. The three colours make the cycle test precise: a grey neighbour (on the current DFS path) is a back-edge and proves a cycle; a black one (fully explored, no cycle found below it) is safe to skip. Prefer DFS when you also want the topological order for free (reverse post-order); prefer Kahn's when the question is just "is there a cycle?" and you want to explain the algorithm in one sentence.

5. The part interviewers ask about: direction of the edge

The input is [a, b] meaning "b is a prerequisite of a". The edge in a prerequisite graph points from the prerequisite to the dependent course: b → a. "I take b, so a's in-degree drops by one." Getting this backwards is the single most common bug; Kahn's still runs, but it answers a different question (whether every course has a successor, not whether every course can be reached).

Second question: why count rather than compare sets? Because a counter is a one-word mental model: "if I took every course, there was no cycle". A set comparison also works but is noisier. The equality taken == numCourses is the clean termination condition.

Third: what if the input has duplicate edges? [[1,0], [1,0]] inflates indeg[1] to 2, and the decrement path still works — course 0 fires both decrements and only then does course 1 become ready. Kahn's survives duplicates. Only a self-loop ([1,1]) is a problem: indeg[1] ≥ 1 forever, so course 1 is never taken, Kahn's correctly flags a cycle.

6. Traps and edge cases

  • Edge direction. [a, b] is b → a. Flipping it answers the wrong question.
  • No prerequisites. prerequisites = [], every indeg = 0, every course goes into the queue, taken == numCourses. Return true.
  • Self-loop. [1,1] means course 1 is its own prerequisite — a cycle of length 1. Kahn's handles this correctly: indeg[1] ≥ 1, never reaches 0.
  • Forgetting to seed every zero in-degree. If you start Kahn's from just one source, you can miss parallel components with their own zero in-degree starts, and conclude "cycle" when there is none.
  • DFS stack overflow. On numCourses = 2 × 105 arranged as a long chain, the recursive 3-colour DFS can overflow. Convert to an explicit stack or use Kahn.
  • Returning !taken. The predicate is taken == numCourses, not "any course taken". Easy to swap in a hurry.
  • Mutating the input prerequisites. Build your own adj and indeg; do not sort or dedup the parameter in place.

7. How to say it in the interview (30 seconds)

"Model it as a directed graph: edge from each prerequisite to the course that needs it. Compute every course's in-degree. Seed a queue with the zero-in-degree courses, and run Kahn's: pop one, bump a taken counter, decrement each successor's in-degree, enqueue the ones that just hit zero. At the end, if taken equals numCourses there is no cycle, so I can finish; otherwise the unseen courses sit on a cycle. O(V + E) time, O(V + E) space. I would mention the DFS alternative with the 3-colour scheme if they want the order itself."
