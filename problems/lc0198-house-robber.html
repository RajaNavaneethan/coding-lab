House Robber

LeetCode 198 · Medium · Pattern: 1-D DP (take or skip) · O(n) time, O(1) space

Problem. Each house has nums[i] money. You cannot rob two adjacent houses. Return the maximum total you can rob.
[1,2,3,1] → 4 (rob 1 and 3)    [2,7,9,3,1] → 12 (rob 2, 9 and 1)
Link: LeetCode

1. The one idea that solves it

At every house i you have exactly two choices:

  • Skip house i. The best so far is whatever dp[i−1] was.
  • Rob house i. You cannot have used i−1, so you take dp[i−2] + nums[i].

Pick the bigger of the two. That is the whole recurrence:

dp[i] = max(dp[i−1], dp[i−2] + nums[i])

dp[i] means "best money using houses 0..i, whether or not you rob house i". That definition is important: it absorbs both choices, so one scalar per index is enough.

Idea. Define dp[i] as the best possible so far up to and including i. At each house, the choice is "take this house's money and skip the previous" vs "skip this house and keep the previous best".

4. Code (C++)

class Solution {
public:
    int rob(vector<int>& nums) {
        int n = nums.size();
        if (n == 0) return 0;
        if (n == 1) return nums[0];
        vector<int> dp(n);
        dp[0] = nums[0];
        dp[1] = max(nums[0], nums[1]);
        for (int i = 2; i < n; i++)
            dp[i] = max(dp[i - 1], dp[i - 2] + nums[i]);
        return dp[n - 1];
    }
};

Complexity: one pass, one max per cell: O(n) time. O(n) space for the array.

Alternative: O(1) space, two rolling variables

int rob(vector<int>& nums) {
    int prev2 = 0, prev1 = 0;        // dp[i-2], dp[i-1]; sentinels before index 0
    for (int x : nums) {
        int cur = max(prev1, prev2 + x);
        prev2 = prev1;
        prev1 = cur;
    }
    return prev1;
}

Prefer this form. The two zero sentinels make the first two iterations handle themselves: at index 0, cur = max(0, 0 + nums[0]) = nums[0]; at index 1, cur = max(nums[0], 0 + nums[1]) = max(nums[0], nums[1]).

5. The part interviewers ask about: why the simple greedy fails

"Just alternate" (rob all even indices or all odd indices) fails on [2,1,1,2]: either strategy picks 3, but robbing houses 0 and 3 gives 4. "Rob the biggest remaining" fails on [2,7,9,3,1]: pick 9, then both neighbours are banned, and you miss that 2+9+1 = 12 beats 7+3 = 10.

Greedy fails because the decision at house i is not local: whether to rob depends on how good the best path through i−2 is, which depends on how good i−4 was, and so on. DP solves this by remembering, at every prefix, the best achievable total so far.

Correctness proof sketch: induction on i. Assume dp[0..i−1] are optimal for their prefixes. Any optimal solution for [0..i] either doesn't use i (so it's an optimal solution for [0..i−1], which is dp[i−1]) or it uses i (so the rest is an optimal solution for [0..i−2], which is dp[i−2], plus nums[i]). Taking the max of the two cases gives dp[i].

6. Traps and edge cases

  • Forgetting dp[1] = max(nums[0], nums[1]). If you set dp[1] = nums[1], you lose cases like [5, 1] whose answer is 5.
  • Signed overflow is not a worry on LeetCode constraints (n ≤ 100, nums[i] ≤ 400), but if the values were much larger you would need long long.
  • n = 0 or n = 1. Handle both explicitly, or start the rolling-variable version with prev2 = prev1 = 0, which gives the right answer for both.
  • LC 213 House Robber II (houses in a circle). Reusing this function directly is wrong because the first and last houses are now neighbours. Call rob twice, once on nums[0..n-2] and once on nums[1..n-1], then take the max.

7. How to say it in the interview (30 seconds)

"Define dp[i] as the maximum money using houses 0 through i. At each house I decide skip or rob. Skip keeps dp[i−1]. Rob takes nums[i] and adds dp[i−2], because I can't use the neighbour. The recurrence is dp[i] = max(dp[i−1], dp[i−2] + nums[i]), O(n) time. Because I only look back two cells I keep two scalars for O(1) space."
