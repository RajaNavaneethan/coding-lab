Median of Two Sorted Arrays

LeetCode 4 · Hard · Pattern: binary search on the partition · O(log min(m, n)) time, O(1) space

Problem. Two sorted arrays A (size m) and B (size n). Return the median of the combined array in O(log(m+n)).
A=[1,3], B=[2] → 2.0    A=[1,2], B=[3,4] → 2.5
Link: LeetCode

1. The one idea that solves it

Imagine the merged sorted array of length m + n. The median splits it into a left half of size (m + n + 1) / 2 and a right half of size (m + n) / 2. The median is a function of the four values that straddle the cut: the two largest on the left and the two smallest on the right.

You do not have to actually merge the arrays. You only need to decide how many of the left-half values come from A (call it i, between 0 and m). Once i is fixed, j = half - i is forced. The four boundary values are:

  • Al = A[i-1] (or −∞ if i == 0)
  • Ar = A[i] (or +∞ if i == m)
  • Bl = B[j-1] (or −∞ if j == 0)
  • Br = B[j] (or +∞ if j == n)

The partition is valid when the left side contains only values ≤ the right side. Since A is sorted Al ≤ Ar automatically, and the same for B. The only two things to check are cross conditions:

Al ≤ Br   and   Bl ≤ Ar

Binary search on i. If Al > Br, we took too many from A, go left (hi = i - 1). If Bl > Ar, too few, go right (lo = i + 1). When both hold, read off the median: odd total → max(Al, Bl), even total → (max(Al, Bl) + min(Ar, Br)) / 2.

Idea. Binary-search the number of A's elements that belong to the left half of the merged array. The partition is valid when the two cross conditions Al ≤ Br and Bl ≤ Ar both hold. Then the median is a function of the four boundary values.

Why we search over the smaller array

Swap A and B at the top so m ≤ n. The range of i is [0, m], so the search runs in O(log(min(m, n))). Also, j = half - i stays non-negative because half ≥ m when m ≤ n.

4. Code (C++)

class Solution {
public:
    double findMedianSortedArrays(vector<int>& A, vector<int>& B) {
        if (A.size() > B.size()) return findMedianSortedArrays(B, A);
        int m = A.size(), n = B.size();
        int half = (m + n + 1) / 2;        // size of the left half
        int lo = 0, hi = m;
        while (lo <= hi) {
            int i = lo + (hi - lo) / 2;        // take i from A
            int j = half - i;                   // take j from B
            int Al = (i == 0) ? INT_MIN : A[i - 1];
            int Ar = (i == m) ? INT_MAX : A[i];
            int Bl = (j == 0) ? INT_MIN : B[j - 1];
            int Br = (j == n) ? INT_MAX : B[j];
            if (Al <= Br && Bl <= Ar) {
                if ((m + n) % 2) return (double)max(Al, Bl);
                return (max(Al, Bl) + min(Ar, Br)) / 2.0;
            } else if (Al > Br) hi = i - 1;    // too many from A
            else                   lo = i + 1;    // too few from A
        }
        return 0.0;                             // unreachable for valid input
    }
};

Complexity: i lives in [0, m] with m ≤ n, so O(log min(m, n)) time, O(1) space.

5. The part interviewers ask about: why the cross conditions are enough

Inside A, A[i-1] ≤ A[i] is automatic because A is sorted, so Al ≤ Ar for free. Same for B: Bl ≤ Br. For the merged left half to be entirely ≤ the merged right half we only need to check the two cross pairs: the top of A's left vs the bottom of B's right, and vice versa. The sentinels ±∞ make the first-pair and last-pair cases fall out with no special code.

Why half uses (m + n + 1) / 2 (ceiling). We want the left half to contain the median candidate for the odd case. With an odd total, ceiling puts one extra element on the left so max(Al, Bl) is the median. With an even total, (m + n + 1) / 2 == (m + n) / 2, so both halves have the same size and the median is the average of the two straddlers.

Which pointer to move. Al > Br means an A-value on the left is bigger than a B-value on the right, so A is contributing too many to the left: move i down. Bl > Ar is the mirror: move i up.

6. Traps and edge cases

  • Forgetting the swap. Searching the larger array still returns the right answer but can give j < 0 when m > n. Keep the m ≤ n precondition.
  • Using INT_MIN / INT_MAX in arithmetic. Fine for comparisons, but do not add them. The (max + min) line only runs after the valid-partition check, so overflow cannot bite.
  • Empty array. A = [], B = [1,2,3,4]: m = 0, loop runs with i = 0 once, Al = INT_MIN, Ar = INT_MAX, cross conditions hold immediately, median is (B[1] + B[2]) / 2 = 2.5.
  • All of one array below (or above) the other. A = [1,2,3], B = [10,20,30]: ends with i = m or i = 0, sentinels do the rest.
  • Returning int. Signature returns double. Dividing by 2 (not 2.0) truncates on even length.
  • Linear-time merge in interview. Easy to write but violates the required O(log(m+n)). Interviewers will nudge you to the partition.

7. How to say it in the interview (30 seconds)

"I binary-search how many elements of the smaller array go into the left half of the merged array. Once that count i is picked, j in the other array is forced by the left-half size (m+n+1)/2. I look at the four boundary values and check two cross conditions, Al ≤ Br and Bl ≤ Ar. Too many from A → move left, too few → move right. On a valid partition the median is max(Al, Bl) if the total is odd, or the average of max(Al, Bl) and min(Ar, Br) if even. O(log min(m, n))."
