Task Scheduler

LeetCode 621 · Medium · Pattern: build the frame around the most-frequent task · O(n) time, O(1) space

Problem. You have tasks (letters) and a cool-down n: the same letter must be at least n slots apart. Each slot takes 1 unit. You can insert idle slots. Return the minimum total slots.
tasks=["A","A","A","B","B","B"], n=2 → 8 ("A B _ A B _ A B")
tasks=["A","C","A","B","D","B"], n=1 → 6 (no idles needed)
Link: LeetCode

1. The one idea that solves it

The task with the highest frequency drives the schedule. Call its count maxFreq. Place that task every n + 1 slots: that uses it up without ever breaking the cool-down. This builds a frame:

  • maxFreq − 1 gap-blocks, each of width n + 1, each starting with the top task.
  • Plus one final column containing the top task and every other task that is also tied at maxFreq.
frame length = (maxFreq − 1) × (n + 1) + countMax

countMax is the number of distinct tasks whose frequency equals maxFreq. The frame is a lower bound: you cannot do better because the top task alone needs that much space, and the final column holds the other tasks tied with it.

What about the non-max tasks? They go into the maxFreq − 1 frame rows, filling the gap positions. If they do not fit, you simply have more tasks than idle slots, and the answer is just tasks.size() — you can lay all tasks out without any idle gap. So:

Idea. Answer = max(tasks.size(), (maxFreq − 1) × (n + 1) + countMax). The frame counts the forced idle time; tasks.size() is the floor when there is no forced idling.

Why the greedy choice is safe

Two directions:

Lower bound. The most-frequent task has maxFreq copies that each demand a cool-down gap of n. Between the first and the last there must be at least (maxFreq − 1) × (n + 1) slots, and if countMax other tasks are tied at maxFreq, their final copies land in the last column alongside the top task's final copy, extending the lower bound to (maxFreq − 1) × (n + 1) + countMax. No valid schedule can be shorter.

Upper bound (construction). Fill the maxFreq − 1 frame rows row-by-row. Place the top task in column 0 of every row. For each other task (sorted by remaining frequency), spread its copies into one column at a time, starting in column 1. Because any single task has ≤ maxFreq copies, it never needs more than one slot per row — so no two copies of the same task land in the same row, keeping the cool-down. If the frame is too small to hold every task, extend by appending the overflow after column 0 of the final column — the schedule stretches to tasks.size(), with zero idles. Either way, we match the lower bound (or the no-idle floor), so the answer is tight.

4. Code (C++)

class Solution {
public:
    int leastInterval(vector<char>& tasks, int n) {
        int freq[26] = {0};
        for (char c : tasks) freq[c - 'A']++;
        int maxFreq = *max_element(freq, freq + 26);
        int countMax = 0;
        for (int f : freq) if (f == maxFreq) countMax++;
        int frame = (maxFreq - 1) * (n + 1) + countMax;
        return max((int)tasks.size(), frame);
    }
};

Complexity: one pass to count, one pass over 26 letters. O(k) where k is tasks.size(), plus O(26) work. O(1) space.

Alternative: priority queue simulation

int leastInterval(vector<char>& tasks, int n) {
    int freq[26] = {0}; for (char c : tasks) freq[c - 'A']++;
    priority_queue<int> pq;
    for (int f : freq) if (f) pq.push(f);
    int time = 0;
    while (!pq.empty()) {
        vector<int> tmp;
        for (int i = 0; i <= n; i++) {
            if (!pq.empty()) { tmp.push_back(pq.top() - 1); pq.pop(); }
            time++;
            if (pq.empty() && all_of(tmp.begin(), tmp.end(), [](int x){ return x == 0; })) break;
        }
        for (int x : tmp) if (x) pq.push(x);
    }
    return time;
}

Simulates each block of n + 1 slots by taking the n + 1 most-frequent remaining tasks. Correct, but O((k)(n + 1) log 26). The math-only formula is faster and sharper for interviews.

5. The part interviewers ask about: proof that both bounds meet

Interviewers love this problem because the formula looks like a trick. The two things that must be checked:

Why tasks.size() is the right alternative. If the frame has maxFreq − 1 gap rows of n + 1 slots each, the non-max tasks occupy up to (maxFreq − 1) × n gap slots. If the total count of non-max tasks is more than that, the remaining tasks spill past the frame — and once they do, every one of them extends the schedule by 1 with no idle required (the cool-down is already satisfied because the frame placed cooled tasks far enough back). So the total length becomes exactly tasks.size().

Formally: let k = tasks.size, M = maxFreq, c = countMax. The frame has M - 1 gap slots after the top-task column, times n, plus M + (c - 1) slots filled by top-tier tasks. Non-top-tier count is k - c · M (not quite; it's k - (number of top-tier task copies)); see below).

Easier way to see it: the formula is monotone in each parameter, and both extremes agree:

  • All one letter. k = M, c = 1: frame = (M - 1)(n + 1) + 1. Correct.
  • Many letters, small n. frame can be ≤ k; answer is k, no idle. Correct.
  • Few letters, big n. frame >> k; answer is frame, lots of idles. Correct.

6. Traps and edge cases

  • Multiplying by n instead of n + 1. The frame slot includes the top task itself, so each row is n + 1 wide, not n.
  • Forgetting countMax. If two tasks tie at maxFreq, their final copies share the last column. Dropping countMax gives the wrong answer for inputs like ["A","A","B","B"], n = 2 (correct is 5; wrong formula gives 4).
  • Returning frame without the max with tasks.size(). Fails when there is no forced idle, e.g. ["A","C","A","B","D","B"], n = 1 → 6 (not 4).
  • Assuming only uppercase letters. LeetCode guarantees uppercase A–Z; the freq[26] array uses that. Make sure the input is normalised.
  • n = 0. No cool-down. Answer is just tasks.size(); the formula agrees: frame = (M - 1) + c ≤ k.

7. How to say it in the interview (30 seconds)

"I count task frequencies. Let M be the max and c be the number of tasks tied at that max. The most-frequent task alone forces a frame of (M - 1) blocks of width (n + 1), and the final column holds the c tasks tied with it. That gives (M - 1)(n + 1) + c. If I have more tasks than that frame can hold, no idling is needed and the length is just tasks.size(). The answer is the max of the two. O(k) time, O(1) space."
