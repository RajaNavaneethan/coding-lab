Lowest Common Ancestor of a Binary Tree

LeetCode 236 · Medium · Pattern: post-order DFS returning a witness · O(n) time, O(h) space

Problem. Given the root of a binary tree and two nodes p and q, return their lowest common ancestor — the deepest node that has both of them in its subtree. Each node is also an ancestor of itself.
root = [3,5,1,6,2,0,8,null,null,7,4]    p=5, q=1 → 3    p=5, q=4 → 5
Link: LeetCode

1. The one idea that solves it

At each node, ask one question: "did I find p or q in my left subtree? in my right subtree?" If both answers are yes, I am the LCA. If only one side is yes, hand that side up to my parent. If neither side has anything, hand up null.

Two base cases make this work without extra state. A null node returns null. A node that is p or q returns itself — it is its own witness. So the return value of each call is a single pointer that means: "the first p-or-q I found in my subtree, or the LCA if I found both."

Idea. Recurse into both children. If both come back non-null, this node has p on one side and q on the other, so it is the LCA. Otherwise, pass up whichever side was non-null (or null if neither).

4. Code (C++)

TreeNode* lowestCommonAncestor(TreeNode* root, TreeNode* p, TreeNode* q) {
    if (!root || root == p || root == q) return root;
    TreeNode* L = lowestCommonAncestor(root->left,  p, q);
    TreeNode* R = lowestCommonAncestor(root->right, p, q);
    if (L && R) return root;                 // split: this node is the LCA
    return L ? L : R;                        // one side has both, or neither
}

Complexity: every node is visited once, O(n) time. Recursion depth is the tree height, O(h) stack.

Alternative: parent map + ancestor set

// Walk the tree once to record each node's parent.
unordered_map<TreeNode*, TreeNode*> parent;
// Then walk p's ancestors into a set, and walk q's ancestors until we hit the set.

Also O(n) time but needs O(n) space for the map. Reach for it when the tree has parent pointers already, or when you have many queries on the same tree and can preprocess (binary lifting is the usual next step then).

5. The part interviewers ask about: why one-sided returns are safe

When only one side is non-null, that pointer might be p, q, or the LCA from deeper down. The code doesn't need to distinguish: it just passes it up. The guarantee is that if p and q are both in the tree, the deepest ancestor that sees both of them in its own two subtrees is where the two one-sided returns finally meet — and that node is the one that returns root instead of L or R. Above it, the recursion keeps bubbling the LCA pointer up untouched.

What about "p is an ancestor of q"? The call at p sees itself first and returns p on the spot without exploring further. That return propagates up, and no higher node sees two non-null children, so the final answer is p. This is why the first check also handles the "same node" case for free.

6. Traps and edge cases

  • Comparing by value instead of by pointer. LC 236 nodes have unique values on paper, but the signature takes pointers. Compare pointers (root == p) so you don't double-match on a value collision in other variants.
  • Keeping walking after finding p or q. The first line returns immediately. Don't recurse into children when the current node is already a match.
  • Separate found-flags for p and q. Not needed. The null / non-null return value carries all the signal you need.
  • Edge: p is the root. Returned on the first line, no recursion needed. LCA = root.
  • Edge: p == q. The problem usually guarantees distinct, but the code still works: it returns p (= q) the first time it meets that pointer.
  • Edge: a BST. You can do it in O(h) time by comparing p/q to root->val and descending the one side that could contain both. That is LC 235, a cheaper variant for sorted trees.

7. How to say it in the interview (30 seconds)

"I do a post-order DFS. Each call returns the first p-or-q it finds in its subtree. The base cases are null and 'this node is p or q, return self'. If both child calls come back non-null, the two targets are on different sides, so the current node is the LCA. Otherwise I pass up whichever side was non-null. One pass, O(n) time, O(h) stack."
