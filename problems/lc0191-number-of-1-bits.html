Number of 1 Bits

LeetCode 191 · Easy · Pattern: Brian Kernighan's bit trick · O(k) time where k = popcount(n), O(1) space

Problem. Given a 32-bit unsigned integer n, return the number of 1 bits it has (also called the Hamming weight).
n = 00000000000000000000000000001011 → 3    n = 10000000 → 1    n = 11111111111111111111111111111101 → 31
Link: LeetCode

1. The one idea that solves it

The trick: n & (n − 1) clears the lowest set bit of n, and only that bit.

Here is why. Let the lowest set bit be at position p. Then n ends with 1 followed by p zeros. Subtracting one flips that 1 to 0 and flips all p trailing zeros to ones (classic borrow). ANDing the two keeps the bits above p unchanged, zeros the bit at p (now 1 & 0), and zeros the bits below p (now 0 & 1). Net effect: one bit disappeared.

So each time you do n = n & (n − 1) you remove exactly one 1. Count how many times you can do it before n becomes 0. That count is the answer.

Idea. n & (n − 1) peels off the lowest set bit. Loop until n = 0, counting the peels. The loop runs exactly popcount(n) times, not 32.

2. Picture of the algorithm

A naive version checks all 32 bits with n & 1 then n >>= 1. That is O(32) always. Brian Kernighan's version is O(popcount), which is faster when there are only a few set bits (common on real data).

4. Code (C++)

class Solution {
public:
    int hammingWeight(uint32_t n) {
        int count = 0;
        while (n) {
            n &= n - 1;        // clear the lowest set bit
            count++;
        }
        return count;
    }
};

Complexity: the loop runs once per set bit, so O(popcount(n)) time, at most 32. O(1) space.

Alternative: shift-and-check

int hammingWeight(uint32_t n) {
    int count = 0;
    while (n) {
        count += n & 1;
        n >>= 1;
    }
    return count;
}

Simple and fine on uint32_t. Use the Kernighan form when you want to show you know it, or when the input is sparse and you want fewer iterations. If the interviewer allows it, mention that modern CPUs have a dedicated instruction (__builtin_popcount / POPCNT) that does this in one cycle.

5. The part interviewers ask about: the follow-up on many calls

"What if this function is called many times?" The question is pointing at a lookup table. Pre-compute popcount for every 8-bit byte (256 entries) once. Then for a 32-bit input, split it into four bytes, sum the four table lookups. Each call becomes four array reads and three adds — constant time, no loop.

Trade memory for time once (256 bytes of table). Every subsequent call pays four cached loads instead of up to 32 loop iterations.

Another natural follow-up: "Why unsigned?" Right-shifting a negative signed value in C++ is implementation-defined before C++20 and often "arithmetic" (sign extended), so the loop could spin forever on a negative input. uint32_t fills the top with zeros, which is what the algorithm needs.

6. Traps and edge cases

  • Signed int and right shift. n >>= 1 on a signed negative value may keep the sign bit, so the loop never terminates. Use uint32_t as the problem specifies.
  • n = 0. The loop body never runs. Count is 0. The while condition handles this for free.
  • n = 0xFFFFFFFF. Count is 32. The loop runs 32 times. Signed types would overflow during n − 1 if you treated them as signed, but on uint32_t this is defined wrap-around and the AND still works.
  • Writing n & n − 1 without parentheses. & has lower precedence than − in C++, so this one parses correctly — but it is still easier to read as n & (n − 1). The dangerous one is n &= n - 1; that is fine too, but adding parentheses is a cheap habit.
  • Thinking the loop is always O(32). It is O(popcount). A number with 3 set bits loops 3 times, not 32.

7. How to say it in the interview (30 seconds)

"I use n & (n − 1). Subtracting one flips the lowest set bit to 0 and the zeros below it to 1s. ANDing with the original zeroes that lowest set bit and the trailing region. So each operation removes exactly one 1. I loop while n is non-zero and count. That runs popcount(n) times, at most 32. If the function is hit a lot, I would precompute an 8-bit popcount table and do four lookups per 32-bit value."
