Build a Matrix With Conditions

LeetCode 2392 · Hard · Pattern: two independent topological sorts (Kahn), one for rows and one for columns · O(k + |rowC| + |colC|) time, O(k) space

Problem. Build a k × k matrix containing numbers 1..k once each (the rest are 0) such that:
  • Every [u, v] in rowConditions means number u is in a strictly earlier row than v.
  • Every [u, v] in colConditions means number u is in a strictly earlier column than v.
If no such matrix exists, return [].
k=3, row=[[1,2],[3,2]], col=[[2,1],[3,2]] → e.g. [[3,0,0],[0,0,1],[0,2,0]]
k=3, row=[[1,2],[2,3],[3,1],[2,3]], col=[[2,1]] → [] (cycle in rows)
Link: LeetCode

1. The one idea that solves it

Rows and columns are independent. The condition u is in an earlier row than v says nothing about their columns, and vice versa. So the "where in the grid" question for number v splits into two 1-D placement problems: give it a row index and a column index, drawn from two independent constraints.

Each constraint set is just a topological sort. rowConditions is a DAG on numbers 1..k: an edge u → v means u must come before v. Any topological order of this DAG is a valid row ordering of all k numbers: position in the order = row index. Same thing for columns.

If either DAG has a cycle, no row/column ordering exists → return []. Otherwise build two mappings rowPos[v] and colPos[v], then write M[rowPos[v]][colPos[v]] = v for each v. Everything else stays 0.

Idea. Treat row and column constraints as two separate directed graphs on {1..k}. Run Kahn's topological sort on each. The i-th number in the row order goes to row i; same for columns. A cycle in either DAG means no matrix exists.

2. Picture of the algorithm

Why "independent" is the whole observation: once you know the row order and the column order, each number v has exactly one legal grid position. You never have to backtrack. The problem seems 2-D but the constraints never couple the axes, so it decomposes into two 1-D problems that can be solved in any order.

4. Code (C++)

class Solution {
    vector<int> topo(int k, vector<vector<int>>& cond) {
        vector<vector<int>> adj(k + 1);
        vector<int> indeg(k + 1, 0);
        for (auto& c : cond) {
            adj[c[0]].push_back(c[1]);
            indeg[c[1]]++;
        }
        queue<int> q;
        for (int i = 1; i <= k; i++) if (indeg[i] == 0) q.push(i);
        vector<int> order;
        while (!q.empty()) {
            int u = q.front(); q.pop();
            order.push_back(u);
            for (int v : adj[u]) if (--indeg[v] == 0) q.push(v);
        }
        return (int)order.size() == k ? order : vector<int>{};
    }
public:
    vector<vector<int>> buildMatrix(int k,
            vector<vector<int>>& rowConditions,
            vector<vector<int>>& colConditions) {
        auto rowOrder = topo(k, rowConditions);
        auto colOrder = topo(k, colConditions);
        if (rowOrder.empty() || colOrder.empty()) return {};

        vector<int> rowPos(k + 1), colPos(k + 1);
        for (int i = 0; i < k; i++) {
            rowPos[rowOrder[i]] = i;
            colPos[colOrder[i]] = i;
        }
        vector<vector<int>> M(k, vector<int>(k, 0));
        for (int v = 1; v <= k; v++) M[rowPos[v]][colPos[v]] = v;
        return M;
    }
};

Complexity. Each Kahn run is O(k + |cond|). Writing the matrix is O(k) plus O(k2) for the zero initialisation. Total time O(k2 + |rowC| + |colC|), dominated by the matrix allocation. Space O(k2) for the output and O(k + |cond|) for each adjacency structure.

Alternative: DFS with 3-colouring for cycle detection

bool dfs(int u, vector<int>& color, ...) {
    color[u] = 1;
    for (int v : adj[u]) {
        if (color[v] == 1) return false;    // cycle
        if (color[v] == 0 && !dfs(v, ...)) return false;
    }
    color[u] = 2; order.push_back(u); return true;
}

Reverse order at the end. Same complexity. Kahn's is easier to defend in an interview because the "zero in-degree pop" has a straight physical reading. DFS wins when you also need the finish-time order (not needed here).

5. The part interviewers ask about: why can we treat rows and columns independently?

Each constraint is one-dimensional. A row constraint only talks about row indices. A column constraint only talks about column indices. The two sets never share a vertex of information: no clause says "if u is to the left of v then u is also above v". Independent constraints decompose into independent sub-problems; nothing couples them except that the same number v is placed in both axes.

Second question: any valid row order works. The problem allows any matrix consistent with the constraints, so once we have one topological order on each axis, we don't need to search for a specific layout. Any Kahn tie-break is fine; Kahn's queue is unordered among same-in-degree vertices and that freedom is OK.

Third: what about shared numbers? All numbers 1..k appear in the matrix exactly once. Topological sort on 1..k places each number in a unique row and a unique column. The two k × k positions, (rowPos[v], colPos[v]), are therefore all distinct across v, so no two numbers collide on a cell.

Fourth: the problem is often framed with n × n; here it's always k × k. Setting the matrix size to k gives us exactly enough room: k numbers, k rows, k columns, and k occupied cells on the diagonal pattern we assign.

6. Traps and edge cases

  • Running one Kahn and reusing the order for both axes. Rows and columns have different constraints — this breaks column requirements. Two independent sorts.
  • Dropping the empty-order check. A cycle in either axis means no valid matrix. Return [] immediately; don't try to patch around it.
  • Off-by-one in indeg[c[1]]. Numbers are 1-indexed. Allocate k + 1 slots.
  • Trying to minimise the "zeros" or make the matrix compact. The problem doesn't ask for that. Any valid layout is accepted.
  • Duplicate conditions. [[1,2],[1,2]] inflates indeg[2] by 2. Kahn still works — after processing 1 twice via two edges, 2's in-degree reaches 0. If you dedupe edges, the queue reads cleaner.
  • Self-loop. [[v, v]] is a cycle of length 1 and must return [] on that axis. Kahn handles it: v never has in-degree 0 and is never popped.
  • Isolated numbers. A number that appears in no condition has in-degree 0 and is enqueued immediately, placed in some row position by Kahn's tie-break. That's correct: unconstrained numbers can go anywhere.

7. How to say it in the interview (30 seconds)

"Rows and columns are independent. I treat each condition list as a DAG over the numbers 1..k and run Kahn's topological sort on each. The i-th number in the row order goes to row i; same thing for the column order. Then I write M[rowPos[v]][colPos[v]] = v for every v; all other cells are zero. If either DAG has a cycle (Kahn can't drain the queue), I return []. Linear in k plus the number of conditions."
