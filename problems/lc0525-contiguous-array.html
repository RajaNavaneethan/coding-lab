Contiguous Array

LeetCode 525 · Medium · Pattern: prefix sum + first-index hash map · O(n) time, O(n) space

Problem. Given a binary array nums, return the length of the longest contiguous subarray with an equal number of 0s and 1s.
[0,1] → 2   [0,1,0] → 2   [0,0,1,0,0,0,1,1] → 6   Link: LeetCode

1. The one idea that solves it

Count each 1 as +1 and each 0 as −1. Now "equal 0s and 1s" means "the subarray sums to 0".

Keep a running total called the balance. If the balance is the same at two positions, everything between them added up to zero, so that stretch is balanced. The longest balanced stretch ending here starts right after the first time we saw this balance.

Idea. Map 0 to −1 and track the balance. Store the first index where each balance appears, seeded with {0: -1}. When the balance repeats at index i, the subarray (first[bal], i] is balanced and has length i − first[bal].

4. Code (C++)

int findMaxLength(vector<int>& nums) {
    unordered_map<int, int> first{{0, -1}};   // balance 0 seen "before index 0"
    int bal = 0, best = 0;
    for (int i = 0; i < (int)nums.size(); i++) {
        bal += nums[i] == 1 ? 1 : -1;
        auto it = first.find(bal);
        if (it != first.end()) best = max(best, i - it->second);
        else first[bal] = i;                        // keep only the earliest index
    }
    return best;
}

Complexity: one pass with O(1) average map work per element, so O(n) time. The balance ranges from −n to n, so the map holds at most 2n+1 entries: O(n) space. You can replace the map with a vector<int>(2*n+1, -2) indexed by bal + n for a faster constant.

5. The part interviewers ask about: why the first index?

We want the longest subarray, so for a given end i we want the cut as far left as possible. The earliest index with the same balance gives the widest span. If you overwrite the map entry every time the balance repeats, you keep the latest index and measure the shortest balanced stretch instead. That still passes [0,1], which is why the bug is easy to miss. On [0,1,0,1] it returns 2 instead of 4.

Compare with LC 560: there we want how many subarrays, so we store a count per prefix. Here we want how long, so we store the first index. Same skeleton, different payload in the map.

6. Traps and edge cases

  • Forgetting the seed {0: -1}. Balanced prefixes that start at index 0 are missed. [0,1] returns 0.
  • Seeding with {0: 0}. Off by one: every length from the start is one too short.
  • Overwriting the stored index. Gives the shortest, not the longest. [0,1,0,1] → 4, not 2.
  • Counting with +1 / +0. Zeros must subtract, otherwise "sum 0" has no meaning.
  • Edge inputs. [0,0,0] → 0; [1] → 0; [0,0,1,0,0,0,1,1] → 6.

7. How to say it in the interview (30 seconds)

"I treat 1 as plus one and 0 as minus one, so equal counts means the subarray sums to zero. I keep a running balance and a map from balance to the first index it appeared, seeded with zero at index minus one. When the balance repeats, the part between the two positions is balanced, and using the first index gives the longest one. One pass, O(n) time and space."
