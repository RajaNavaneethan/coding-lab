Jump Game

LeetCode 55 · Medium · Pattern: greedy, farthest-reach · O(n) time, O(1) space

Problem. You stand at index 0 of nums. From index i you can jump any distance from 0 to nums[i]. Return true if you can reach the last index.
[2,3,1,1,4] → true    [3,2,1,0,4] → false
Link: LeetCode

1. The one idea that solves it

Do not pick a jump length at each step. Instead track one number: the farthest index you can reach so far. Call it reach. Walk left to right. At index i ask one question: is i ≤ reach? If no, you are stuck. If yes, update reach = max(reach, i + nums[i]) and keep going.

You never commit to a specific jump. You keep the frontier of what is reachable and push it as far right as the current cell allows. The last index is reachable the moment reach catches up to it.

Idea. Walk the array once with a single scalar reach. Any index i with i ≤ reach is reachable, and from it the frontier can grow to i + nums[i]. Return true when reach reaches the last index.

Why the greedy choice is safe

At index i we extend reach to max(reach, i + nums[i]). We never ask "should I jump less here so I can jump more later?". The reason is a simple exchange argument:

Suppose some solution reaches the end using a shorter jump at i, landing at some j ≤ i + nums[i]. Any index you can visit from j is also an index ≤ j + nums[j], and both j and j + nums[j] are ≤ i + nums[i]'s own frontier only after further hops. The frontier never gets smaller by expanding it earlier. So replacing a short jump with "treat every cell up to i + nums[i] as reachable" cannot miss any index the short-jump solution reaches. In one word: a larger frontier dominates a smaller one.

4. Code (C++)

class Solution {
public:
    bool canJump(vector<int>& nums) {
        int reach = 0, n = nums.size();
        for (int i = 0; i < n; i++) {
            if (i > reach) return false;        // cannot step onto i
            reach = max(reach, i + nums[i]);     // extend frontier
            if (reach >= n - 1) return true;    // early exit
        }
        return true;
    }
};

Complexity: one left-to-right pass, one max per index: O(n) time. One scalar: O(1) space.

Alternative: scan right to left

bool canJump(vector<int>& nums) {
    int goal = nums.size() - 1;
    for (int i = goal - 1; i >= 0; i--)
        if (i + nums[i] >= goal) goal = i;
    return goal == 0;
}

Equivalent idea viewed from the other side: shrink the goal post. If some earlier index can reach the current goal, make it the new goal. The whole array is passable iff the goal shrinks down to 0.

5. The part interviewers ask about: why not DP?

You can mark each index as reachable with DP: reach[i] = any j < i reachable with j + nums[j] ≥ i. That is O(n2) in the worst case (every index checks every earlier index).

The greedy pass does the same work in O(n) because you only need the maximum frontier so far, not the full set of reachable indices. If some index is reachable, every index up to the current reach is reachable, so compressing them all into one scalar loses nothing.

Proof the greedy answer equals the DP answer: by induction on i, after processing index i the value of reach equals the largest index DP would mark reachable among [0..i]'s descendants. Base: at i = 0, reach = nums[0], same as DP. Step: at i, if i ≤ reach then by inductive hypothesis DP marks i reachable, so DP's new frontier is max(prev, i + nums[i]), exactly what the greedy sets.

6. Traps and edge cases

  • Index 0 is always "visitable". You start there. Even nums = [0] returns true (last index already).
  • Zero on a non-last index is only fatal if reach cannot pass it. [2,0,0] is true: index 0 pushes reach to 2 before the zeros matter.
  • Do not confuse this with Jump Game II. This one is yes/no. II asks for the minimum number of jumps.
  • Early exit matters. Without if (reach >= n - 1) return true you still get the right answer, but you waste a scan past the goal. Interviewers notice.
  • n = 1. Return true. The code handles it: loop runs once, hits the early return (or exits).

7. How to say it in the interview (30 seconds)

"I keep one number, reach, the farthest index I can get to. I walk the array left to right. If the current index is past reach, I am stuck and return false. Otherwise I update reach to max(reach, i + nums[i]) and continue. If reach ever covers the last index, I return true. The greedy is safe because a larger frontier is always at least as useful as a smaller one, so I never regret extending it. O(n) time, O(1) space."
