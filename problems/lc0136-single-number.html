Single Number

LeetCode 136 · Easy · Pattern: XOR cancellation · O(n) time, O(1) space

Problem. Every element in nums appears exactly twice except one, which appears once. Find and return that one. Must run in linear time and use constant extra space.
[2,2,1] → 1    [4,1,2,1,2] → 4    [1] → 1
Link: LeetCode

1. The one idea that solves it

XOR has three properties that fit this problem exactly:

  • x ^ x = 0 — a value XORed with itself cancels.
  • x ^ 0 = x — zero is the identity.
  • XOR is commutative and associative — order does not matter.

So if you XOR every element of the array together, every value that appears twice cancels to zero. The lonely value XORs with 0 and survives. One accumulator, one pass.

answer = nums[0] ^ nums[1] ^ … ^ nums[n−1]
Idea. Fold all numbers with XOR. Duplicates pair up and vanish; whatever is left is the one that did not have a partner.

2. Picture of the algorithm

No sorting, no hash set. Just one integer that accumulates the running XOR.

4. Code (C++)

class Solution {
public:
    int singleNumber(vector<int>& nums) {
        int x = 0;
        for (int n : nums) x ^= n;
        return x;
    }
};

Complexity: one pass, one XOR per element: O(n) time. One accumulator: O(1) extra space.

5. The part interviewers ask about: why XOR, not sum or hash

Three constraints push you toward XOR:

  • O(1) extra space. A hash set is O(n). Sorting with nth_element is O(1) extra but destroys the input and is O(n) in a different way; the interviewer wants no auxiliary data structure at all.
  • Pairs cancel cleanly only in a group where x + x = 0. With plain integer addition, duplicates don't cancel — they double. You could compute 2 · sum(set) − sum(nums), but that needs the set in the first place, so you have not saved space.
  • XOR is addition in GF(2), bitwise. Every bit is independent, and in each bit "two of the same" sums to zero. That is exactly the structure of the problem.

If you ever see "every element appears k times except one that appears m times", XOR alone is not enough: XOR only cancels pairs. Use bitwise counts mod k instead (LC 137 is this problem with k = 3). Still constant space, but you count each bit position mod k and reconstruct the odd one.

6. Traps and edge cases

  • Starting the accumulator at anything other than 0. x = nums[0] works but then you must start the loop at index 1. Starting at x = 0 is cleaner and uses the identity law.
  • Using sum() accidentally. Addition does not cancel duplicates. You need XOR (^), not +.
  • Negative numbers. C++ XOR of signed int works bit for bit on the two's-complement representation, which is what you want. -1 ^ -1 = 0. No special handling needed.
  • Array of one element. The loop runs once: 0 ^ nums[0] = nums[0]. Correct.
  • "Every number appears three times except one" (LC 137). XOR alone fails: three XORs leave the value, not zero. Switch to a per-bit mod 3 counter.

7. How to say it in the interview (30 seconds)

"XOR is associative and commutative, and x ^ x = 0. If I XOR every element together, every value that appears twice cancels, and the odd one out survives. One pass, one int accumulator, O(n) time and O(1) space. Works for negatives because XOR acts on the bit pattern. The trick does not generalise if a value appears three times — there I would count each bit mod 3 instead."
