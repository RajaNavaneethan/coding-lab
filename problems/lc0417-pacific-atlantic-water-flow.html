Pacific Atlantic Water Flow

LeetCode 417 · Medium · Pattern: reverse multi-source BFS from each border, intersect the two reach sets · O(R · C) time, O(R · C) space

Problem. You are given an R × C grid of heights. The Pacific borders the top and left edges; the Atlantic borders the bottom and right edges. Water on a cell flows to a 4-neighbour whose height is less than or equal to this cell's height. Return every cell from which water can reach both oceans.
heights = [[1,2,2,3,5],[3,2,3,4,4],[2,4,5,3,1],[6,7,1,4,5],[5,1,1,2,4]]
→ [[0,4],[1,3],[1,4],[2,2],[3,0],[3,1],[4,0]]
Link: LeetCode

1. The one idea that solves it

Running a BFS from every cell to see whether it reaches each ocean is O((RC)2) and unnecessary. The trick is to flip the direction: instead of flowing down from a cell to an ocean, imagine water climbing up from the ocean border inward. If climbing from the Pacific border can reach a cell, then water from that cell can reach the Pacific. Same for the Atlantic.

Two reverse BFSs then: one seeded with every cell on the top row and left column (the Pacific border), one seeded with every cell on the bottom row and right column (the Atlantic border). From a border cell, step to a neighbour whose height is ≥ the current cell. Mark everything reached. The answer is the intersection of the two reached sets.

Idea. Reach-from-cell problems with many sources become cheap when you reverse the move: start at the sinks (the oceans) and climb back. Two reverse multi-source BFSs, overlap of the reached sets is the answer.

2. Picture of the algorithm

Each BFS is a classic multi-source grid BFS: push all border cells into the queue at once with their reach flag set, then expand. The two BFSs are independent, so you can run them in any order (or in parallel). The intersection pass is one more sweep over the grid.

4. Code (C++)

class Solution {
public:
    vector<vector<int>> pacificAtlantic(vector<vector<int>>& heights) {
        int R = heights.size(), C = R ? heights[0].size() : 0;
        vector<vector<int>> ans;
        if (!R || !C) return ans;
        vector<vector<char>> pac(R, vector<char>(C, 0));
        vector<vector<char>> atl(R, vector<char>(C, 0));

        auto bfs = [&](queue<pair<int,int>>& q, vector<vector<char>>& reach) {
            int dr[] = {1,-1,0,0}, dc[] = {0,0,1,-1};
            while (!q.empty()) {
                auto [r, c] = q.front(); q.pop();
                for (int d = 0; d < 4; d++) {
                    int nr = r + dr[d], nc = c + dc[d];
                    if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue;
                    if (reach[nr][nc]) continue;
                    if (heights[nr][nc] < heights[r][c]) continue;   // climb: need >=
                    reach[nr][nc] = 1;
                    q.push({nr, nc});
                }
            }
        };

        queue<pair<int,int>> qp, qa;
        for (int c = 0; c < C; c++) { pac[0][c] = 1; qp.push({0, c}); }
        for (int r = 0; r < R; r++) { pac[r][0] = 1; qp.push({r, 0}); }
        for (int c = 0; c < C; c++) { atl[R-1][c] = 1; qa.push({R-1, c}); }
        for (int r = 0; r < R; r++) { atl[r][C-1] = 1; qa.push({r, C-1}); }
        bfs(qp, pac);
        bfs(qa, atl);
        for (int r = 0; r < R; r++)
            for (int c = 0; c < C; c++)
                if (pac[r][c] && atl[r][c]) ans.push_back({r, c});
        return ans;
    }
};

Complexity. Each cell is pushed and popped at most once per BFS, so each BFS is O(R · C). Two BFSs plus the overlap sweep add up to O(R · C) time, with O(R · C) for the two reach matrices and the queue.

Alternative: reverse DFS from the borders

function<void(int, int)> dfs = [&](int r, int c) {
    reach[r][c] = 1;
    for (auto& [dr, dc] : {pair{1,0},{-1,0},{0,1},{0,-1}}) {
        int nr = r + dr, nc = c + dc;
        if (nr >= 0 && nr < R && nc >= 0 && nc < C
            && !reach[nr][nc] && heights[nr][nc] >= heights[r][c]) dfs(nr, nc);
    }
};

Same complexity. DFS is a few lines shorter; BFS is safer on larger inputs because the recursion stack of DFS can blow up on a long monotone grid. Both reverse the direction of flow in the same way.

5. The part interviewers ask about: why reversing the direction is correct

Water flows from cell A to a neighbour B when height[B] ≤ height[A]. Reversed, we climb from B to A when height[A] ≥ height[B]. The predicate is symmetric by renaming, so "cell X drains to the ocean" is equivalent to "the ocean, following the reverse rule, climbs up to X". The equivalence is exact; nothing is lost in the flip.

Second question: why ≥ and not >? Because the flat terrain case must be reachable both ways. On an all-equal grid water should reach every cell from every border; using strict inequality would stop the climb at the first same-height neighbour, which contradicts the problem's "lower or equal" rule.

Third: multi-source BFS. Both oceans have many starting cells, which is a classic multi-source BFS pattern — seed every source with distance 0 and run one BFS, not one BFS per source. If you push the sources one at a time inside a loop, the complexity blows up and the correctness is the same.

6. Traps and edge cases

  • Running BFS from every interior cell forward. That is O((RC)2). Reverse from the borders instead.
  • Strict inequality in the climb. Using > loses equal-height cells. The rule says water moves to "lower or equal", so the climb condition is ≥.
  • Forgetting the corner cells. (0, C-1) touches both the Pacific border and the Atlantic border; it must be in both reach sets by seeding. Simplest: push the whole top row and the whole left column into Pacific, and the whole bottom row and the whole right column into Atlantic. Overlaps on the corners are harmless (the reach[r][c] = 1 guard dedups them).
  • Mutating heights. Use separate reach matrices; do not overwrite the heights to track visited, because future BFSs would mis-compare.
  • Empty grid. R = 0 or C = 0: return [], do not read heights[0].size() without the guard.
  • Pushing a border cell into the queue twice. Keep a per-ocean reach matrix that is set when a cell is enqueued, not when it is popped, so each cell enters each queue once.

7. How to say it in the interview (30 seconds)

"The naive flow forward is quadratic. I reverse the move: start at the ocean borders and climb inward to a neighbour whose height is greater than or equal. Two multi-source BFSs, one from the top row and left column for the Pacific, one from the bottom row and right column for the Atlantic. The intersection of the two reach sets is the answer. O(R · C) time and space, each cell is enqueued at most twice."
