Word Ladder

LeetCode 127 · Hard · Pattern: BFS by level over an implicit word graph · O(N · L · 26) time, O(N · L) space

Problem. Given beginWord, endWord, and a wordList, return the length of the shortest transformation sequence from beginWord to endWord (including both endpoints). Each step must change exactly one letter and every intermediate word must be in the list. Return 0 if no such sequence exists.
begin = "hit", end = "cog", list = ["hot","dot","dog","lot","log","cog"] → 5
  ("hit" → "hot" → "dot" → "dog" → "cog")
begin = "hit", end = "cog", list = ["hot","dot","dog","lot","log"] → 0
Link: LeetCode

1. The one idea that solves it

Think of the words as nodes of a graph with an edge between any two words that differ in exactly one letter. The shortest sequence is the shortest path from beginWord to endWord in that graph. Shortest path on an unweighted graph is just BFS by levels; the level number when the end word pops out of the queue is the answer.

Building the graph explicitly (N2 word pairs) is too slow when N is large. Generate neighbours on the fly instead: for the current word of length L, try every one-letter mutation (L × 26 candidates) and keep the ones that are in the dictionary. That gives an O(N · L · 26) BFS, dominated by the mutation generation.

Idea. BFS on an implicit word graph. Edges are "differ by one letter". Explore the frontier level by level; the first level that contains endWord is the answer. Compute neighbours by trying every letter in every slot and checking the dictionary — cheaper than building the full adjacency list.

2. Picture of the algorithm

The crucial discipline is mark on push, not on pop. If you only remove a word from the dictionary when you pop it, a word can be enqueued many times from different parents in the same level, costing an extra factor. Remove the word from the dictionary (or add to visited) the moment it is pushed, so each word enters the queue exactly once.

4. Code (C++)

class Solution {
public:
    int ladderLength(string beginWord, string endWord, vector<string>& wordList) {
        unordered_set<string> dict(wordList.begin(), wordList.end());
        if (!dict.count(endWord)) return 0;
        unordered_set<string> visited;
        queue<string> q;
        q.push(beginWord);
        visited.insert(beginWord);
        int steps = 1;                                     // counts words, not edges
        while (!q.empty()) {
            int sz = q.size();                               // one BFS level
            for (int i = 0; i < sz; i++) {
                string w = q.front(); q.pop();
                if (w == endWord) return steps;
                for (int k = 0; k < (int)w.size(); k++) {
                    char orig = w[k];
                    for (char c = 'a'; c <= 'z'; c++) {
                        if (c == orig) continue;
                        w[k] = c;
                        if (dict.count(w) && !visited.count(w)) {
                            visited.insert(w);                   // mark on push
                            q.push(w);
                        }
                    }
                    w[k] = orig;                                 // restore for next slot
                }
            }
            steps++;
        }
        return 0;
    }
};

Complexity. Each word is enqueued at most once (N words). Expanding a word tries L × 26 mutations, each a hash lookup. Total time O(N · L · 26). Space is dominated by the dictionary set and the queue, O(N · L).

Alternative: bidirectional BFS

// Keep two frontiers (begin and end). Each step expand the SMALLER one.
// Terminate when a newly generated neighbour sits in the other frontier.
// Complexity drops roughly from b^d to 2 * b^(d/2) in the branching factor b and depth d.

Same big-O but much faster in practice when N is big and the two words are far apart. Worth mentioning for interviews that care about constants; implementation is a bit fiddly (swap frontiers to always expand the smaller side, so neither side gets stuck exploring a huge frontier).

5. The part interviewers ask about: counting words vs. edges

LC 127 asks for the number of words in the shortest sequence, which equals (number of edges) + 1. Start the counter at 1 (for beginWord), bump it after each full level is processed, and return it the moment endWord is popped. Starting at 0 and bumping before the pop gives you edges, not words — off by one.

Second question: why generate neighbours by letter mutation rather than pre-build an adjacency list? With N up to 5000 and L up to 10, the direct adjacency build is O(N2 · L) ≈ 2.5 · 108; the on-the-fly form is O(N · L · 26) ≈ 106. The flipped-form adjacency with "wildcard patterns" ("h*t") is a middle ground some solutions use; it is roughly the same big-O as mutation but a bit different in constants, and both are standard answers.

Third: why remove from dict (or add to visited) on push, not on pop? Because the first time BFS enqueues a word is the shortest path to it; later rediscoveries are strictly longer and would duplicate work. Marking at push time keeps every word's queue count at 1 and the overall complexity clean.

6. Traps and edge cases

  • endWord not in dict. Must return 0 before starting. Checking after the BFS runs is still correct but wastes a traversal.
  • Off-by-one on steps. Return steps on the pop of endWord; starting at 1 counts words. If you start at 0 you need an extra +1 at the return.
  • Marking on pop. The same word enters the queue many times, blowing the time bound and sometimes causing MLE on large inputs. Mark on push.
  • Including c == orig in the mutation loop. It skips to a dictionary hit on the same word, which is already visited, so no bug — but it wastes a hash lookup per slot. Skip it.
  • beginWord in dict. The problem says beginWord is not necessarily in the dict and the sequence counts it. Do not require it to be a dictionary word; the generated neighbours still check against the dict.
  • Infinite loop on self-mutation. If you forget the c == orig skip you must still guard against revisiting via visited, which the code above does.
  • Modifying w without restoring it. The w[k] = orig line at the end of each slot is mandatory so the next slot mutates the original letter, not whatever you left behind.

7. How to say it in the interview (30 seconds)

"The words form an implicit graph: two words are neighbours iff they differ in one letter. Shortest sequence is a shortest-path BFS from beginWord. I process the queue in levels and keep a counter that increments once per level, so the counter is the sequence length when endWord pops. Neighbours are generated on the fly by trying every letter in every slot and checking the dictionary — cheaper than building all edges. Mark words visited at push time so each word enters the queue exactly once. O(N · L · 26) time, O(N · L) space. For much larger inputs I would do bidirectional BFS."
